## 原应用产品流程与兼容基线

状态：2026-10-13 对现有功能的现状整理，不是补写的历史审批。新需求需明确确认后更新。

用户可以调用既有应用，也可描述新需求并生成可审阅的流程。应用不是单纯的角色提示词，必须具有可验证的输入、运行状态和结果。

流程：明确需求/输入 → 生成预览 → 用户确认 → 必要文件授权 → 顺序执行 → 查看结果/错误 → 明确选择保存。保存后的应用换输入复用；修改要求创建新运行，旧结果保留。

验收条件：预览无业务执行；拒绝不执行；确认绑定具体内容；失败停止后续步骤且保留已完成结果；取消有实际状态；保存与执行分离；新一次调用不默认沿用旧文件；生成成功不能被表述为结果正确。

第一阶段以 CSV 分组求和验证通用链路，不包含策略回测、自动交易或社区发布。

2026-10-14扩展：导入外部应用包仅保存并标注结构验证；个人应用可下载、另存和自然语言改编，生成新预览后确认执行。创建或改编应用可组合个人库中的Tool/Skill，保留精确版本和运行时准入。应用包不包含连接凭据、个人输入文件或运行结果。详细流程与当前限制见[应用包与组件复用](应用包与组件复用.md)；统一社区发布由[愿景交付](../vision-delivery/README.md)协调。

## 2026-10-13：官方目录已添加标识与重复副本

公共Skill/Tool和预置Application显示当前账号“已添加到我的库（内容一致）”及数量；此状态表示保存，不表示已经验证或启用。只比较个人当前内容，删除或修改后的副本不算一致。

重复添加允许，但提交前说明已有相同内容，确认才创建独立个人副本，并按名称、名称_2、名称_3分配未占用名称。后端再次检查重复并要求confirmDuplicate，幂等重试不额外创建；事务中分配名称防并发冲突。名称是展示信息，不应改变Skill/Tool包摘要或官方依赖。自动依赖准备继续复用精确版本，不因主能力重复添加而重复依赖；官方更新必须精确定位个人assetId。

Application沿用预置目录，新增只保存不执行的复制入口；原先成功运行后保存仍保留。新副本独立ID和名称，输入授权、运行确认及隔离执行规则不变。
