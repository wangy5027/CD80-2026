## 共同转换规则

- 代码始终字符串；用户代码和数据库格式通过明确映射转换。未知市场、同名或同码多市场不能猜测。
- 日期严格解析YYYYMMDD、YYYY-MM-DD和已证实的YYYYMMDD.0；拒绝不存在的日期。先规范化比较，混合源格式不得直接依赖文本排序推断最新日期。
- SQL NULL、空字符串、文本NULL按缺失处理；零保持零。用Decimal转换有限数字并以十进制字符串输出，避免金额精度丢失；原库REAL精度不能凭转换恢复。
- 单位表随包版本维护：字段、单位、依据、换算系数和未知状态。无法核实则source_raw，不换算，不自行写“元”。金额、数量、百分比不可混列。
- 精确重复可按已验证业务键和内容摘要折叠；冲突版本选择须记录规则。不能用最大_row_id当业务最新，也不能把不同营业部记录去重。
- 报表使用报告期与披露日两条时间轴；as_of查询排除当时未披露版本。缺少披露日不进入保证无前视偏差的计算；不可从累计报表直接称单季。
- 每次关联先验证键唯一性和行数；金融算法在包内实现，数据服务仅做类型化受控读取/通用聚合。

## 数据核验交付表

每个M项提交一份记录：代码快照、库标识（脱敏）、查询时间、只读方法、字段及类型、业务键、冲突样本、选版规则、日期覆盖、逐证券缺口、单位来源、实际接口结果与独立预期值。原始行包含敏感信息时只保留必要脱敏证据。

无依据的选版、单位或事件映射属于该子功能发布阻塞，不自动阻塞其他已核实子功能。UI必须明确受限范围，进度不能将受阻子功能标为完成。禁止为通过样例向正式库补数；合成夹具与真实数据证据分开。
