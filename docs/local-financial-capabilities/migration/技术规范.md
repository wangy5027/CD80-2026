# 能力迁移技术规范

## 发布与回滚约束

发布脚本锁定26包内容摘要及13个Skill的逐条审阅；结果在capabilities/local-financial/releases/a313dfa6495c3fad。个人副本独立、默认不自动升级或启用。回滚本地包可参考pre-migration-catalog.json，但必须保留现行retiredCapabilities，禁止重新开放南财历史/公告；发布前重新验证精确依赖。不可变release目录不可原位覆盖。

状态：目标设计，2026-10-13。现有首批代码不代表本轮全部实现；执行协议新增项见[接口与协议设计](接口与协议设计.md)。

## 代码分层

| 层 | 允许职责 | 禁止职责 |
| --- | --- | --- |
| Skill | 触发条件、操作方法、精确依赖、澄清、解释、验证标准 | 安装依赖、直接联网、模型补数、授予权限 |
| Tool包 | 输入校验、字段映射、日期/代码/数值转换、金融计算和覆盖判断 | 读取宿主数据库、导入backend内部模块、任意URL/SQL |
| 能力库 | 生命周期、准入、版本、执行、证据、连接与预算桥接 | 按每个金融业务新增特殊handler |
| 数据服务 | 白名单字段查询、参数化SQL、游标、修订检查、类型化通用聚合 | 模型自定义SQL、动态表达式、修改业务数据以适配包 |
| sub-agent | 委派、串行执行、纠错、预算、工件和主agent验收 | 绕过未启用能力、按预览冒充完整计算、另建金融专用调度 |

## 建议包结构

沿用capabilities/local-financial。src中按职责拆为common的dates/numbers/identifiers/coverage/query_protocol，以及history/announcement/margin/search/valuation/finance/lhb/macro/calendar等业务模块。名称为实施建议，避免继续把所有逻辑堆进一个execute(kind,payload)。

每个发行Tool保留短入口original/tool.py，提供run(payload)，仅协调明确函数；所需共享模块随包复制并进入清单摘要。构建由现有scripts/build_local_financial_packages.py扩展，业务代码不写在构建脚本中。脚本生成ZIP、文件索引、精确Skill依赖及样例，禁止手动只改解包目录而忘记ZIP。源代码和发行字节一致性纳入测试。

每个模块说明输入、输出、单位、选版与失败语义；对不直观算法写原因说明和独立数值样例。函数职责单一，转换为纯函数；不采用动态eval、隐藏全局状态、猜测字段或无界循环。用户界面展示业务术语，代码细节留在文档和错误追踪。

## 执行与兼容

复用python_wasi和python_connector，不增加“可以任意联网”的执行类型。需要扩展分页时为connector引入显式版本选择，新旧包按声明使用不同限额和请求结构；旧版本不因宿主更新获得更大权限。Skill脚本仍只执行已声明WASI，联网读取拆成Tool依赖。

库格式保持cd80.capability/1的前提是机器Schema以可选字段增加功能且旧解析不被静默误用；旧宿主遇到新协议应明确不支持。若实现证明不能满足兼容条件，单独提升格式版本并补适配，不能把不兼容行为藏在同一字段下。

两份capability.schema.json/文档schemas必须同步；检查packages.py允许的JSON Schema子集，避免生成$ref/oneOf等当前不支持字段。人类文档、OpenAPI和包清单不得分别维护不同字段。manifest权限、连接、版本、内容摘要和配置修订共同绑定验证证据。

## 与sub-agent衔接

实施基线中已观察到backend/app/modules/sub_agent下的service/store/routes/model等文件，含任务超时、工件归属和工具结果转工件逻辑；不据此宣称已验收。先复核当前实现，再在同一机制增加读取预算及覆盖元数据。

复用逻辑任务ID、owner、conversationId、执行代次、取消信号和工件ID；这些是宿主上下文，不能由Tool输入JSON指定。普通独立调用由宿主建立受限调用上下文；接入子任务后累计预算不因重新加载Skill、重试、纠错或创建新桥接实例重置。遵守既有同对话串行和最多三次纠错，不以本项目要求新增并行子agent。

不再建设第二套工件表或下载接口。现有工件若已包含size/sha256/mediaType/sourceRefs/complete，补充需要的schema与coverage元数据；任务内读取核验owner及授权链，跨任务沿用子任务系统显式授权机制。完整字节先持久化后发布引用，失效或取消产生的不完整结果不可默认为可计算。

## 旧南财退出与发布

历史/公告删除包括产品skills文件、工具定义及handler、专属路由白名单（确认无其他调用方后）、目录、提示和相关测试。共享客户端及其他南财工具不一并删除。模型无法发现退役名称，直接API或旧应用引用得到CAPABILITY_RETIRED，不能落为模糊404或改成本地调用。

审计历史保持可读；旧应用已确认定义与待运行方案在执行前检查退役依赖，拒绝执行并要求用户改选和重新确认；不能修改其原始定义、审批摘要或个人历史版本。旧能力库builtin适配若引用退役handler也必须拒绝，不仅检查聊天目录。

本地更新保持source.identity，创建新版本；公共包不能覆盖个人副本，升级按现有确认/重新验证/启用机制。发布前完成官方样例实际执行及效果复核，生成内容绑定证据并更新public-catalog，不直接给正式用户自动启用。

## 部署与回退

先交付兼容平台，再发布新包，最后执行已确认退役。数据库修订元数据/索引等通用变更先在临时副本验证迁移、备份与回退，不能把正式库当测试库。上线前备份涉及的库与配置；日志不含凭据。

失败回退优先撤回新公共发行并明确不可用，保留用户数据和历史；退役南财能力不因回退自动恢复联网。新包依赖新协议时旧服务明确拒绝，不以宿主Python或旧南财补偿执行。修改前端后构建dist；只写文档不构建。
