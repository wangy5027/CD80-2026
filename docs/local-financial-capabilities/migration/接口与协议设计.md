# 迁移接口与协议增量设计

状态：2026-10-13已实现并随26包发布；实际证据见发布验收（本地资料，未随源码发布）。机器Schema和数据服务OpenAPI已同步。

## 当前实现边界

底层scan与宿主业务结果均采用有界不可变快照，连续读取使用绑定作用域及查询的cursor；offset仅为首请求兼容。aggregate_v1已支持order_by。lookup_v2沿用/query作受限截止日查找；日期筛选规范化紧凑YYYYMM、YYYYMMDD、YYYYMMDD.0与ISO，不能规范化即DATA_AMBIGUOUS。业务错误由宿主白名单转换为失败，不当作成功内容。详细字段与预算如下。

## 现有接口继续复用

公共复制/官方准备、验证、试用、调用、导出、启用均使用现有capabilities接口；不为每个金融Tool新增Flask路由。Cookie及资源owner隔离、POST幂等、PATCH的ETag/If-Match、202作业和只读观察规则保持。新增数据能力不授予CRUD写权限。

sub-agent第一版已使用/conversations/{id}/messages和sub-agent-runs/artifacts接口，控制命令采用body.revision，其错误目前为error/code可选；不能把能力库的ETag或requestId/details强套到所有旧接口。本设计的结构化金融错误先在能力调用结果中保留，子任务层通过兼容适配记录；若扩展子任务HTTP错误字段，只能增量兼容并同步其规范与调用方。

Tool输入业务字段用snake_case，宿主既有assetId/versionId/configurationId等字段不改名。现有参数page/offset等按具体包版本维护，新旧参数不能同时传且静默择一。

## 包输入约定

| 能力 | 最小参数 | 默认及约束 |
| --- | --- | --- |
| history | code、asset、period、date或start_date/end_date、limit、cursor | asset=stock，period=day；week/month新增；默认limit=20最大100；date与区间互斥；无日期取最近周期 |
| announcement | code、keyword、date或区间、limit、offset | code必填；默认区间见产品设计；keyword只在证券内；20/100分页 |
| margin | code、market可选、date或区间、limit、offset | code必填；市场有歧义必须补；不提供跨证券sort榜单参数 |
| security-search | keyword、asset_types、limit、cursor | 非空关键词；股票/ETF/基金枚举；不支持事件推断 |
| close-valuation | code、asset、date、fields | 未填日期取该证券最新可用记录，各源日期单列；显式日期不回退 |
| financial-statement | code、kind、start_period/end_period、as_of、fields、limit、cursor | kind=indicator/income/cashflow/balance；fields按kind白名单；未指定默认最近已存报告，as_of明确时约束披露时间 |
| lhb-detail | code、date或区间、limit、cursor | 默认数据集最新日期，code必填；无旧type枚举 |
| macro-series | indicator、start_date/end_date、limit、cursor | indicator来自本地明确目录；默认最近20个记录期；收益率须明确曲线和期限 |
| event-calendar | event_type、code可选、start_date/end_date、limit、cursor | 必选事件类别与日期区间，避免把过时数据当今日日历；代码筛选仅对有可靠代码映射的事件开放 |
| local-search | category、keyword、limit、cursor | category=stock/etf/fund/industry；不接收announcement/research/theme |

新增包接口的具体字段清单由构建源生成manifest及参数文档，并以契约测试固定。上表是目标约束，不能忽略原包已有兼容字段；已有包需要新版本，旧输入继续按旧定义解释。

## 统一金融结果

新/升级包的content采用result_schema="financial-result/1"；外层仍是现有content/sources/artifacts，不再套新HTTP成功包装。字段如下：

| 字段 | 类型及语义 |
| --- | --- |
| records | 有序对象数组；有限数字用十进制字符串，缺失null |
| requested | 规范化业务条件，不含owner、密钥或宿主路径 |
| source | 来源标识；本地表名或明确AkShare标识 |
| sources | 表/字段与单位依据、源日期、可用修订标识；不伪造URL |
| as_of | 数据集最新日期，未知null；多源具体日期在sources中 |
| returned_range | 实际返回记录最早/最新日期，可为null |
| units | 字段对应单位及verified/source_raw状态；未知禁止换算 |
| coverage | status=complete/partial/unknown；basis描述；period_state=open/closed/not_applicable；缺口原因 |
| pagination | has_more、next_cursor可空、returned；旧offset包可保留原字段 |
| warnings | 结构化code/message/fields；不把异常混成成功 |
| provenance | 输入摘要、包版本/配置、读取摘要由宿主补充，不能相信包自报调用成功 |

complete仅表示对声明筛选及数据版本的读取完整，不证明所有市场记录存在。period_state描述自然周期相对于可核验数据时间的状态；数据完整性不因此变complete。建议将retrieval_complete和market_completeness分别放coverage，后者默认unknown。分页结束但有无效字段仍需warning。

## 受控连接v2

旧python_connector请求run({input,responses})及6次读取行为保持。新包在execution中声明protocolVersion="2"，permissions仍为connector_only/none外部影响；连接operations显式包含query_v2或aggregate_v1。旧宿主必须拒绝未知版本。Schema、解析器、配置摘要和发布检查同时支持后再发行包。

宿主注册query_v2：主站POST /desktop/api/financial-data/tables/{table}/scan代理数据服务POST /api/v1/tables/{table}/scan。两者均读取，不允许任意路径。请求字段为columns、filters、order_by、page_size、cursor；表来自维护者白名单，字段/操作/排序类型逐表限定。

order_by为受限字段序列，最多2个业务字段，服务端追加_row_id稳定决胜；只允许asc/desc。page_size默认100、最大100。cursor由宿主生成并绑定owner、任务/调用、连接修订、表、查询摘要、数据修订、最后键、失效时间；不能由模型构造SQL片段。后续页不得改变原查询。

当前实现采用有界不可变内存快照：源记录上限10000，超量明确失败；单快照4MiB、缓存32MiB、游标最多6400、TTL120秒。查询阶段释放SQLite事务，跨页复用原快照；数据库后续修改不混入已有结果。重启/过期返回CURSOR_EXPIRED，未引入伪数据修订号。scope由服务端注入并绑定用户/任务与查询。

业务结果另由宿主ResultPages保存不可变快照：cursor绑定owner、任务、包/配置摘要与原输入；后续调用不得改筛选、limit等条件，不再重新取源数据。源读取完成与当前页面完整分开记录：source_retrieval_complete不等于retrieval_complete，最后一页才结束页面读取。offset仅保留首请求兼容用途，连续读取使用cursor。容量与TTL同上。

date/number类型转换由字段契约明确。索引和查询计划在临时数据上验证，避免对百万行表每页全扫描；无法在预算内执行时明确失败，不提高到无限预算。

## 通用排序聚合

已实现独立aggregate_v1操作，路由与scan同层，后缀aggregate；不是开放SQL。输入限filters、group_by、metrics、order_by、limit。group_by最多3个白名单字段；metrics最多8项，op仅count/sum/min/max，数值字段先通过已核实的类型映射。拒绝自定义表达式、JOIN、HAVING文本和模型指定函数。排名的计算字段如净买入由包在已完整读取的受限范围计算，不允许为它临时新增SQL表达式入口。

聚合覆盖必须记录匹配行数、实际处理行数及是否完整；超过资源限制不能对前N条静默聚合。返回多组需要稳定分页或明确拒绝超量。Decimal所需精度不能用SQLite浮点SUM冒充精确值；选择经过验证的有界计算方案并保留精度说明。全市场两融榜单不因这个操作上线而开放。

## 预算与取消

以下为工程初始值，须经测试与sub-agent实际限额对齐，并在配置中集中定义：单v2调用最多100次读取、10000条累计读取、120秒；单页512KiB；单调用输入/输出及内存受WASI更严格限额约束。普通查询不自动使用最大预算。

任务级累计读取限制200次/20000条，计重试实际成本；任务期限取已有sub-agent任务剩余时间与Tool期限较小值，不另延长任务。工件沿用观察到的4MiB单件、32MiB/64件任务上限，实施时复核，以较严格限制为准。需更多数据时让用户缩小范围或建立明确新任务，不以拆成子调用绕过累计限制。

宿主在开始读取前原子预留额度，读取后结算实际量；失败/重试记录成本。取消在读取前、响应后、包重新执行前检查，迟到结果不发布成功；纠错不重置预算。所有上下文由服务端注入，不添加可由用户指定owner/run权限的Tool参数。

## 中间结果与文件

复用sub-agent实际工件ID与下载路由，不另新增一套/result接口。工件附带schema、coverage、来源日期和版本、sha256/size；计算读取验证完整字节与授权，不使用preview。M13 CSV工具在宿主将已授权结果挂载为只读输入后执行WASI，声明inputFiles/outputFiles；工具不接受宿主路径。普通对话也须经既有文件授权适配，不能因支持工件而绕过fileIds归属检查。

## 错误与审计

沿用error/code/requestId/details。新增目标码：DATA_CHANGED或CURSOR_EXPIRED（409，需要显式重新开始读取），DATA_AMBIGUOUS/UNSUPPORTED_OPERATION（422），READ_BUDGET_EXCEEDED（429），CAPABILITY_RETIRED（409），DATA_SOURCE_FAILED（502）；和既有错误重名时复用其语义。无匹配为成功空records；取消采用现有任务状态，不映射成成功空数据。

每次读取记录父任务、调用/步骤、包版本、查询摘要、行数/字节、源修订、耗时和结果摘要，不记录凭据。必须能从最终产物追溯到实际读取，不能只保存模型描述。

聚合order_by只允许分组字段或指标别名，Decimal数字排序、空值最后、稳定决胜；最多100组，超过limit明确拒绝。具体字段权限由注册表tableFields逐表限制。官方文件依赖示例仅挂载包内声明文件，重名/缺失拒绝；不读取任意宿主路径。
