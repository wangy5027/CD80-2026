## 一 已上线统一 App 兼容契约

以下第一部分已实现并加载本机服务，验收范围见开发进度（本地资料，未随源码发布），不等于所有历史版本均支持。HTTP前缀为 `/desktop/api/asset-apps`，沿用当前登录与本地来源校验。JSON错误为 `{error,code,details}`。写请求使用 `Idempotency-Key`；同键异内容返回409。第二部分协调层实现后，旧资产运行及底层接口保持各自语义；相同创作意图的用户入口统一接入协调层。

### 定义与版本

定义格式 `cd80.app/2`：`name`、`description`、`inputSchema`（JSON Schema object）、`rules`（字符串数组）、`nodes`（顺序数组）、`outputs`（结果名到绑定）、`parameterization`（审阅记录）、`gaps`（待解决事项）。草稿可以保存缺项；验证与正式运行拒绝存在阻断缺项的定义。

节点字段：`id`、`kind`（code/tool/skill）、`title`、`inputBindings`、`delivery`、`checkpoint`、`provenance`。code 保存 `code`（含 run(payload)）和 `files`（资源数组）；tool/skill 保存 `component` 完整快照，首次保存可用 `componentRef:{assetId,versionId}` 转为快照。skill 另有 `task`。delivery 为 `{schema,files:[{name,mediaType?}],evidenceFields:[]}`。provenance 为 `{type:historical|modified|generated,runId?,stepId?,description?}`，不把改造后的代码标历史原件。

绑定对象：

- `{from:"input",path:"security"}`：本次参数，点路径可访问对象/数组。
- `{from:"literal",value:...}`：明确常量。
- `{from:"step",stepId:"fetch",path:"data.rows"}`：任意前序节点实际 JSON。
- `{from:"file",input:"csv"}`：本次 `fileBindings.csv` 授权上传，映射隔离 `/input/` 路径。
- `{from:"artifact",stepId:"fetch",name:"prices.csv"}`：前序同名输出文件，校验实际字节后映射只读输入。

inputBindings 每个键对应传给实现的参数，可用常量对象或多个来源键合并；不隐式猜合并规则。输出绑定只能引用节点/常量。内嵌代码可通过 payload 接收已解析字段和 payload.files 的文件别名映射。

App 详情返回 `{id,name,description,revision,versionId,latestVersionId,enabledVersionId,definition,definitionDigest,versions,verification,issues,createdAt,updatedAt}`。versions 为摘要数组，versionId 唯一；definition 是当前选择版本。验证、启用是可变状态，定义不可覆盖。verification 为 `{status:unverified|running|passed|failed,cases:[...],contextDigest?,runIds:[]}`。直接调用本兼容接口保存的新版本及导入版本始终未验证、未启用；第二部分的候选晋升是独立目标契约，不改变本接口的直接保存语义。

本人详情另返回 `runtimeBindings` 与 `bindingRequirements:[{sourceIdentity,name,nodeIds,options:[{connectionId,name,configured,enabled}]}]`；导入预览返回同样的需求清单和接收账号可选连接，不传作者配置。`POST /<id>/bindings` 接收 `{versionId,revision,bindings}`，仅保存本人连接映射，清除该版本验证与启用；有正在执行或待继续的本版本运行时拒绝修改，保留运行环境一致性。新保存版本未提供 bindings 时沿用当前版本本人配置，导出不携带。

本兼容保存接口不接收也不要求验证用例；新版本保留`verification.status=unverified`、空`cases/runIds`，不自动运行或启用。已上线界面直接保存后确认已保存，测试入口独立且默认收起；保存不依赖先调用`/preview`。下一轮创作请求通过第二部分统一准备和最终确认，单纯保存仍不执行。

已上线Creator的来源`stepIds`为原运行的成功步骤ID。未指定时只选明确采用/交付依赖闭包；没有采用记录时返回候选，App为空的待补定义，Skill/Tool为`draft:null`，由用户明确选一个或多个步骤后重新整理。候选含`stepId,type,title,status,reconstructable,issues,inputStepIds,adopted`。来源记录须终态，非终态返回409 `SOURCE_NOT_FINISHED`；失败、部分完成、中断中的成功步骤可恢复。`source`保留`runId,status,completion,objectiveCompleted,selectionBasis,selectedStepIds`；`completion`当前为`{status,missingDeliverables,reasons}`，兼容旧字符串。`objectiveCompleted`只有明确完成且运行成功才为true，旧记录未知为null。选定范围会带上成功前置依赖，不能据此倒填历史采用或宣称原目标完成。下一轮协调层允许自动推荐范围并生成候选，不要求普通用户走该技术选步分支；此兼容响应暂不改变。详见[来源步骤契约](来源步骤选择与内置适配.md)。

本兼容验证的 expectation 使用 `{mode:"json_equals",value:...}` 或 `{mode:"fields",values:{"path":expected}}`，检查 App 最终 outputs，未满足不通过。Skill 非确定性效果另结合每步真实交付约束，不能仅凭自评通过。第二部分候选验证新增业务断言与动态交付评审适配，不能借适配降低客观检查要求。

run 字段：`id,appId,versionId,definitionDigest,input,inputDigest,fileBindings,revision,mode,status,steps,artifacts,result,error,waiting,createdAt,updatedAt`。mode 为 run/verification。status 为 queued/running/awaiting_input/awaiting_authorization/awaiting_confirmation/succeeded/failed/cancelled/interrupted；steps 含 nodeId、kind、status、resolvedInput、result、artifacts、error、skillCallId、attemptId。工件含 id/name/sha256/mediaType/downloadUrl；下载总经本人校验。waiting 为 `{nodeId,reason,missing:[]}`。

### 原子存储与恢复

沿用 agent_platform 的 SQLite 文件与事务锁，新建 `asset_apps`、`asset_versions`、`asset_runs`、`asset_artifacts`、`asset_requests`。组件快照与定义同事务存储；输入上传继续归工作台所有，输出字节与元数据在 asset_artifacts 同事务保存。旧 agents/runs 不改。迁移为幂等建表，回退旧程序保留新增表；首次上线前以 SQLite backup 制作备份，并在临时库执行迁移/重启检查。

运行线程只处理已提交run；幂等记录和新版本/运行同事务写入。状态修改需revision，执行提交需attemptId和当前running状态。重启把未结束动作标 interrupted；GET从不启动线程。继续核对固定的定义、输入摘要、当前文件授权和成功输出摘要；固定代码重试可显式执行，未知外部操作需核对结果或明确知情重新尝试。

继续还复查本版本仍启用、验证有效和最初运行环境摘要（模型地址/选项/凭据摘要、执行器版本及限制、组件当前配置）；变化时要求重新验证并开新运行。每次继续均复验缺失输入，产物需同时符合数据库字节摘要和步骤当时接受的 id/nodeId/name/size/sha256。重启后重新计算被中断验证的结果，避免永久处于 running。Tool 返回 unknown 保留结果未知门槛。Skill 问答暂停为 `waiting.kind=skill_question`，继续传 `skillAnswer:{questionId,revision,answer}`；同一次 Skill 调用保留请求身份与输入。

Creator 请求有 creating/completed/failed 幂等状态，未完成的同键请求返回 CREATOR_RUNNING；客户端保留原键，不能因响应丢失重复模型创作。支持 kind=app/tool/skill，Tool/Skill 编辑传 draft 和 instruction，选定节点可由 `POST /<id>/extract` 提取独立草稿。保存时历史源码来源须匹配本人真实成功实现及完整选定闭包，或前版已核实内容；来源真实性与是否原交付采用分开记录。未经核实的 historical 声明降为修改草稿，始终不继承验证。受控内置Tool保存完整参数及当前接口适配快照，标modified，不宣称已冻结历史宿主实现。

交付核实文件真实非空字节、约定 MIME、JSON/CSV/XML解析及PNG结构/压缩数据；JPEG/GIF/WebP/PDF为封套检查，不宣称完整语义解码。保留必要二进制资源并按原字节导入导出，凭据、私人路径与私人运行工件引用仍拒绝，压缩资源递归检查有容量限制。最终 artifact 输出绑定返回可下载工件元数据，内部 `/input/` 路径只用于节点执行。

已上线局部预算：App 最多64个顺序节点；单定义和包8MiB、最多512个资源；App路由请求信封上限9MiB以容纳完整包与控制字段，其他普通JSON默认仍2MiB；代码单文件128KiB；每次输出沿用隔离执行器现有限制。Skill 内部沿用子任务步骤/时间/纠错预算，Tool 固定模型步骤沿用能力库预算。下一轮创作时还须扣第二部分的共享会话预算，不能让嵌套调用重复领取总额度；普通旧运行仍按原协议。这些限制不重新引入旧8步产品限制。


已上线历史recipe按真实 `source:{kind:sub_agent,runId}` 恢复（兼容旧顶层sourceRunId）。Creator从实际采用或明确选定步骤及其调用记录归因所需Skill，加载但未使用的Skill不打包；`library_script`恢复完整脚本包为固定Tool，`library_skill`从已保存的实际Skill快照恢复动态节点，不把其一次轨迹固定化。没有完整旧调用证据时仍可保留实际源码并列缺口。Tool/Skill的authoringProvenance保留来源与修改说明，平台存储时标记historicalEvidenceVerified=false，编辑不得继承来源成功或启用。

## 二 统一创作契约（工作区已实现）

路径 `/desktop/api/authoring-sessions` 已注册，App、Tool、Skill 的现有内容格式和隔离执行器继续使用。协调层在既有平台数据库持久化内部候选、测试和提交过程，不新增第四种用户资产；只读接口不启动或恢复任务。以下响应以当前源码为准，部署和真实上游验证不由路由存在推定。

### 对象与身份

所有对象保存owner并按当前登录账号检索，客户端不提交或覆盖owner。ID为不透明稳定字符串，名称不能代替身份；内容摘要统一由服务端规范化后计算，文件按真实字节计算。完整内容与执行内容摘要分开，执行摘要排除项必须通过服务端元信息分类，不能由前端指定。

纯讨论可以生成新实现，历史不足可以推荐或补全，但`observed`仅用于实际可核实记录。原件/修改/新生成的源码性质继续沿用App节点provenance及能力库authoringProvenance；推断选择并不把真实执行原件改成虚构，也不把未执行的代码标为历史成功。

### 状态与并发

`phase=preparing|checking|validating|repairing|awaiting_input|awaiting_authorization|budget_paused|awaiting_review|committing|completed|failed|cancelled|interrupted`。failed、cancelled、interrupted及预算暂停均保留草稿、证据、余额和下一步，不删除用户成果。草稿是否持久化、验证是否通过、正式资产是否启用分别记录，phase不能替代验证和启用事实。

`revision`是会话乐观锁；每次用户写入须匹配当前revision，后台推进核对当前revision和工作状态。每会话只允许一个活动worker，新修订先停止旧worker，待其退出再启动；候选及正式提交另绑定精确身份。旧回调只能补记旧执行事实。所有写操作按`owner + operation + Idempotency-Key`及完整请求指纹去重，同键异内容409。幂等重试先恢复原操作，再判断修订，避免原请求已成功后因旧revision误报并重复提交。

问题为`{id,kind,prompt,revision,requiredRefs?}`，`kind=business|input|authorization|unknown_result`。只有影响业务含义或缺必需输入/授权的问题阻断自动推进；回答绑定当前questionId及revision。输入回答不自动扩权，授权回答仍须通过对应归属和权限检查。

### HTTP 操作

统一Cookie及本机来源校验；错误包沿用`{error,code,details}`。写请求必须带`Idempotency-Key`。结果返回最新会话及允许动作；后台工作返回202，不由浏览器轮询启动。

| 方法及路径（相对 `/desktop/api/authoring-sessions`） | 请求 | 响应/语义 |
| --- | --- | --- |
| POST `/` | `{conversationId,kind,intent,instruction,mode?,sourceRefs?,target?}`；mode默认prepare | 201 `{session}`；幂等重复返回同一会话。prepare默认整理、计划、范围内验证及有限修复；draft_only仅持久化当前输入/草稿，不调用模型或执行资产 |
| GET `/` | `?conversationId=&assetId=&cursor=&limit=`，limit默认20、最多100 | `{items,nextCursor}`，过滤条件均限定本人；不触发执行 |
| GET `/{id}` | 无 | `{session,candidate?,testPlan?,evidence,reviewSnapshot?,budget,commit?}`；身份、revision、问题和允许动作完整返回，不向前端发凭据 |
| POST `/{id}/messages` | `{revision,instruction,sourceRefs?,runtimeBindings?}` 或 `{revision,candidateContent,sourceRefs?,runtimeBindings?}`，两种内容互斥 | 202完整详情；沿用同一目标及预算，持久记录原始修订，替代过时检查。补充sourceRefs只接受本人upload；runtimeBindings为完整sourceIdentity→本人connectionId映射，逐项复查身份匹配。candidateContent必须是当前kind完整内容，不接受预算/验证/启用自报 |
| POST `/{id}/answers` | `{revision,questionId,answer,sourceRefs?,runtimeBindings?}` | 202完整详情；仅回答当前问题。补文件/连接与messages同一校验，失败整体回滚、不留下部分授权；不加额度或绕过运行准入 |
| POST `/{id}/continue` | `{revision,mode,budgetRoundId,confirmationId?,acknowledgeUnknownRequests?}` | 202完整详情；`mode=resume|extend_budget`。resume沿用余额；extend_budget绑定当前轮和confirmationId。模型回复未知时，须以当前全部unknown请求ID明确确认放弃未完成回复，记录acknowledgedAt/revision且保留state=unknown、不返还额度；外部动作未知仍须独立核实 |
| POST `/{id}/cancel` | `{revision}` | 202 `{session}`；阻止后续动作并取消子调用，重复调用不恢复执行；完成后仍可读取草稿和事实 |
| POST `/{id}/confirm` | `{revision,mode,candidateId?,contentDigest?,reviewSnapshotId?,reviewDigest?,baseRevision?}` | 完整详情；成功保存目标在`session.result={assetId,versionId,enabled}`，完成200。save_and_enable必须精确候选、完整审阅摘要及编辑时baseRevision；draft_only可无尚未形成的候选，仅保留草稿并停止准备，不启用 |

所有命令返回同一详情结构`{session,candidate,runtimeBindings,sources,testPlan,evidence,reviewSnapshot,budget,commit}`，不存在的对象为null。`sourceRefs`只提供用户明确关联或服务端已验证的来源身份；创建支持`conversationId`、`runId`、`fileId`、`assetId/versionId/kind`和导入`portableAssetId`/旧`draftId`，后续补充仅支持upload。当前message类来源按所属对话近期消息解析，不提供精确messageId单条筛选。主对话后续明确选择的文件传给同一会话；普通App运行的fileBindings必须属于本次消息授权fileIds，不能因同账号已有文件就自动使用。

`fileFixtures=[{name,text|base64,bindAs?}]`中text与base64二选一，服务端规范化补id、sha256和claim=generated。最多8份、单文件256KiB、总1MiB，必须非空、安全平面文件名；允许.txt/.md/.csv/.tsv/.json/.xml/.svg/.png/.jpg/.jpeg/.gif/.webp/.pdf/.xlsx/.docx/.pptx，按既有交付检查验证真实格式并拒绝凭据。App的bindAs对应文件输入别名，Tool/Skill以`/input/<name>`访问且仍要求manifest输入文件权限。原件存本人作用域authoring_fixture及blob，不进入用户文件/资产列表；证据逐例保存`fixtureRefs:[{id,name,size,sha256,claim:generated}]`并与真实授权fileRefs分开，按真实内容摘要判定不同输入，更名或换id不算新样本。

高级编辑提交也写入AuthoringMessage修订日志，固定输入内容摘要和前后候选，不回退旧资产保存接口。日志与候选同库关联保存，不能只覆盖Session.instruction而丢失原始追加要求。完整内容提交沿用目标格式的体积、文件与执行边界；新请求信封限额须容纳现有允许的完整包，不能借高级编辑扩大包限制。

`confirmationId`由服务端基于当前预算暂停和展示的追加额度签发并关联本人会话；接受该确认才可调用extend_budget。新幂等键不能重用同一confirmationId再次加额；普通resume、answers或messages不能替代追加授权。completed且仅存草稿的会话可继续编辑；已正式提交后对同一资产的新修改建立新的创作会话和基础版本，不覆盖原提交记录。

### 统一预算台账

`BudgetRound={id,sessionId,number,status,limits,consumed,reservedRequests,previousRoundId?,extensionConfirmationId?,startedAt,closedAt}`；`limits={activeMilliseconds:600000,modelRequests:32,repairRounds:2}`；`consumed={activeMilliseconds,modelRequests,repairRounds}`。详情另返回`lifetimeConsumed,confirmationId?,unknownRequests:[{id,model,sentAt}]`。status不是会话是否暂停的权威字段，按session.phase显示；累计值不用于放宽当前轮上限。

`ModelRequestLedger={id,sessionId,attemptId,budgetRoundId,provider,model,state,sentAt,completedAt?,usage?,usageStatus,acknowledgedAt?,acknowledgedRevision?,acknowledgement?}`；当前state为sent/succeeded/failed/unknown，usageStatus为reported/unknown。真实provider发送前以短事务原子校验`已计请求 + reservedRequests < 32`并立即扣一次、记录sent，不另创建独立reserved中间记录。发送失败、取消或结果未知不退额度；确认放弃未知回复保留原状态/消费，新尝试使用新请求身份。上游usage缺失记未知，不当零或精确费用。

所有Creator、测试计划、验证、协议/网络重试、嵌套Skill及固定Tool内模型调用都须取得该账本许可。第32次许可可在剩余时间内完成，第33次发送前拒绝；无需新增模型请求的结果检查仍可完成。局部执行器更严格限制继续生效。

`RepairRound={id,sessionId,budgetRoundId,number,causeEvidenceIds,candidateBeforeId,candidateAfterId?,status,startedAt,completedAt?}`；依据一批失败开始自动改稿时原子扣减一次，包含该轮所需复验。第二轮获准后可在剩余时间/请求额度内完成，第三轮启动前拒绝；不能把实现改写伪装为协议重试。用户追加需求不扣自动修复轮，但继续扣当前时间和请求额度。

生成内容、静态定义/资源和未冻结测试计划的技术格式修复同样使用这2轮总量，不能各自另获2轮。静态/计划失败按`scope=static_check|test_plan_check`记录实际问题；业务gaps、必需文件/授权或连接缺口仍提问，不以自动改稿猜业务条件。`agent_model_output_invalid`与`MISSING_IMPLEMENTATION`可作为技术格式缺陷；单独`CAPABILITY_BLOCKED`不能据此推定授权已满足，须有其他明确技术原因才能随该技术原因修复。

计划格式修复仅在首次计划冻结前，用`planRepairFeedback`携带无效计划及错误；实际执行失败后只通过`technicalRepairFeedback`修实现，反馈包含有界实际结果、失败检查和冻结预期，保持原业务instruction与已冻结计划，不用待测输出重写答案。取消/截止仍保留已取得的部分证据及其原candidateId/planId，不因此生成可提交审阅。

有效时间按会话活动区间累计，包含等模型/工具响应，并发分支的重叠时间只计一次。未开始调度排队、等用户及预算暂停不计时；从暂停再执行继承剩余量。活动区间和消费须持久化检查点，崩溃恢复保留已用时间及未结算区间，不从零计时；无法核实剩余量时保守暂停，不能凭重启增加可用量。

截止时间传至所有在途调用，600秒到期中断可取消调用并停止业务处理；清理和记录事实不用于继续业务工作。不能仅检查“是否允许开始下一步”，导致最后一次调用突破总时限。无法立即撤回的外部调用标unknown，核实前不自动重放。

resume不改变limits/consumed；extend_budget仅在额度不足、明确确认且旧在途工作已停止或记为未知后，幂等关闭旧轮并创建下一轮同等额度。旧轮剩余不结转；同一`sessionId + previousRoundId + extensionConfirmationId`最多建立一个下一轮。刷新、追加、回答、服务恢复不产生新轮。

### 候选验证、元信息分类与正式提交

内部验证目标为`{targetType:authoring_candidate,sessionId,candidateId,contentDigest}`，由三类适配器prepare/validate/inspect/commit使用；不通过客户端伪造正式版本或先启用来取得执行资格。App适配完整定义与步骤交付，Tool适配固定实现及断言，Skill适配标准资源、效果标准和最后人工接受。用例执行前静态核验资源、依赖、授权与环境，读取包内容不授予权限。

纯展示修改只进行静态检查并记录`changeClass=display_only`；前提是执行及匹配行为均未改变，原证据仍适用。`matching`修改必须产生受影响的匹配检查证据，不能只静态解析；可复用未受影响的业务执行证据。当前Tool/App名称与描述可进入matching检查；Skill名称进入实际模型观察，因此按behavior重新验证。`behavior`候选重新实际验证。适配器保存reuse及所比较摘要，服务端复查旧证据、内容、检查范围、配置和授权，不能只凭executionDigest相等或用户声明免测；Skill证据还绑定当前模型和引擎，正式准入再次校验。

验证计划至少两类实际输入；自动生成的独立预期和依据在执行前冻结。planDigest发生变化时不改写原证据，改后需验证相应检查。reviewSnapshot固定全部展示内容和结果；人工确认只能接受标记awaiting_review的效果项，不能覆盖失败、缺授权、未知或未执行的客观项。真实、隔离、模拟证据及其适用范围分别保存；模拟不能被晋升为真实上游验证。

save_and_enable前，在短事务内固定提交所对应session revision、candidateId、contentDigest、reviewSnapshotId、evidenceIds、reviewDigest及基础资产revision，并预留稳定commitId；暂停对此提交对象的变更。正式目标身份在对应资产库事务中产生并与commitId幂等结果一同保存；同一原请求重试返回同一目标，不新建第二份资产。

save_and_enable逻辑顺序为预留→保存版本→关联证据→启用→完成；当前中间三步在单一资产事务内，不各自暴露持久中间状态。最终内容必须与候选规范化内容及全部资源/依赖摘要一致；只允许登记正式身份等与执行无关的映射，不得改写实现后沿用旧证据。检查当前环境及权限仍与证据适配，不再调用Creator或追加一次业务执行。draft_only仅reserved→completed，持久保留当前需求/可用候选并停止准备，不创建正式版本或启用。

当前实现将正式版本、证据关联、启用和adapter幂等结果放在各自资产库的单一事务中；会话台账与资产库之间仍不是跨库原子事务。以commitId作为adapter稳定幂等键，资产已保存但协调响应丢失时，保持提交锁定并用原请求核实，重启不允许通过编辑或取消清除未核实提交。旧可用版本保持到新版本事务成功；没有出现的version_saved中间状态不伪装为事实。环境变化或基础版本冲突停止提交，旧确认在新要求之后不能保存新候选；不自动覆盖或重跑。

### 错误与恢复

| HTTP / code | 条件及处理 |
| --- | --- |
| 409 `REVISION_CONFLICT` | 会话或基础资产修订已变化；返回当前身份/修订和差异入口，原编辑保留 |
| 409 `CANDIDATE_SUPERSEDED` | 请求指向旧候选/尝试；不覆盖新候选，历史结果可查 |
| 409 `REVIEW_STALE` | 审阅内容、计划或结果变化；重建审阅摘要，不用旧确认提交 |
| 409 `VERIFICATION_REQUIRED` | 客观项未满足、条件已失效或必要效果未确认；保留草稿/证据，不能启用 |
| 409 `BUDGET_EXHAUSTED` | 请求/修复额度不足；返回当前轮和允许动作，不自动加额 |
| 504 `AUTHORING_DEADLINE` | 有效执行截止；停止在途可取消调用，保留事实和未知结果 |
| 409 `BUDGET_CONFIRMATION_REQUIRED` | 缺明确追加确认、确认已消费或对应轮次过时；不建立额外轮次 |
| 409 `OUTCOME_UNKNOWN` | 外部执行/提交结果待核实；不按失败直接重放 |
| 409 `COMMIT_IN_PROGRESS` | 同一提交仍在恢复；返回commitId及实际阶段，不创建新版本 |
| 403 / 404 | 归属或授权失败/不存在；不泄露其他账号来源、资产或文件 |

断开观察不取消后台工作，GET从不启动线程。取消先撤销当前候选的后续执行及提交资格再传播stop；迟到回调只记旧事实。重启将活动attempt标interrupted或unknown，保留来源、候选、计划、预算预占和提交阶段；resume先核实内容、输入、环境和授权，不自动重放未知模型/工具调用或外部业务写入。

### 增量存储、迁移与验收

新增表存入既有agent_platform SQLite，目标表为`authoring_sessions,authoring_messages,authoring_sources,authoring_candidates,authoring_authorizations,authoring_test_plans,authoring_evidence,authoring_review_snapshots,authoring_attempts,authoring_budget_rounds,authoring_model_requests,authoring_repair_rounds,authoring_commits,authoring_requests`。全部记录含owner及稳定主键；JSON内容按以上对象契约存储，源文件和完整资源按现有受控工件/快照存储引用并校验摘要，不新增可见辅助资产。

同库事务保护会话修订、当前候选、预算许可及提交阶段；对owner/session、当前候选、预算轮/调用身份、幂等键和提交目标建立唯一约束及查询索引。正式App/能力版本仍由各自库维护，提交记录保存其实际ID和阶段；跨库资源引用在晋升前校验完整性。候选与失败草稿不得在迁移或回退时自动清除。

迁移采用幂等建表；本轮临时库验证创建、重复初始化、重启预算/候选恢复与提交响应丢失，不使用正式用户写入数据。正式六库及用户文件备份、真实库副本两次增量迁移和17:03:34本机重启只读核验已执行；完整恢复、回退再升级和多进程恢复演练未执行。回退须保留新增记录，具体分层结果见实施验收（本地资料，未随源码发布）。
