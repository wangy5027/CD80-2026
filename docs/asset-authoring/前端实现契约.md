## 统一入口与创作对象

- 沿用现有工作台字体、青蓝色、浅底、留白及按钮，不重做整站。自然语言是主要编辑入口，技术实现、原始定义与连接细节默认收起。
- 主对话、任务结果的沉淀按钮、App/Tool/Skill详情、能力库及导入后“准备使用”进入同一持久创作会话。卡片、详情与资产库读取同一对象，不能各自生成草稿或维护独立验证状态。旧资产继续按原语义运行，编辑或升级接入统一流程，不强制批量迁移。
- 用户明确创建、沉淀或修改时，默认整理来源、实现、参数、依赖、两组用例并在授权范围内验证、有限修复；无需逐步点击生成、保存版本、填用例、测试和启用。明确“保存当前草稿”“只保存”“先别测试”仅持久化，不执行资产；有实质授权歧义时才提出具体问题。
- 目标使用资产身份和基础版本关联，不以同名或当前打开页面猜测。可推荐资产类型；用户指定类型时不能静默换类。默认只增加用户要求的可见资产，辅助组件保存在完整快照中；明确提取请求才增加独立Tool/Skill。
- 自动整理本会话、明确关联历史及本人相关记录，结合消息、源码、资源和真实执行证据；重要业务歧义才询问。技术选步、依赖组织和JSON用例填写降为可选高级入口，不再作为普通流程前置条件。
- “历史实际执行”“推断关系”“新生成或修改”分别标记，用户可展开来源。缺采用关联可以由系统推荐，纯讨论可以生成新实现；不能将推断、模拟或作者声明显示成历史真实成功。

## 卡片、详情与连续修改

| 当前状态 | 主卡内容及允许操作 | 详情内容 |
| --- | --- | --- |
| 整理、检查、验证或修复中 | 目标、真实阶段、耗用摘要、追加要求及取消 | 当前候选、参数规则、完整方法和资源、来源、测试计划与逐例实际进展 |
| 等待业务回答或权限 | 具体缺项、已保留成果、对应回答入口 | 问题适用范围及已有证据，不用泛化报错要求用户重新开始 |
| 预算暂停或重启中断 | 已保留草稿、停止原因、按实际允许动作恢复或追加额度 | 本轮与累计消耗、已完成及未知结果；继续不会被误表述为重新运行 |
| 待审阅 | 用途、实际示例结果、范围和限制；“确认保存并使用”“继续修改”“只存草稿” | 可变输入、固定规则、可读差异、全部用例与检查依据、真实/隔离/模拟标记 |
| 提交中或部分完成 | 固定所确认的内容，显示真实保存及启用阶段 | 明确已保存未启用、冲突或结果待核实，保留幂等恢复入口 |
| 完成、失败保留或取消 | 正式资产入口或已保留草稿及下一步 | 历史候选、失败证据和正式版本；未满足准入不能显示“可使用” |

对话卡与详情双向定位同一会话及候选。桌面使用侧边详情，手机使用全屏详情，返回后保留原会话、当前对象和未发送输入。App详情仍用纵向步骤表达“输入 → 方法 → 交付”，Tool和Skill展示各自契约或标准方法；统一操作不把三类资产压成同一内部结构。所有源码、消息、包说明及输出按不可信内容安全渲染，不解释为可执行HTML。

整理中可追加修改，沿用同一创作会话，形成新的需求修订和候选，停止过时检查。旧结果仍可查，但迟到结果不能覆盖新候选或使其通过验证。追加要求不重置预算，不自动算作一轮技术修复。业务规则需要变化时询问；范围内技术错误可自动修复候选，普通运行不静默修改正式资产。

修改先显示差异，默认只影响当前App内部副本，旧可用版本保持原状态。白名单中的纯展示元信息可只做静态检查；名称或描述参与匹配时必须验证受影响的发现/选择行为。方法正文、算法、提示、输入输出、数据源、连接和交付要求的变化需重新验证。免重测和证据复用由后端裁定，前端不能仅凭字段名宣布免测。

## 候选验证与最终提交

候选、资源和验证记录先在内部持久保存，不要求用户先向个人库提交正式版本才能测试，也不将每次修复注册为可见资产。系统准备原案例或需求案例及不同输入案例，在执行前记录独立预期和依据。普通用户不必手填两组用例，仍可查看或调整；预期不能从待测输出复制，检查标准不能为通过而降低。

真实上游、隔离执行与模拟结果分开显示。默认测试只使用已授权文件、连接、只读数据和临时产物；外部业务写入需隔离或可验证模拟，模拟不能替代必要真实条件或授予生产写权限。导入本身仅静态检查并保留原件，“准备使用”才启动同一创作流程，作者验证和授权不自动带入。

后台的保存、验证和启用仍是不同状态，用户在最后一次审阅中可以一并确认当前内容与实际效果。Skill和动态App保留全部逐例结果，但不强制逐例再点接受；客观失败不能被人工确认覆盖。主操作“确认保存并使用”只晋升已冻结且证据仍有效的相同候选并启用，不重新生成内容，不额外执行一次业务任务。“只存草稿”不启用，“继续修改”返回同一对象。

最终提交前由后端核对候选、用户审阅范围、基础版本、验证、配置及权限。冲突时显示差异和具体原因，形成新候选后重验受影响部分，不覆盖其他入口的新内容。跨库存储部分成功时如实显示“已保存，未启用”，重试复用同一提交身份，不重复生成资产或版本。

## 共享预算、恢复与并发

每轮共享600秒有效执行时间、32次实际模型请求、2轮自动修复；创作、测试、重试、子Skill和固定Tool内部模型调用都计入同一持久预算，模块更严格限制继续有效。前端展示服务端实际耗用和暂停原因，不自己计发额度、伪造百分比或估算精确金额；请求数和耗时不代表费用上限，上游未返回token用量时标未知。

第32次已获准请求和第2轮已启动修复可在剩余其他额度内完成，第33次请求或第3轮修复启动前被拒绝。修复从自动改候选开始扣轮；技术重试计请求及时间，不另获额度。600秒截止约束在途调用，到期停止后续业务处理；清理不用于继续任务。等待用户、未开始的调度排队和额度暂停不计有效时间，并发活动区间不重复累加。

追加要求、刷新、重新打开和服务恢复不重置预算。恢复使用剩余额度；仅明确同意继续并追加预算时幂等开始新一轮，旧轮余量不叠加，累计消耗保留。普通回复及回答问题不能被当作追加额度。取消传播至全部子操作，迟到回调只补记旧尝试事实；未知外部结果先核实，不自动重放。

所有视图只读观察同一服务端状态，关闭或卸载只取消观察，不等于取消后台工作。账号切换清理视图及请求引用；跨账号、旧修订、旧候选或旧尝试的响应不能写入当前界面。请求按修订和读取次序防倒退。提交结果未知时保留内容及幂等身份，先核实再恢复；明确成功后才清理相应未变化的本地输入。已提交的审阅对象固定，后续新要求形成新修订，不能改写正在确认的内容。

## 接口职责与普通使用

统一入口为 `/desktop/api/authoring-sessions`；创建、读取以及 `messages`、`answers`、`continue`、`cancel`、`confirm` 已有工作区实现，精确字段、状态和错误只引用[接口与存储契约](接口与存储契约.md)。聊天识别、各页面按钮和导入准备调用同一协调服务；前端集中封装操作，不在组件中重新编排资产保存、验证和启用。

通用 `request()` 已添加 `/desktop/api`，调用方不得重复添加前缀。已有 `/asset-apps`、能力库及运行接口保留所属存储和执行职责，由协调层适配；旧接口的可调用现状不代表新会话接口已上线。正式资产列表、版本查看、包导出和历史运行继续沿用所属模块。

普通任务主动检查适用且已启用的个人资产，显示实际采用对象及精确版本；重要方法差异才澄清，强制指定不可用时不能冒充或静默替换。换参数是新运行，不改资产；改方法进入创作候选。运行仍展示步骤、实际输入、结果、文件和检查点，继续与重新运行分开，授权不自动扩大。无合适资产可继续临时任务，普通成功不自动沉淀。

本轮静态文档检查核对CA-Q1–CA-Q14、链接、接口职责及预算边界，不运行构建或业务测试。未来按[实施与验收计划](实施与验收计划.md)覆盖三类资产的十二条主路径及AC-CA-01至22；U/I、实际Vue组件、隔离浏览器及获准真实调用分开留证。使用临时账号、合成输入和独立数据库，前端构建由集成任务顺序执行。

旧前端规则中“先保存正式版本再测试”“创作、验证和启用必须分别点击”“手填原用例与新输入”“缺采用关联必须手选步骤”均被本页目标替代：候选先验证、最终一次审阅提交，系统组织来源与用例。直接保存不执行、双用例门槛、客观验证、权限准入和来源真实性仍保留。旧实现的分步管理能力可保留为高级入口，不能继续成为新普通流程的前置要求。
