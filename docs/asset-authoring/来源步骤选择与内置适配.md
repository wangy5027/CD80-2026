# 来源步骤选择与内置适配

更新：2026-10-14（Asia/Shanghai）。统一创作已实现来源整理和缺采用关联时的系统推荐，推断关系不改写旧成功事实；本地专项与真实上游的范围分别见实施验收（本地资料，未随源码发布）。已上线的来源恢复与内置适配保留为兼容基线，历史证据见来源恢复验收（本地资料，未随源码发布）。机器字段和接口只在[接口与存储契约](接口与存储契约.md)维护。

## 1. 统一来源整理

创建、沉淀、修改和升级统一由持久创作会话整理当前对话、明确关联历史、本人授权文件、成功执行、源码与结果。用户指向以前的任务时可以检索本人相关记录；普通用户无需先勾选消息、执行步骤或依赖。多个来源或解释会影响业务含义时才提出具体问题，不按同名猜资产身份，也不读取无关或其他账号资料。

有明确采用记录时优先恢复最终交付依赖闭包。没有采用关联时，系统可结合任务要求、对话与真实结果推荐一个或多个成功步骤，并补齐实际前置依赖；推荐关系标为推断，不倒填原任务采用事实。无法恢复的内容可在已授权创作中生成新实现，纯讨论也可生成，但均不能标为历史实际运行原件。自动推荐不是默认全选所有尝试。

失败尝试只作为诊断和修复参考，不纳入成功交付证据。历史不完整时显示具体缺口和来源性质；若可以在现有业务要求内补全，系统继续生成和验证，不强迫用户处理技术绑定。算法、口径、目标或交付要求存在重要歧义时暂停询问。无法满足真实条件时保留候选和已完成事实。

## 2. 来源真实性与固定快照

来源记录、素材内容摘要、实际调用证据与候选内容分别固定。真实执行原件、基于原件修改、新生成代码，以及推断选择关系是不同维度；新的候选测试成功也不能反向证明旧任务已经完成或旧实现相同。旧记录仅明确完成且运行成功时才称原目标完整完成；部分完成、失败、中断仍保留原状态，缺明确完成依据则保持未知。

恢复必须核对本人归属、来源运行、步骤、资源字节及完整参数。脱敏占位、裁剪日志、错误来源工件、缺失源码和未知工具不能无损恢复；不得从这些材料编造历史参数。新生成实现可以解决后续方法问题，但不填补原数据覆盖、单位依据或过去已经交付图表的事实缺口。

历史执行恢复沿用终态来源要求，不将正在变化的运行直接当作已冻结历史实现。当前会话内容与已完成的历史依据形成独立来源快照；后续追加需求形成新的候选及来源修订，停止过时验证，不覆盖原记录。精确对象和候选失效规则见[接口与存储契约](接口与存储契约.md)。

## 3. 技术选步与已上线兼容入口

已上线 `POST /desktop/api/asset-apps/creator` 继续提供按来源运行和明确步骤恢复的能力；其机器字段、返回候选及错误仍以[已上线兼容契约](接口与存储契约.md)为准。未显式选择时，该旧接口仅恢复明确采用或交付依赖；没有采用关系仍返回候选和待补内容，不会因为本文定稿就自动获得新行为。

`/desktop/api/authoring-sessions`已注册，普通入口在协调层完成自动推荐、补充实现和验证，再转为不可变候选；不要求用户先走旧接口的“需要选步”分支。高级明确选步保留，用户选择覆盖系统推荐的范围，但仍自动纳入必要成功前置闭包，保留选择依据和影响提示。

失败、部分完成及中断来源里的实际成功步骤仍可选，不将其原目标改写为成功。旧Creator对非终态来源的拒绝行为保留。只预览来源、查看旧记录、保存现有草稿不会执行资产；明确创作或准备请求可按统一授权范围测试，不能继续把“所有来源整理均不测试”作为新流程规则。

## 4. 受控内置 Tool 适配

受控内置Tool继续复用既有legacy适配协议，保留实际参数和来源，绑定当前可信注册表的明确输入契约与handler。适配明确说明未冻结历史宿主实现，候选节点标为修改；来源恢复或单纯保存不调用工具。统一创作可在已授权只读/隔离测试范围验证当前接口，运行时仍检查连接、可用性和权限。

当前适配、新测试与历史实现分别记录，不能把当前注册表的行为冒充旧代码快照。原任务没有取得的历史序列、计算结果或图表不因几个查询步骤成功而补造；后续新增实现标记生成并独立验证。外部写操作不因“恢复历史”获得正式执行授权。

## 5. Skill、Tool 与 App 的完整性

Skill沉淀保留所选或推荐方法真正需要的标准正文、辅助脚本、资源和精确工具依赖；不因旧采用标记缺失丢失实际使用的方法，也不把仅加载但未使用的Skill伪称已采用。系统在新实现中明确引入的新依赖可以加入完整快照，但须标为新增选择并验证，不能称为历史实际使用。

App保留代码、组件和资源的完整快照；只有用户明确要求独立提取时才新增对应可见Tool/Skill，辅助依赖不会批量注册进个人库。固定步骤可组成Tool；动态Skill决策不能仅换类型标签成为固定实现。App内部修改默认只影响候选副本，不反向改写个人库组件或其他App。

完整App提取可以由自然语言定位目标步骤并展示可读范围，高级明确节点选择继续可用；重要业务歧义才询问。所有方式最终进入同一候选、测试计划和审阅提交，不因入口不同继承来源资产的验证或启用。

## 6. 验证与交付边界

来源整理只是创作准备的一部分。下一轮系统自动生成原案例与不同输入、在现有授权和共享预算内实际验证及有限修复；最终只晋升用户审阅的相同候选。纯展示或匹配变化的证据复用、修复计数及恢复/追加额度均以[接口与存储契约](接口与存储契约.md)为准。

验收需分别覆盖明确采用、缺采用关联、用户高级选步、纯讨论生成、部分完成历史、不可恢复参数、当前内置适配、真实依赖和重要歧义。原有恢复验收只证明已上线基线，不证明新自动推荐、会话协调或测试闭环已实现；本次仅定稿文档，未运行上述业务验收。
