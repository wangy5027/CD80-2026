## 本轮用户流程与验收原则

1. 创建、沉淀或修改默认自动整理来源、实现、参数和依赖，准备原案例及不同输入并执行授权范围内验证；“保存当前草稿”“只保存”“先别测试”只持久化。导入先静态检查保留原件，明确“准备使用”进入同一流程。
2. 自动利用当前会话、明确关联历史及本人相关记录，重要业务歧义才问。缺采用关联可以推荐范围，纯讨论可以新生成；用户不必选技术步骤。推断、生成和模拟均不得改写历史事实或伪称真实上游成功。
3. 候选先持久化和验证，不要求先保存为个人库正式版本。修复技术问题不得改变用户业务规则，至少保留两类用例与独立预期；失败或受阻保留草稿、已完成证据和具体下一步。
4. 用户最后一次审阅可以完成必要效果确认、保存相同候选并启用，不额外运行一次业务任务。客观失败不能人工接受为通过；只存草稿不启用，继续修改沿用当前对象。默认仅新增所要求的可见资产。
5. 处理中可追加要求，同一创作会话的新修订停止过时检查，旧回调不覆盖当前候选；预算不重置。刷新只恢复观察，取消阻止全部子执行及迟到提交，重启和未知外部结果不得自动重放。
6. 普通任务主动复用适用且已启用的个人资产，显示实际版本；参数变化是新运行，方法变化进入候选。强制指定不可用不静默替代，个人组件修改不反向更新其他App快照。
7. 对话卡、桌面详情及手机全屏详情呈现同一对象；技术内容默认收起，必要业务问题具体可答。状态分别显示草稿保留、验证、正式保存与启用，页面组合操作不合并后端准入事实。

旧前端计划要求“用户先保存版本，再分别点击验证和启用”、手填两组用例及缺采用关联必须选步，已被上述流程替代。双用例、来源真实性、权限与客观检查继续保留；现有逐步管理入口可以作为高级操作，但不能作为本轮普通流程必经步骤。

## 数据与数值依据

- 用户贯穿案例为平安银行 `000001.SZ`、`2025-01-01` 至 `2025-12-31` 日线走势、价格变化率、最大回撤及图表；这是待验证需求，不是本地数据已经存在或全年完整的声明。
- 真实验收先检查实际返回、标的、日期、字段、口径和覆盖依据。真实数据不可用、覆盖不足或无法核实完整性时，停在对应取数/交付检查处并报告缺口，不用合成数据、其他年份或其他标的冒充本案例完成；不得插值补造交易记录。
- 确定性计算使用独立的合成小数据，明确不代表平安银行：A 收盘序列 `[100, 120, 90, 108]`，价格变化率为 `108 / 100 - 1 = 8%`，最大回撤为 `1 - 90 / 120 = 25%`；B 序列 `[80, 100, 95, 120]`，对应 `50%`、`5%`。
- 上述公式是验收夹具的明确口径；真实应用的数据字段、复权及缺失值规则仍从审阅后的固定规则读取。独立预期值由人工公式或独立检查器给出，不调用待测算法生成答案；CSV 逐行、数值、图表数据和实际执行源码分别比对。
- 新输入至少改变数值，并覆盖可变标的、日期或新文件路径的适用组合；核对取数调用、源码输入、步骤引用及结果均采用本次值，不能只检查表单文字变化。空数据、缺列、乱序、重复日期和不适用输入另设明确预期，不把任意异常默认为成功。
