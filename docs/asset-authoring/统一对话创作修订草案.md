## 二 范围与保留规则

覆盖 App、Tool、Skill 的新建、从历史沉淀、修改、导入后准备，以及普通对话中的发现和复用。保留高级编辑、原件查看、包导出及旧资产运行。社区发布和分享体验不在本轮重做。

三类资产语义沿用[已确认产品设计](产品设计.md)：Tool 保存固定实现与输入输出契约，Skill 保存通用方法及资源并可在任务约束内动态执行，App 保存有序编排、实现和完整组件快照。系统可以推荐类型；用户明确指定类型时尊重意图，无法按该类型兑现时说明原因，不悄悄换类型。

继续保留账号隔离、WASI执行、受控连接、完整资源、版本不可变和来源可追溯。App 默认修改内部组件副本；个人组件的新版本不自动改写既有 App，界面可以展示来源和可升级关系。旧版本和历史运行保留。数据覆盖、单位、算法口径等真实缺口不能靠生成内容补造。

## 三 用户流程

### 创建和沉淀

用户说“做一个……”“把刚才的方法沉淀下来”，系统建立持久创作记录，明确目标资产和相关来源。系统自动理解相关消息、成功执行、结果、源码、资源及必要依赖，生成可变输入与固定规则、完整候选实现和测试计划，然后在授权范围内验证、有限修复。

没有采用关联的旧记录，由系统结合对话与真实结果推荐范围；纯讨论也可生成新实现。只有影响业务含义的多解才中断询问。失败尝试可以作为修复参考，不能作为成功交付依据。推断关系和新生成实现不改写旧执行记录。

在上下文中“保存当前草稿”“只保存”“先别测试”是持久化动作，不重新执行资产；“把刚才的方法做成可复用资产”是创作请求，默认执行准备与验证。语义确实不清且会影响执行范围时，提出一个具体问题。

### 修改和提取

用户可以在原对话、资产卡或详情中直接提出修改。服务端解析并固定当前资产身份和基础版本；多个目标均合理时先询问，不按同名猜测。修改形成候选与可读差异，旧的可用版本继续保持原状态。

当前 App 内部的代码、Tool 和 Skill 可以继续编辑；独立提取只针对用户要求的部分，并带齐必要依赖。提取默认不顺便向个人库注册一批辅助资产。来源关系和快照身份分别保留。

处理中追加要求沿用当前创作记录，形成新的需求修订和候选；停止过时执行并使其证据不再满足新候选准入。已完成的实际结果继续可查。只有内容、条件和检查范围仍完全适用的证据才可复用，不因“上一轮成功”直接授予新内容验证。

### 审阅和提交

系统准备好后展示用途、可变输入、固定规则、实际示例结果、检查范围、来源变化及限制。客观检查通过后，必要的效果判断由用户最后一次审阅完成；用户可展开查看全部用例结果，不强迫逐项额外点接受。

主操作“确认保存并使用”表示接受当前展示内容及效果，保存相同内容的正式版本并启用。服务端再次核对候选、测试证据、当前配置和权限；该操作不再生成内容，不额外执行一次业务任务。“只存草稿”不启用，“继续修改”保留原成果并进入下一次编辑。

准备失败、预算耗尽或缺少条件时，保留草稿及结果，显示已完成事项、阻塞原因和可操作的下一步。未通过不能用用户的效果确认覆盖客观失败，也不能显示为可使用。

### 普通使用

普通分析请求先检查已有可用资产及适用范围；明确匹配时直接复用，并显示实际采用的资产和版本。参数变化属于本次运行，不自动修改保存的方法。改变算法、规则或流程属于创作，形成修改草稿。

多个资产的方法差异影响结果时询问；明确指定的资产不可用时说明具体原因，不使用其他能力冒充。没有合适资产时仍可完成临时任务。普通执行不自动沉淀，不因运行失败静默重写 Tool 或 App。

### 导入与旧资产

导入先静态检查并保留原件，不执行包内内容。用户发起“准备使用”后进入同一创作流程，整理本人的连接、依赖及验证。导入或适配不继承作者的凭据、文件授权、验证和启用；改变实现的适配生成新候选，原件保持可追溯。

旧资产继续按原语义运行。编辑或升级时恢复可核实内容；缺失部分可明确生成并标注，不能将旧研究目标模板当作已恢复的完整实现。无需批量改写旧资产才能使用新流程。

## 四 测试和自动修复

测试计划至少包含原案例或原需求对应案例，以及不同输入的适用案例；空数据、缺条件等边界按业务需要增加。计划在执行前记录检查标准及依据。预期来自用户规则、独立计算、可信已知样例或可核实约束，不能把待测输出复制成预期，也不能为通过测试而降低原要求。

| 类型 | 主要检查 |
| --- | --- |
| Tool | 固定实现、真实输入输出、计算与业务断言、资源和约定文件 |
| Skill | 方法要求、必要工具使用、实际任务效果、资源及真实交付；最后统一审阅效果 |
| App | 参数与节点连接、中间结果、组件约束、真实文件、最终业务要求；动态文字不强制用全文相等评判 |

原有两组用例要求保留，系统承担准备工作。真实上游、隔离运行和模拟结果分别展示，模拟通过不满足真实上游结论；缺少必要真实条件时按已有准入规则保留待准备状态。只读数据操作和临时产物生成属于默认范围，外部业务写入不通过自动测试获得授权。

一次自动修复轮指：依据一批失败或缺项，开始自动调整候选，再执行所需复验。最多两轮；从启动自动调整即扣减。修复上限限制启动第三轮，已获准的第二轮可以在剩余时间及模型请求额度内完成改稿和复验；成功后正常进入审阅，不因计数等于2而停止该轮。结构化响应重试和网络重试计模型请求数及时间，不额外给予额度；不能借协议重试无限改稿。用户主动追加需求不算自动修复轮，但继续使用当前模型与时间预算。

自动修复限于实现错误、输入连接、缺资源等技术问题。用户指定的业务规则需要变化时暂停询问；已冻结的检查标准不能由修复器自行删减。修复后的行为内容重新冻结和验证，失败保留实际证据。

元信息免重测采用明确白名单，只涵盖不进入模型上下文、执行逻辑或匹配条件的展示字段。名称或描述若参与用途匹配，属于发现或选择行为变化，须完成受影响的匹配验证，可以复用未受影响且条件仍有效的执行证据，但不能统称纯元信息免测。方法正文、适用范围、提示词、契约和连接配置不能归入纯展示。验证复用记录执行内容摘要及免重测原因，不能依赖前端声明“只改文案”。

## 五 统一预算和执行控制

每轮上限：600秒有效执行时间、32次实际模型请求、2轮自动修复。创作、测试、重试、子 Skill、固定 Tool 内部模型调用共享一份持久预算；各模块自身的更严格限制仍生效，不能各自重新领取32次额度。

实际向模型发出请求即计次，失败也计次；发送前原子预占额度，并保留调用身份。第32次已获准的请求可以在剩余时间内完成，第33次发送前阻止；无需新请求的结果检查可以完成。时间按会话实际活动时间段计算，包含等待模型和工具返回；并发分支不重复相加。未开始的调度排队、等待用户回答和额度暂停不计有效时间。统一截止时间传至模型、工具及子Skill；达到600秒中断可取消调用并停止后续业务执行，保留已发生事实或结果未知状态，清理时间不用于继续业务处理。

刷新、重新打开、追加修改及服务恢复不重置预算。模型请求和修复上限分别阻止新的超额请求或修复轮，时间上限同时约束在途执行；无法继续完成目标时暂停，显示耗用和保留成果。恢复处理沿用剩余额度；预算不足且用户明确同意继续处理时，才幂等建立新一轮600秒/32次/2轮额度，旧轮剩余额度不叠加，并保留全部累计消费。补充信息、回答问题和普通回复不视为追加授权，同一次继续确认不能重复加额。

取消传播到所有正在执行的子操作，阻止后续调用和过期结果提交。页面关闭不取消已授权后台工作；服务重启将活动工作标为中断，恢复观察不重放业务。继续前核对候选、输入、环境、权限及已有结果；外部结果未知时先核实，不直接重试可能已经发生的操作。

前端展示真实阶段、耗时、请求次数和需要用户处理的原因；不得制造进度百分比或精确费用。上游有 token 用量才记录，缺失标未知。当前没有准确金额汇总，模型请求数和耗时不等于费用上限。

## 六 拟采用的技术契约

本节是落实已确认产品规则的工程方案，接口和数据表尚未实现。正式机器字段将在[接口与存储契约](接口与存储契约.md)中维护，不要求用户逐字段选择。

### 持久创作记录

在现有服务上增加统一协调层，复用 App、能力库和子任务的版本、执行及证据能力，不增加第四种用户资产。

| 对象 | 必要内容 |
| --- | --- |
| 创作会话 | id、owner、conversationId、入口意图、目标类型/资产/基础版本、revision、当前需求、候选、阶段、预算、问题与提交结果 |
| 来源集合 | 相关消息、本人历史任务、文件及实际执行证据；每条记录身份、内容摘要、相关性及真实/推断/生成性质 |
| 不可变候选 | candidateId、完整内容摘要、执行内容摘要、完整资源和依赖、参数规则、当前运行条件、来源链 |
| 测试计划与证据 | 候选身份、用例、独立预期与依据、实际调用及结果、环境/权限摘要、真实或模拟、客观检查与人工审阅状态 |
| 提交记录 | 幂等身份、用户审阅的候选与验证身份、基础版本、仅存草稿或保存启用、已完成阶段及正式资产/版本 |

当前对话的编辑对象必须以身份引用传递，不能只靠显示名称。来源包和模型输出均为待检查数据，不能授予权限、变更准入或指挥读取无关账号资料。

### 阶段与并发

内部阶段覆盖整理、静态检查、验证、自动修复、等待输入/权限、预算暂停、待审阅、提交、完成、失败保留、取消和重启中断。持久化状态、验证状态与启用状态分别记录，界面可合并为可理解的摘要，但不能丢失“草稿已保留”的事实。

所有写入使用账号范围内的幂等键，同键异内容冲突。修改、回答、继续和最终提交绑定 revision；执行回调同时绑定 candidateId 和 attemptId。追加需求或取消后，旧回调只能补记旧尝试事实，不能覆盖当前候选或授予验证状态。

### 接口操作族

拟统一在 `/desktop/api/authoring-sessions` 下提供以下操作，沿用 Cookie 和本机来源校验；这是新接口方案，不代表当前可调用。

| 操作 | 拟契约与约束 |
| --- | --- |
| POST 集合 | 创建或按幂等键恢复创作会话；请求包含 intent、kind、instruction 及明确来源/基础资产；默认进入准备，明确保存模式仅持久化 |
| GET 集合或单项 | 按本人、会话或资产读取摘要/详情，返回 revision、当前候选、实际阶段、允许动作和预算；不触发执行 |
| POST `/{id}/messages` | 追加要求，固定当前目标及基础 revision，替代过时检查，不另建重复资产 |
| POST `/{id}/answers` | 回答绑定 questionId 与 revision 的具体问题；普通文字不自行提升权限或追加额度 |
| POST `/{id}/continue` | mode区分resume与extend_budget；resume沿用剩余额度，extend_budget绑定当前轮次和明确确认，幂等建立下一轮；结果未知时返回核实要求 |
| POST `/{id}/cancel` | 停止当前准备和子执行，保留草稿与证据；幂等重复不恢复执行 |
| POST `/{id}/confirm` | 包含候选及审阅摘要、基础 revision 和提交模式；仅相同内容及有效条件可保存启用，成功返回资产和版本 |

聊天识别、页面按钮和导入准备均调用同一协调服务，不在前端重复拼装流程。底层既有资产接口继续维护各自存储与执行语义；旧入口通过适配接入，不让相同创作意图继续走两套产品规则。

### 候选验证与正式提交

现有验证要求已保存版本，需要增加内部候选目标适配。候选和验证可以持久保存，但不作为正式资产或每次修改的可见版本堆入个人库。

三类资产通过 prepare、validate、inspect、commit 适配统一工作流，继续使用各自执行器和准入规则。App 补齐动态交付和业务断言的评审适配；Skill 的人工效果确认并入最终审阅，仍保留逐例结果和客观失败。

最终提交只晋升已经冻结和验证的相同内容。证据绑定账号、候选执行摘要、完整依赖、用例与检查标准、环境配置及授权；提交前重新核对条件。不得在保存时重新生成实现后沿用旧验证，也不得把客户端的 passed 当作平台事实。

跨 App/能力库的保存、验证关联和启用使用持久提交阶段及幂等恢复，不宣称跨库原子事务。中途失败展示实际已保存/未启用状态，重试不重复建版本、不绕过验证、不改写旧可用版本。当前版本已被其他入口修改时返回明确冲突，先展示差异再形成新候选，不静默覆盖。

### 存储迁移与边界

创作记录、候选、测试计划、预算台账和提交阶段拟增量存入现有平台 SQLite，具体表及索引在正式契约内落实。原有账号、资产和运行记录保留，既有表不通过本轮方案重写历史事实。

迁移为幂等建表，备份范围覆盖新增数据及其关联存储；回退程序保留新增记录，不删除已保存用户成果。测试只使用临时账号和隔离库。新迁移、重启恢复及跨库提交失败恢复必须单独留证，不沿用旧全量结果。

## 七 前端契约

对话卡、详情面板、资产库和任务结果入口读取同一创作记录。主卡只展示用途、当前阶段、实际结果摘要及下一步；完整方法、参数、规则、来源、用例和版本在详情查看。代码与连接等技术内容默认收起。

准备中提供进度、追加要求及取消；待审阅展示实际示例结果和“确认保存并使用”“继续修改”“只存草稿”；受阻时展示具体问题与恢复动作。已经持久化的草稿明确提示已保留，不用一张展开的测试表单让用户误以为保存尚未完成。

桌面使用侧边详情，手机使用全屏详情；返回原会话时保留对象与输入。账号切换清理当前账号视图及请求引用，迟到响应不能跨账号显示。保存期间用户可见的审阅内容固定；新需求形成新修订，不能改变已经提交的确认对象。

系统自动判断相关历史和依赖；技术选步、完整 JSON 及高级连接编辑保留为可选能力，不作为普通流程的必填项。没有明确目标时采用可读的资产名称与摘要让用户选择，不要求识别内部ID。

## 八 实施顺序和验收

实施依次完成：持久创作记录及统一预算；候选快照与三类验证/提交适配；上下文和历史组装；对话分流与资产复用；各入口及移动端统一；完整回归、隔离浏览器、受控真实服务验收。分阶段可以交付代码，但只有三类资产和各入口贯通后才宣称本轮体验完成。

### 十二条主路径

App、Tool、Skill 均分别验证新建、沉淀、修改、导入四条路径。共同要求：普通用户不手填 JSON、不手选技术步骤、不手工组织依赖或两组用例；系统自动推进，必要业务问题具体可答，最终结果可审阅。

| 场景 | 共同行为 | 类型专项 |
| --- | --- | --- |
| 新建 | 一句话进入创作并生成实现、用例和实际结果 | Tool固定契约；Skill完整方法和资源；App参数与完整编排 |
| 沉淀 | 相关消息与执行依据共同整理，区分真实、推断和新生成 | Tool固定部分；Skill方法及辅助资源；App采用链及内嵌代码 |
| 修改 | 精确目标、可读差异、元信息分类、行为重验，旧版保持可用 | App默认内部副本；Tool/Skill修改不回写他处快照 |
| 导入 | 原件保留，统一准备条件，重新验证 | 标准Skill资源无损；Tool契约完整；App组件与本人连接完整 |
