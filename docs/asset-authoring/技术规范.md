## 3. 定义、版本与组件快照

工程记录至少区分资产身份、不可变版本、可编辑草稿、平台运行配置、验证证据和运行记录。名称是展示字段，不能代替身份。行为修改生成新版本，原版本及原运行保留；普通运行只读取所选版本，不自动重新生成方法。

App 版本保存输入契约、可变参数及默认值、固定规则、节点顺序、每步输入来源和交付要求、检查点设置、完整组件快照与来源。步骤 ID 在该版本内唯一；组件槽位与来源身份分开，同源不同配置组件不能折叠。源码与资源按内容摘要校验，重复字节可物理去重，但不得丢失槽位或来源关系。

快照包含可在本地保存的 Tool 源码、标准 Skill 文件、必要辅助代码与资源、内嵌代码及其依赖内容。保留源资产/版本、来源任务/步骤和快照摘要，执行以 App 快照为准，不再通过个人库最新版补读。原个人组件修改、删除或归档不改变已保存 App；依赖升级是显式版本修改。

外部服务、模型连接、语言环境和运行时是显式运行条件。快照不复制凭据、原账号授权或远端服务实现，不保证外部行为永远相同。导入或复制得到独立资产，接收者的连接、权限、验证和启用另行建立。

## 4. 有序节点与数据来源

首版节点类型为 tool、skill、code。App 支持顺序执行、引用任意前序结果及多个结果合并，不支持 App 级分支、通用循环、并行或嵌套 App 调用。Tool 和 Skill 的内部处理不受“一个节点只能一次调用”的限制。

以下仅说明内部语义；精确字段及已上线格式以[接口与存储契约](接口与存储契约.md)为准，不在本页维护另一份机器定义：

| 信息 | 工程语义 |
| --- | --- |
| 节点身份与用途 | 稳定步骤标识、执行类别、对用户可解释的用途 |
| 实现与快照 | 内嵌实现或本版本组件快照；不能仅指向会变化的个人库记录 |
| 输入绑定 | 参数路径到来源的映射：App 输入、明确常量、前序节点结构化结果字段、前序工件 |
| 交付要求 | 下游所需字段、类型、文件与证据；不以一段“成功”说明替代真实交付 |
| 检查点 | 完成并验证该步后是否需要用户检查再继续 |

每个绑定的源和目标均可检查；结构化字段路径必须定位实际值，多来源合并需明确名称和冲突规则，不能靠数组顺序猜测。前序文件使用受控工件引用，执行时校验 owner、运行授权、完成状态和摘要，再映射只读输入；不保存旧宿主路径作为执行参数。

保存前展示参数化清单。Creator 可以建议证券、日期、文件等可变字段和默认值，但须验证其贯穿提示、代码、工具输入及连接；固定算法与数据口径独立记录。代码或参数中的值来源无法确认时列缺口，不把猜测绑定成已恢复事实，不通过字符串替换声称完成全部参数化。

## 5. 标准 Skill 内容与平台适配

标准 Skill 内容遵循产品引用的 Agent Skills 标准，保留 SKILL.md 及 scripts、references、assets 等完整必要文件。不得要求普通标准 Skill 原生提供本平台 capability.json、固定输入输出 Schema 或运行状态字段。平台适配元数据与标准包分离，纯标准导出不混入本机配置。

平台适配记录工具绑定、外部依赖、运行条件、权限、验证与启用；合法性与本机可运行性分别报告。环境或工具缺失时保留合法内容，明确缺口，不能删文件后伪装为兼容导入。

App 每次执行 Skill 建立独立调用记录，关联父运行及节点，接收本次任务、授权数据、固定规则和交付要求。内部工具、资源读取、脚本、临时代码及纠错关联到该调用；同一个 Tool 被多个 Skill 使用时分别记录实际调用归属，不能依赖最后加载的工具别名映射。

Skill 可在本节点范围内选择实现和参数，不能改 App 的前后步骤、固定算法或未授权数据。动态生成代码保留本次执行证据，不自动覆盖已保存 App 实现。Skill 完成须形成一次可检查的逻辑交付，平台检查通过后才交给下游；适配约束不反向改写标准正文的通用格式。

## 6. Tool 与内嵌代码执行

Tool 可以包含多个固定步骤和明确固定的模型调用，代码、提示、输出处理与控制逻辑均属于版本内容。模型可按固定调用契约产生结果，不能自行改写 Tool 实现或增加执行流程；固定实现不保证模型或外部数据数值每次相同。

内嵌代码是 App 的正式可执行步骤，无需先发布为 Tool。实际源码、必要辅助模块、输入与输出契约、资源和环境要求完整保存；后续提取一个或多个固定步骤需建立独立 Tool 草稿及验证。包含动态 Skill 决策时不能只换类型标签就变成固定 Tool。

沿用[现有隔离边界](../../backend/app/modules/agent_platform/executor.py)：不以宿主执行回退，无任意联网或依赖安装。固定模型调用由受控平台连接适配执行，不能据此开放 WASI 网络。统一创作每轮600秒有效执行、32次实际模型请求、2轮自动修复已定稿，详见第13节；既有执行器更严格的局部限制继续生效。当前没有准确金额汇总，不把请求数或时间上限称为费用上限，也不借用旧8步限制代替统一预算。

## 7. 实际执行证据与 Creator

实际执行记录需保存以下事实，并与用于 UI 的有界摘要分离：

- 明确 run/node/call 身份及父子关系；实际工具、Skill 和实现版本、配置身份、输入绑定解析结果。
- 完整非凭据输入、输入文件身份及摘要、输出值与工件引用、真实执行源码及资源摘要。
- 开始/结束、成功/失败/取消、权限决策、输出检查、有限纠错及最终采用结果。
- 模型调用、外部调用及结果未知状态；凭据只通过受保护的连接引用提供，不能进入资产或普通日志。

需执行的数据不得从脱敏占位符或裁剪文本恢复；凭据引用与非敏感输入的分离应在写入权威记录前完成。一次动作关联具体节点/Skill调用和 invocation，不能仅按时间顺序猜测。已有历史日志不足时标缺口，不倒填事实。

Creator 自动组装当前会话、明确关联历史、本人授权文件和真实执行记录。有明确采用关系时，以最终交付为根恢复成功步骤及必要前置依赖；缺采用关联时可以结合对话和实际结果推荐范围，纯讨论也可以生成新实现，只有影响业务含义的重要歧义才询问。失败尝试可以辅助诊断，不能作为成功依据；推断关系不倒填原任务的采用事实。历史实际原件、基于原件修改、新生成实现及推断选择分别记录，详见[来源步骤选择与内置适配](来源步骤选择与内置适配.md)。

Creator 可整理代码、标准 Skill 资源、使用说明和验证用例，可通过对话继续改稿；不能授予权限或宣告验证通过。新生成或修改字节不继承原运行成功状态，摘要相同也不能替代输入连接、配置和运行环境的验证。

## 8. 验证、启用与逐步交付

草稿持久化、格式检查、实际验证和正式启用仍有不同状态及准入判断；用户不必逐步点击。创建、沉淀、修改及导入后“准备使用”的请求默认授权整理、生成用例、范围内测试和有限技术修复。单纯保存当前草稿、明确不测试、查看或导入原件仍不执行资产。创作模型调用、验证调用和正式业务运行分别记录，Creator 的文字判断不能写入验证通过状态。

已上线的直接保存及独立测试入口保留为兼容能力；新统一创作由持久会话准备候选，最后一次审阅可完成保存并启用，不额外再运行一次业务任务。“只存草稿”始终可用，不以预览、填写用例或验证通过为前置。系统自动组织上下文、依赖及测试，技术选步和完整JSON编辑仅为可选高级入口。任何中断或失败都要显示草稿已保留及下一步。

系统生成的测试计划至少覆盖原任务或原需求对应案例及一个不同输入的适用用例，在执行前冻结独立预期和依据，不能复制待测输出或降低原要求。证据绑定精确候选内容、参数、组件、环境和授权；提交后再关联相同内容的正式版本。Tool 核对计算及契约，Skill 核对效果、能力使用与交付，App 核对连接、中间结果与最终交付；动态文字不要求全文相等。行为或关键配置变化后重新验证，范围明确展示，不能推断任意输入可靠。

纯展示字段采用服务端白名单；字段若进入模型上下文、实现或用途匹配，就不属于纯展示。名称或描述影响发现/选择时验证受影响匹配行为，可复用仍有效且未受影响的执行证据；方法正文、适用范围、提示、输入输出契约、数据源及连接变化均按行为变化处理。每次证据复用保存内容分类、摘要和理由，不信任客户端“只改文案”的声明。

默认测试限已授权文件、连接、只读数据与临时产物。外部业务写入使用隔离环境或可验证模拟，真实、隔离和模拟证据分别记录；模拟通过不能满足必要真实上游结论，也不授予正式写入权限。客观检查失败不能通过用户效果确认覆盖，必要的人工效果接受合并到最终审阅。

未完成相应验证的资产可以保存草稿，但不能标已验证或正式启用。接收方不能继承发布者验证和启用。输出检查同时验证真实字段、类型、文件、来源与要求的业务依据；模型声称成功不覆盖平台缺项。

普通运行中，Skill 仍只在节点目标、权限和预算内有限纠错；固定 Tool/代码失败不能触发模型静默改写原资产。已授权创作模式可以修复候选的实现错误、连接及资源问题，形成新候选并复验；改变用户指定算法、口径、目标或交付要求必须先询问。自动修复不能删减冻结的验收标准；预算耗尽或仍失败时保留草稿和已有事实。

## 9. 运行、检查点与恢复

工程状态应区分未开始、执行中、等待输入、等待授权、等待检查、取消中及成功/失败/取消/中断。节点单独记录状态与输出检查，运行状态不能掩盖某步未完成。状态名称是设计示例，现有 API 不因此改变。

默认连续执行，只有交付通过后才进入下一步；检查点发生在已验证完成的节点之后。缺必需输入或权限也暂停，恢复命令绑定当前运行、节点、状态修订与待处理事项，过期回答或重复点击不能启动第二次执行。刷新/关页只影响观察，不取消后台任务。

| 操作 | 必须保证的语义 |
| --- | --- |
| 新运行 / 重新运行 | 新运行身份，以本次版本、参数、文件授权重新取数并执行完整流程，不借旧成功结果跳步 |
| 从中断处继续 | 保持原版本与输入身份，核实已完成节点、输入、输出字节与摘要及准入条件；从失败或未完成处接续 |
| 继续检查点 | 仅释放该运行的当前检查点，不等于重跑、改版本或扩大权限 |
| 取消 | 先阻止后续步骤及迟到成功写入，再停止当前可中断动作；保留已完成事实 |
| 修改实现后运行 | 保存新版本并建立新运行，不嫁接原运行的成功状态 |

继续前无法核实已有结果、输入或外部调用结果时明确报告，不能将未知状态当成功，也不能静默重复可能已发生的外部操作。继续与新运行在界面和服务端命令上均需可区分。

服务重启保留成功节点与检查点，将未结束调用记为中断或结果未知，不自动重跑。恢复需复查当前授权和运行条件；新增输入或权限不能由旧检查点默许。所有状态更新需有执行身份/修订校验，旧线程或重启前迟到回调不能写入新执行结果。

## 10. 接口操作与并发语义

下表定义统一创作操作；已注册HTTP、当前机器字段和状态集中在[接口与存储契约](接口与存储契约.md)的“统一创作契约”维护，未填充的扩展字段与既有兼容接口单独说明。工作区实现不代表正式服务已经加载。

| 操作族 | 输入与结果约束 |
| --- | --- |
| 创作 / 沉淀 / 升级准备 | 本人相关来源，自动整理候选、测试及有限修复；只预览或只保存模式不执行；不提前注册可见正式资产 |
| 草稿编辑 / 版本保存 | 绑定草稿修订、内容和组件快照，校验输入来源及资源完整性；冲突不覆盖他人编辑 |
| 候选验证 / 最终确认 | 自动生成用例、固定授权及证据；用户审阅同一候选，保存与启用依次核验，不额外业务执行 |
| 追加要求 / 恢复 / 追加额度 | 需求修订使过时检查失效；恢复不加额，明确追加授权才建立新额度轮次 |
| 运行 / 继续 / 检查点 / 取消 | 绑定版本、运行、输入摘要与修订；继续和取消不能隐式编辑资产 |
| 详情 / 观察 / 下载 | owner 与来源权限校验；只读不启动执行，完整源码资源与摘要均可检查 |
| 导入 / 导出 / 发布 | 内容快照、依赖和共享预览分离；导入只保存，发布继续沿用明确审阅确认 |

写操作按 owner、操作范围、幂等键和请求内容指纹去重，同键异内容冲突；版本、快照、输入与授权身份纳入对应指纹。跨存储步骤需有可恢复关联，不能把重试当新请求而产生重复版本、调用或启用。状态修订与执行去重分别处理，不能仅靠浏览器按钮防并发。

## 11. 旧资产、导出与权限

旧 recipe、旧 pipeline、来源运行及原数据保留，新入口显示原模式并允许升级。充分记录可恢复候选；历史缺失时可在已授权创作中补充实现并标记生成/推断，不能把旧目标模板当完整历史实现。准备过程按统一授权测试，最终审阅后才提交；查看、文档读取和单纯预览不重跑真实任务。旧资产不必批量改写才能继续使用。

Skill 提供纯标准内容包；Tool/App 包含定义、必要实现、资源与专门准备的示例。包内文件使用安全相对路径、内容摘要和完整清单，导入校验越界路径、缺失资源、格式与运行条件。包格式版本在实施前确定，不能把新含义塞进旧格式而仍宣称完全兼容。

默认不导出账号密钥、连接密文、真实用户文件或完整运行历史。原运行结果另行下载/导出，不与资产包混合。外部依赖只保留可移植需求及说明；接收者重新配置连接、授予文件权限、验证和启用，源码内容本身不授予执行权限。

## 12. 存储迁移、备份和回退

现有状态跨工作台 JSON、应用 SQLite、能力库 SQLite、子任务 SQLite、evolution SQLite 与文件工件，见[数据生命周期](../存储与数据生命周期.md)。下一轮创作会话、候选、计划、预算及提交台账增量存入既有平台SQLite，原资产存储继续负责正式版本；表和关联以[接口与存储契约](接口与存储契约.md)为准。明确快照字节归属、引用完整性及提交顺序，不宣称跨库已有统一事务。

迁移前记录实际工作区/发布版本、原数据格式、迁移范围和备份。在线 SQLite 使用备份接口或停止写入后备份完整相关数据，不遗漏 WAL；JSON、文件与数据库需要一致时点或明确可恢复关系。迁移先在隔离副本验证，不用正式账号数据做写入测试。

升级以保留旧记录、增加明确版本和关联为原则；历史摘要不得批量伪造为完整参数。跨库写入失败需可识别未完成步骤并幂等恢复，不对外暴露缺实现的正式版本或已验证状态。无论物理去重方式如何，删除个人组件不能清除仍被 App 快照使用的字节。

回退保留新格式数据与原件，不让旧代码错误解析新版本，也不回写覆盖原运行。发布前验证新旧入口并存、迁移中断、备份恢复、回退后再升级及权限隔离；本轮已做备份、真实库副本两次增量迁移和正式重启核验；完整恢复及回退再升级尚未演练。

## 13. 持久创作协调、统一预算与提交

### 同一创作对象与连续编辑

聊天卡、详情、任务成果入口、资产库编辑和导入准备都操作同一持久创作对象。保存当前需求、精确目标和基础版本、来源集合、不可变候选、测试计划、证据、授权、预算及待办；不增加第四种用户资产。只创建用户要求的可见资产，辅助组件与资源保存在内部完整快照中，独立提取才注册独立资产。

会话修订与候选内容身份分开。追加要求沿用会话，形成新需求修订和候选；停止旧检查，旧回调只补记旧尝试事实，不能覆盖当前候选或满足新候选准入。除已确认的纯展示/匹配证据复用外，行为候选必须重新验证。取消、回答、恢复和提交绑定最新修订；刷新只恢复观察。

普通分析先发现并复用适合且已启用的个人资产，记录实际采用版本；明确指定不可用时说明原因，不静默替代。参数变化只是本次运行，改变方法则进入创作；普通成功任务不自动沉淀。

### 共享预算与停止

创作每轮共享600秒有效执行、32次实际模型请求和2轮自动修复。所有创作、用例生成、测试、网络/格式重试、嵌套Skill及固定Tool内模型调用都进入同一持久账本；子模块较严格局部上限继续生效。发送前原子预占，发出即计次，失败不退；第32次可在剩余时间内完成，第33次发出前拒绝，无新模型请求的结果检查可以完成。

每轮修复从启动自动改稿时计数；第二轮可在剩余时间和请求额度内完成改稿、复验及审阅，第三轮启动前拒绝。协议重试仍扣模型请求及时间，不能借此无限修改候选。用户追加新需求不算自动修复，但不重置时间和请求额度。

有效时间按会话活动时段累计，包含等待模型/工具响应；并发操作不重复累加。尚未开始的排队、等用户和额度暂停不计时。统一截止传至在途调用；600秒到期中断可取消调用、停止业务处理，仅允许清理并保留已发生或未知事实。清理时间不用于继续执行业务。

恢复处理只使用剩余额度；额度不足且用户明确同意继续才建立下一轮同等额度，旧轮剩余不叠加，累计消费保留。追加、刷新、恢复及服务重启不自动加额。同一次追加确认幂等；回答问题不自动构成追加授权。预算台账细节、恢复与追加额度的机器区分见[接口与存储契约](接口与存储契约.md)。

取消传播至全部子操作，阻止新动作及迟到提交；关闭页面不取消已授权后台工作。重启中断不自动重放，恢复前复查候选、输入、环境及授权；未知外部结果先核实。只展示实际阶段、耗时和请求次数；上游未返回token用量时标未知，不推算精确金额。

### 内部候选验证与最终晋升

三类适配承担准备、验证、结果检查和提交，复用既有执行器及准入。内部候选可持久化和测试，但不将试错版本批量加入可见资产库。测试对象不再要求先创建正式版本；证据固定候选内容、依赖、计划、环境及授权，人工效果接受合并为最终一次审阅。

最终确认只晋升用户审阅的相同内容，重新核对当前候选、独立验证、有效条件及基础资产修订；不生成新内容、不额外跑业务，不让客户端声明代替平台事实。只存草稿无需通过测试。跨库用持久提交阶段、预留目标身份和幂等恢复串联正式版本、证据关联与启用；部分失败显示实际阶段，不重复建资产或改写旧可用版本。基础版本冲突先展示差异并形成新候选，不静默覆盖。

实施顺序与验收范围见[实施与验收计划](实施与验收计划.md)，状态见开发进度（本地资料，未随源码发布）。本轮只定稿文档；后续实现需同步模块契约、进度、总项目状态和变更记录，另行执行业务、迁移和真实服务验收。
