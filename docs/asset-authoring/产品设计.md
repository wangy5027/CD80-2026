## 目标与问题

用户希望把“取得平安银行 000001.SZ 在 2025 年 1 月 1 日至 12 月 31 日的日线行情，分析走势，计算价格变化率和最大回撤”这类成功研究保存为 App，并能检查和修改实际方法。子 agent 临时写出的可视化代码也应保存，即使个人库没有对应的 Skill 或 Tool。

此前完整资产、代码资源、版本和验证能力已经实现，但对话、旧应用分流、统一App和能力库分别组织操作；从对话文字和实际执行沉淀的结果不一致，测试用例及依赖整理仍需要用户处理。本轮让系统统一承担相关历史、实现、参数、依赖、测试及有限修复，用户主要表达要求、处理重要业务歧义和审阅实际效果。

## 统一入口与默认行为

主对话、任务结果沉淀、资产详情修改和导入后准备进入同一持久创作流程，三类资产均覆盖新建、沉淀、修改和导入。用户无需在不同页面重填上下文、手选技术步骤或组织测试JSON。社区发布与分享体验不在本轮重做。

“做一个……”“把刚才的方法沉淀下来”“把这个改成……”默认授权系统整理实现、生成测试、在已有权限和预算内试跑及有限修复。“保存当前草稿”“只保存”“先别测试”仅保留草稿，不重新执行资产。语义确实不清且影响执行范围时，提出一个具体问题。

系统自动读取当前会话及明确关联的资产、来源任务、实际执行和文件。用户指向以前的研究时查找本人相关历史，重要歧义才询问；不默认把全部历史送给模型，不读取无关或跨账号材料。系统可推荐资产类型，用户明确指定时尊重选择；无法兑现时说明原因，不悄悄换类型。

默认只新增用户要求的可见资产，必要组件和资源完整保留在内部快照中；仅在明确要求独立复用时提取为个人Tool或Skill。临时验证候选不逐个进入个人资产库。

## 三类资产

| 资产 | 保存内容 | 对外调用与执行边界 |
| --- | --- | --- |
| Tool | 明确的实现、输入输出契约、必要源码与资源；内部可以包含多个固定步骤及固定的模型调用流程 | 按参数调用，返回约定结构；固定的是契约与实现，不是每次返回的数值。模型不能自行改写 Tool 或扩展执行流程 |
| Skill | 标准 Agent Skills 的方法、工具使用说明、辅助代码、参考资料和资源 | 接受任务、数据及约束，动态选择内部方法、工具和代码；不因包含多次工具调用就变成 App |
| App | Tool、Skill、内嵌代码构成的步骤、输入来源、输出要求、固定规则与组件版本快照 | 正常运行复用保存的编排和固定实现；Skill 在本步骤目标与约束内动态执行，逐步交付并形成最终结果 |

Skill 沿用 [Agent Skills 标准](https://agentskills.io/specification)，最小内容是带元数据与方法正文的 SKILL.md，可包含 scripts、references、assets 及其他必要文件。工具绑定、验证和启用状态由平台另外管理。“一次逻辑交付”是 App 调用 Skill 时的运行边界，不是新增一种 Skill 格式，也不按消息、文件或流式文本数量区分资产。

## 从任务沉淀资产

用户在对话或已有入口提出沉淀要求后，Creator结合相关消息和完整实际执行证据，提炼方法、适用范围、代码与资源、必要依赖、参数和连接，生成使用说明与验证用例。无需再次输入“请整理”才启动模型提炼；用户可以在原对话连续修改。

真实历史流程恢复以最终交付依赖的成功步骤及必要前置处理为依据。失败尝试、已替换代码和未采用结果留在原记录，可以帮助理解错误，但不能当作成功实现。实际运行原件、推断的范围或连接、修改及新生成内容分别标注来源；新内容不能继承历史成功。

历史缺少采用关联时，系统结合对话及真实结果自动推荐范围并继续整理，只有不同选择影响业务含义且无法可靠判断时才询问。用户仍可在高级入口明确选步。纯讨论也可生成新实现，部分完成任务也可整理成功部分；必须说明推断或新增内容，不补造旧任务的采用关系和成功结论。无历史实现指纹的内置Tool采用受控当前接口适配并重新验证。

临时绘图或计算代码可直接作为 App 内部步骤保存，无需先注册为个人 Tool。用户以后可以把一个或多个固定步骤整理成 Tool；包含动态 Skill 决策的流程，需要先整理成明确实现并验证，不能仅更换资产名称。

保存 Skill 时保留真正需要的方法、工具说明、辅助脚本和资源，避免只摘录步骤目的而丢失执行所需内容；也不机械复制整个研究日志。

## 参数和固定规则

保存前自动生成“可变输入与固定规则”清单，用户可以调整后确认。股票、日期、文件等运行输入应贯穿提示、代码、工具调用和步骤连接；历史文件标识、临时路径需要转换为本次输入或前序结果的引用。

价格变化率与最大回撤的算法、数据口径等固定规则明确保存。日线或周线等选项可以按实际能力形成带默认值的参数，不把单一案例里的全部常量自动当作可变字段。无法可靠参数化的地方显示具体缺口，不能保存成表面可改、内部仍写死的 App。

## 统一详情与编辑

App、Tool和Skill在原对话保留资产卡，桌面详情面板与资产库打开同一对象；手机使用全屏详情，返回后继续原会话。旧资产保留运行，编辑或升级时接入统一流程。

主卡展示用途、实际阶段、结果摘要和下一步。详情展示输入、固定规则、方法、检查结果、来源及版本；App以纵向步骤展示目的、组件及交付。自然语言为主要编辑入口，实际源码、Skill文件、测试输入和连接放在可展开的高级详情中。

修改先展示具体变化，再保存为新版本；默认修改该 App 内的副本，不反向修改个人库组件。原版本和历史运行保留，影响行为的修改重新验证。

系统处理期间允许直接追加要求，沿用同一草稿并形成需求修订；停止不适用的旧检查，迟到结果不能覆盖新要求。保存确认绑定用户审阅的那份内容。草稿及执行进度可恢复，页面关闭不取消后台处理，刷新和追加要求不重置预算。

纯展示名称或标签等不影响执行的字段只做静态检查。名称、描述若影响发现或选择，需验证匹配行为，可复用未受影响的执行证据；实现、参数、数据源、方法、适用范围、提示词、流程或交付变化须重新验证。由服务端判断修改范围，不能仅信任“只改文案”的声明。

## 对话中的使用

普通任务主动检查并复用适合且已启用的个人资产，说明实际采用对象及版本。多个候选的方法差异会影响结果时才询问；用户明确指定的资产不可用时说明原因，不能静默替代。无合适资产时仍可完成临时任务，普通执行不自动沉淀。

更换股票、日期、文件等已有参数属于新运行；改变方法、算法或规则进入修改流程。正常运行不静默改写固定实现，个人组件更新不改变其他App快照；界面可展示来源和可升级关系。

## 顺序执行与逻辑交付

首版 App 支持顺序执行、引用任意前序步骤结果，以及合并多个结果作为输入。App 层面的条件分支、通用循环、并行和嵌套调用不在首版范围；该限制不把 Tool 或 Skill 内部约束为单步。

App 默认连续执行并逐步展示结果。用户可为步骤设置“检查后继续”；缺少必需输入、必要授权或到达检查点时暂停，用户可以取消。

每步由 App 明确下游需要的数据、字段、文件和依据。Skill 的标准正文保持通用，具体要求由本次调用传入。平台核实真实交付后才进入下一步；Skill 可在既定范围内有限纠错，仍不满足要求则停在该步，展示缺失项并保留成功结果。

“重新运行”按本次参数重新取数并执行完整流程；“从中断处继续”只复用版本、输入和结果均可核实的成功步骤，从失败或未完成处接续。失败或服务重启后保留完成记录，修改代码形成新版本后开启新运行。刷新或关闭网页不影响后台执行，再打开可以继续观察。

## 保存与验证

创作默认自动准备与验证，最后展示用途、可变输入、关键规则、各组实际示例结果和限制。主操作“确认保存并使用”在一次审阅后保存已验证的相同内容并启用，不重新生成实现，也不额外执行业务。必要的Skill/动态App效果判断并入这次确认；用户可以展开全部结果，不强迫逐案额外点击接受。

保留“只存草稿”和“继续修改”。草稿可随时保留，明确显示已保存；失败、条件缺失或额度耗尽时保留成果、证据和具体下一步。单纯预览、保存草稿和导入不隐式执行；导入后明确“准备使用”进入默认自动创作流程。后台仍分别记录保存、验证、启用，未通过不能显示可使用，用户确认不能覆盖客观失败。

平台负责格式检查、实际执行和证据，Creator不能自行宣布验证通过。生成用例与修复实现不能降低用户要求；预期来自业务规则、独立计算、可信样例或可核实约束，不能复制待测输出作为正确答案。候选测试不需要先向个人库新增正式版本；最终提交绑定精确候选、测试及当前运行条件。

验证覆盖原任务对应的预期，以及至少一个不同输入的适用用例。Tool 检查实际计算和输出契约，Skill 检查任务效果、工具使用与交付，App 检查步骤连接、中间结果与最终交付。完成相应验证后才标记为已验证并允许正式启用。验证范围及所用版本、输入和环境可追溯，不由一次成功推断任意输入都可靠。

默认测试使用已授权文件、已有连接和只读数据，允许临时图表与结果文件。外部业务写入使用隔离环境或可验证模拟；缺少合适条件时保留草稿并说明。模拟、隔离和真实上游证据分别记录，模拟成功不等于真实服务验证或实际写入授权。

## 自动修复与处理预算

创作期间可自动修复候选的实现错误、参数连接和资源缺漏。用户指定的算法、数据口径、目标或交付要求需要改变时先询问，既有可用版本保持稳定。普通运行失败不静默修改Tool或App。

一轮创作共用10分钟有效执行时间、32次实际模型请求和2轮自动修复，重试、子Skill和固定Tool内部模型调用均纳入。模型失败请求也计数；第32次可在剩余时间内完成，第33次发送前阻止。第2轮修复可完成改稿和复验，第3轮启动被拒绝。600秒截止约束在途执行，不能在最后一秒启动调用后继续无限执行。

等待用户和未开始的排队不计有效时间，并发分支不重复累计；刷新、追加要求、恢复不重置预算。恢复沿用剩余额度；预算不足且用户明确同意追加预算后继续时，幂等追加一轮同等额度，旧轮余额不叠加，累计消费保留。普通回复“继续”不能自动加额。界面展示真实进度、耗时和请求数，缺失用量标未知，不宣传精确费用上限。

取消停止后续调用并传播到子执行，保留成果；服务重启标记中断，不自动重放。继续前核对候选、权限、配置和实际结果，未知外部效果不能直接重试。精确计数与恢复契约见[技术规范](技术规范.md)及[接口与存储契约](接口与存储契约.md)。

## 组件快照与迁移

App 保存本地可保存的 Tool 源码、Skill 方法与资源、内嵌代码的完整版本快照及来源。个人库的修改、删除不改变已保存 App；升级依赖需要显式修改 App 版本。外部服务和运行环境仍是明确依赖，行情每次按新运行参数读取。

标准 Skill 可完整导入和导出。缺少本机工具或语言环境时，仍保留合法 Skill 的完整内容，显示运行条件缺口；不删除资源或用平台特有清单重新定义 Skill。通用格式不保证任意环境无需配置就能执行。

Skill 可导出纯标准包，Tool 和 App 可导出完整实现包。默认包含定义、必要资源及专门准备的示例，不携带账号密钥、真实用户上传或完整运行历史。运行结果另行下载或导出；接收方使用自己的连接、文件授权，重新验证和启用。

## 旧应用升级

旧 App 与原任务保留。有充分真实记录时，可生成新版 App 草稿，展示恢复步骤、代码和待补内容，经确认再保存。记录不足时指出缺口，通过重新执行或补充实现完成升级；推测和新生成内容不能标成历史实际执行内容。平安银行旧 App 按同样规则检查，不预先声称它的历史记录足够或原数据完整。
