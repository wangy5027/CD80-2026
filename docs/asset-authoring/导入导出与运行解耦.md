# 三类资产导入导出与运行解耦

日期：2026-10-14（Asia/Shanghai）。用户已明确 App、Tool、Skill 均支持外部导入、平台创建和导出；完整保存或导出不承诺能在当前平台、其他平台运行。本页是本轮增量实现约束，验证结果在交付时补记；统一创作流程仍以[产品设计](产品设计.md)、[技术规范](技术规范.md)和[接口与存储契约](接口与存储契约.md)为准。

## 用户行为

导入先完整保存用户提供的原始字节，显示类型、名称、原件格式、大小和“原件已保存，尚未准备运行”。标准 Skill、平台 Tool/App 包和未知外部单文件或 ZIP 均可保存；未知协议、缺少依赖、平台不支持其执行语言，都不是丢弃原件的理由。文件安全和体积检查仍执行，危险 ZIP 路径、链接、重复项、加密或异常压缩包拒绝接收。

保存原件不执行代码、不联网、不创建连接、不继承原作者授权、验证或启用。用户明确选择“准备使用”后才进入统一创作，系统读取本人原件并检查可适配内容；未知格式保留完整原件并给出准备缺口，不能宣称可运行。对话、详情与资产库以原件身份引用该来源。

“导出原件”按导入时的字节原样下载，保留文件名、完整资源和摘要；不以验证、启用或运行环境作为前提。用户本人原件下载与发布、共享或格式转换分开：原件不会补入平台凭据，转换包继续遵守完整性与敏感内容检查；无法无损转换时仍可导出原件，不静默删文件。

平台创建的三类资产继续沿用既有完整包导出。能力库的原件/标准 Skill/平台包导出无需执行准入；App 导出只读取保存内容，不依赖当前运行条件。导入原件不是第四类用户资产，仅是 App/Tool/Skill 的外部来源保存形态。

## 原件接口

统一前缀 `/desktop/api/portable-assets`，沿用本机来源校验、Cookie 和 owner 隔离。

| 操作 | 请求与结果 |
| --- | --- |
| POST `/imports` | multipart：`file`、`kind=app|tool|skill`、可选`name`；必需`Idempotency-Key`。安全检查后201返回原件记录，同键同内容复用同记录，同键异内容409 |
| GET 集合 | 可选`kind`筛选，返回`{items}`；仅读取本人原件 |
| GET `/{id}` | 本人原件元数据，其他账号404 |
| GET `/{id}/export` | 原始字节附件，原文件名，`no-store/nosniff`，不触发运行或准备 |

原件记录包含 `id,kind,name,sourceFormat,status=stored,runtimeReadiness=unprepared,originalName,sha256,size,files,issues,createdAt,exportUrl`。`files`仅列路径、字节数及SHA256，不在列表塞入源码或二进制。`sourceFormat`只描述识别的格式，不证明其结构、权限或运行有效。未知格式用 `external`，未准备状态与检查问题不混作导入失败。

统一创作来源使用 `{kind:'import_draft',reference:{portableAssetId}}`。内部 `portable_assets.read_source(library,owner,id)` 仅解析本人原件，返回 `kind,name,sha256,sourceFormat,files,issues,content`：已识别 App 为 `{definition}`，Skill/Tool为 `{draft}`；未知或不可适配格式 `content=null` 并给出 `SOURCE_NEEDS_EDIT`。归一化内容与原件分离，原件字节不改写；不能把JSON内的启用/验证/账号身份作为实际授权。

## 持久化、安全与兼容

复用能力库 `capability_records` 的 `portable_asset`、`portable_request` 类型及 `capability_blobs`，记录、原件与幂等结果同一 SQLite 事务。原始字节以账号及内容摘要存储；没有新数据库或后台任务，不需要额外迁移，现有备份覆盖原件。回退保留这些新记录，旧代码忽略它们。

原件最多20 MiB；ZIP最多500项，单展开文件1 MiB、总展开50 MiB，路径深度12，沿用受控压缩比。不写到宿主文件系统、不解压执行、不安装依赖。Unicode/大小写冲突、路径穿越、特殊文件、符号链接、加密及损坏ZIP拒绝；扩展名伪装的ZIP也做同样检查。单文件原件不以平台是否理解内容作为保存条件。

旧 `/capabilities/imports`、App包接口保留其原生结构化导入职责；新增通用原件入口承载外部格式，不把原件保存状态冒充旧运行资产状态。所有下载和内部读取再次检查本人归属及摘要。原件保存和导出不创建模型调用、Tool调用、验证记录或启用状态。

## 验收要求

- App、Tool、Skill 的未知外部单文件和安全ZIP均完整往返，包含二进制和不支持语言资源；跨账号不能读取或下载。
- 标准Skill、平台Tool/App原件可保存并提供只读创作适配；缺连接、无WASI或不支持执行不能影响原件保存与导出。
- 路径穿越、伪装ZIP、链接、大小写/Unicode冲突、压缩限制及损坏文件被拒绝；同键重试不重复保存，冲突不覆盖原件。
- 既有未验证、停用、缺运行条件的能力仍可导出其保存内容；导入及导出过程没有模型、执行器或外部调用。
- 准备失败保留原件，解析候选不继承包中的权限/验证/启用声明，不静默删减资源。

## 本项实现与验证

实现：已新增原件保存/列表/详情/原样下载、只读创作来源适配和公共ZIP安全读取；保存采用现有能力库事务与账号隔离。既有能力库 `format=original` 下载按本人原件读取，不再被转换包的秘密扫描阻断；平台转换与发布检查保留。正式服务加载和统一前端衔接由总集成记录单独确认。

隔离验证：原件专项、能力库既有生命周期与组件联合55项通过（60.375秒）；随后补齐实际DEFLATE损坏包拒绝及测试上传临时流关闭，原件专项11项再次通过（4.451秒，无警告）。命令为 `python -X utf8 -m unittest tests.test_portable_assets tests.test_capability_library tests.test_asset_components -q`，最终增量为 `python -X utf8 -m unittest tests.test_portable_assets -q`。均使用项目虚拟环境、临时账号和临时数据库；原件专项对模型/执行路径设置禁止调用检查，未触碰正式数据或真实模型。55项包含原件11项，不能相加。此前一次专项出现测试上传临时流的ResourceWarning，已关闭输入流并重跑消除。

边界：未知格式及旧 `infinity-application` 原件可完整保存与导出；当前只读创作适配支持标准Skill、平台Tool/组件以及 `cd80.app/2`、`cd80.app-package/2`，其他格式返回明确准备缺口。通过原件存储验收不证明第三方包在本平台或外部可运行，也不代表统一创作整体已验收。
