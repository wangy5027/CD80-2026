# 保存原用例与可选追加测试

日期：2026-10-15。依据：用户要求 APP、Skill、Tool 保存时带好原任务用例，取消必须两组输入的测试门槛。当前状态：已实施并验收，正式服务已重启。证据见本轮验收（本地资料，未随源码发布）。

## 使用流程

保存版本时同步保存测试用例，仍为未验证，保存不执行实现。详情自动填入本版本原任务的输入和独立预期，提供“一键填入原用例”。用户可以编辑本次测试；轮询不能覆盖编辑，切换账号、资产或版本重新初始化。

原任务用例为必测项。不同输入放入默认折叠的可选区域，只有明确勾选追加测试才提交；展开、填写或一键填入均不执行。默认只执行原例，通过后可沿现有流程启用；显式追加的用例失败仍使本次整体验证失败。Skill 的效果确认保留，文字调整为本次所选用例。官方及已公开 Skill/Tool 的免验证规则不变。

## 数据与接口

每个精确版本及其详情响应增加 `testCases` 数组，第 0 项是原任务模板；保存请求支持携带同名字段。APP 为 `{label,input,fileBindings,expectation}`，Tool 为 `{label,input,fileIds,expectation}`，Skill 同 Tool 但 expectation 为 `{mode:"manual_review",prompt,criteria}`。预期沿用既有验证协议，不产生第二套运行器。外部包和完整导出保留测试元数据；源码、业务 outputs 与运行结果不得混入验证标志。

原例来源优先使用明确保存的测试案例、包中 examples、原测试计划或已保存的原始预期，不能把实际执行结果复制为预期。自然语言生成同时整理输入及从任务规则推导的独立预期。未附案例的旧版本或通用外部包，从接口默认值/示例和任务说明生成静态输入候选；不能推导业务预期时保存 `expectation:null` 并明确待补。合法实现仍能保存，不能用空精确结果冒充正确预期。静态候选不代表历史真实输入，授权文件由当前用户明确选择，跨账号复制不得继承私人文件引用。

独立验证接受 1–10 个用例，至少首项有完整输入及预期。测试计划默认只生成 original；different_input、boundary 可以显式追加，不能再成为原例通过后的准入门槛。已有双例证据继续有效，配置/版本/授权变化导致证据失效的现有规则保留。测试/审阅、启用、发布引用同一有效证据规则。

## 验收

- 三类保存后重新读取均有版本归属明确的原例；APP JSON/ZIP 往返、Skill/Tool 导入与创建覆盖。
- 仅原例真实执行可通过并启用；空用例或缺预期不能通过；选择追加且失败不能误判成功。
- 默认不展示第二表单、不提交第二例；恢复按钮回填模板；版本/账号隔离、轮询保留编辑。
- 保存、导入和预填不执行待测代码；实际测试不削弱文件归属、配置与官方/公开免验证边界。
- 前端构建、针对性回归与浏览器检查通过后，重启实际服务并核对健康和所服务资源。
