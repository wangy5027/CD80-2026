# 统一创作开发与外部接入指南

更新：2026-10-15。技能池 APP 的当前入口与外部格式见[两种创建入口](../integration/APP两种创建入口.md)，统一运行定义始终为 `cd80.app/2`。APP 得到完整实现后立即保存为未验证版本；后续在已保存详情修改、配置和验证。以下原件保管接口继续兼容，不代替技能池的标准 APP 导入。真实模型、金融上游和正式实例加载状态见开发进度（本地资料，未随源码发布）。旧`infinity-application`、recipe和pipeline资料仍供兼容运行，不是新建App的首选格式。

## 三类资产的入口

App保存`cd80.app/2`定义及完整内嵌组件；Tool保存固定实现、输入输出与资源；Skill保存标准`SKILL.md`、脚本、参考资料和资源。平台创建通过统一创作；外部提供的格式不必已经符合平台执行器，先作为原件保存即可。保存、导出、准备运行和启用分别记录。

外部程序使用登录Cookie及合法本机Host/Origin；写操作带不重复的`Idempotency-Key`。本机API并非公开托管服务或OAuth接口。字段的唯一权威定义见[接口与存储契约](接口与存储契约.md)。

1. `POST /desktop/api/portable-assets/imports`提交multipart `file,kind=app|tool|skill,name?`。响应返回原件ID、摘要、格式与`runtimeReadiness=unprepared`；不调用模型或运行代码。
2. `GET /desktop/api/portable-assets/{id}/export`始终读取本人原件并核对摘要。不能运行、未验证或未启用不影响下载；未知安全格式不被静默转换或删文件。
3. 用户选择“准备使用”后，`POST /desktop/api/authoring-sessions`提交`{kind,intent:"prepare_import",instruction,sourceRefs:[{kind:"import_draft",reference:{portableAssetId}}]}`。平台已识别的定义成为候选；不认识的格式保留原件并询问必要适配资料，不假称可运行。
4. 平台直接创建使用`intent=create`与自然语言要求；修改已有资产使用`intent=edit,target:{assetId,baseVersionId,baseRevision}`。APP 的 `mode=prepare` 只生成完整定义并纯保存，不执行或验证；Skill/Tool 保留各自准备规则。`mode=draft_only`仅保留要求/草稿，不表示已创建 APP；技能池自然语言创建不提供这个容易混淆的快捷选项。
5. 观察GET详情；补要求调用`messages`，回答当前问题调用`answers`，均绑定当前revision。正常等待不需要轮询请求触发执行。模型未知回复和预算追加各有明确确认，不能用刷新、回答或重试悄悄增加额度。
6. APP 会话完成后直接从 `session.result.assetId/versionId` 打开已保存的精确版本，显示未验证；只有用户后续在详情发起验证且通过，才可主动启用。APP 不再允许旧 `confirm mode=save_and_enable`。Skill/Tool 原创作的确认流程仍按对应准入规则执行，不与 APP 流程混用。

导出标准Skill或平台Tool/App包可使用现有资产导出接口；已有未验证、未启用资产同样可导出其可保存内容。原件下载与转换为平台格式的导出分开；原件完整保存不代表允许向其他账号发布其中的私人内容。标准包、路径、容量和未知格式行为见[导入导出规范](导入导出与运行解耦.md)。

## 源码职责

| 文件 | 职责 |
| --- | --- |
| `backend/app/modules/agent_platform/authoring.py` | 同一会话的生成、候选、计划、修复、最终确认与并发修订 |
| `authoring_store.py`、`authoring_budget.py` | 本人持久化、幂等、重启恢复和600秒/32请求/2修复账本 |
| `authoring_context.py`、`authoring_chat.py`、`authoring_routes.py` | 来源归属、主对话接入及HTTP信封 |
| `authoring_adapters.py` | 三类私有候选的实际检查、证据和正式资产事务提交 |
| `backend/app/modules/workbench/graph_runtime.py` | 真实模型传输入口的统一预算许可、超时与在途停止 |
| `backend/app/modules/capability_library/portable_assets.py`、`portable_routes.py` | 原件保存/读取/导出与只读解析，不接管运行准入 |

正式App和能力库仍使用各自存储；APP 完整定义形成后即注册为本人可见的未验证资产，空需求或缺少实现的会话不制造占位应用。表采用既有SQLite增量建表，原件使用既有能力库存储和blob。正式数据备份、迁移、回退属于独立维护步骤，不能拿临时测试结果代替。

## 本地检查

在仓库根使用既有虚拟环境，临时数据库和合成输入；不读取正式账号、不连接真实模型：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_authoring_sessions tests.test_authoring_budget tests.test_authoring_adapters tests.test_authoring_integration tests.test_portable_assets -v
```

会话测试使用可控适配器；预算测试直接走真实provider代码但mock HTTP；候选/集成测试使用模型替身和真实WASI。这些层次验证的是协议、隔离执行及恢复，不能证明真实LLM对所有需求都能生成正确方法。前端、浏览器命令和记录从[测试指南](../../tests/README.md)及实施验收（本地资料，未随源码发布）进入。

真实模型检查使用显式入口，按本次任务授权运行，会消费配置模型的正常额度：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/verify_conversation_authoring_live.py --run --kind all
```

`--kind`可选`app|tool|skill|all`。脚本从环境变量或`.env`读取`GITEE_AI_*`模型配置；创建临时`DATA_DIR`和一次性账号，只发送合成整数汇总需求，使用真实模型与真实WASI完成双输入验证、最后确认并保存到临时库，不读取正式历史或金融数据。每个创作会话仍受600秒/32请求/2修复共享上限约束；脚本最多等待660秒以观察停止和收尾。逐次时间戳JSON报告保存在`data/conversation-authoring-live/`，包含候选、计划、实际证据、预算及提交结果，初轮失败也保留。脚本存在不代表执行通过，当前结果以实施验收（本地资料，未随源码发布）为准。
