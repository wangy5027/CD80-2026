# Skills 与 Tools 双栏目录

2026-10-14，按用户要求复用 Apps 的目录、详情和创建交互。实现、自动化、隔离浏览器与正式服务验证通过，见本轮验收（本地资料，未随源码发布）。

## 产品设计

Skills、Tools 各自显示上下两栏：上栏为当前账号的“我的 Skills / 我的 Tools”，右侧提供创建入口；下栏为官方能力与其他用户主动发布的“平台 Skills / 平台 Tools”。两栏独立搜索，卡片显示来源、版本状态和是否已拥有。不得展示其他用户私人草稿，也不自动把全部公共能力安装到个人库。

点击任意卡片打开与 Apps 一致的详情悬浮窗，左上角显示“添加为我的 Skill / Tool”或“已拥有”。详情展示用途、精确版本、输入输出、权限、依赖及文件清单。添加保存独立个人副本，不自动验证、启用或执行。已有同一精确内容版本时复用已有副本，不因名称相同误判。个人资产详情提供“管理与验证”，进入原管理器处理源码、版本、验证、启用、连接、发布等操作。目录另保留能力管理和公开目录入口；原有外部资产跳转、对话沉淀和连接管理必须继续可用。

创建支持现有分项填写，以及完整原件录入或上传。Skill 使用 SKILL.md 及可选资源；Tool 使用 name、description、input_schema 定义及可选独立执行实现和资源，执行实现不是 Tool 标准定义的一部分。ZIP 可保留目录与资源。上传先离线预览解析结果、文件及兼容性，再确认保存；无执行实现的 Tool 如实显示待配置，不能启用。用户上传的原始字节保留，原有验证和权限门禁不变。

## 技术规范

新 CapabilityDirectoryPanel 复用 Apps 的共享目录样式，kind 参数统一驱动 Skills/Tools；个人库与官方库沿用 capabilities/assets 分页接口，其他人公开项沿用 community/capabilities。所有请求按账号隔离并取消过期响应。能力已拥有关系按 kind、来源标识与精确内容摘要匹配当前账号所有未删除资产的版本，不能只检查最新版本。官方准备与社区复制增加兼容的 ensureOwned 语义，重复请求键及不同键重复添加都不重复创建；既有 confirmDuplicate 操作保持兼容。

新 CapabilityCreatePanel 组合现有 SkillPoolEditor 和完整原件上传流程。新增只读 multipart 预览接口，使用与导入完全相同的包解析规则，返回标准元数据、文件清单、静态问题和原件摘要。保存仍复用原导入 job，核对预览摘要以保证保存的是同一份原件。扩展原生 Tool ZIP 对 tool.json、可选 tool.py 和资源的适配；不接受路径穿越、链接、歧义入口和超限文件，不在预览或导入时执行代码。结果未知时保留原提交及幂等身份，重试确认同一操作，账号切换不混入新账号。

SkillPoolPanel 区分目录与完整管理视图；外部 initialAssetId/initialCapture 直达管理器。连接管理先挂载再触发，避免 watcher 丢失请求。创建成功刷新目录并打开精确保存版本。Apps 仅抽取样式共享，业务行为保持现状。

## 验收条件

覆盖我的/平台分页、独立搜索、两类详情、官方与社区添加、已有旧版本识别、重复添加、公开/私人隔离、手填与上传创建、原件保留、待配置状态、管理/连接/沉淀跳转、账号切换及小屏滚动。自动化和隔离账号浏览器验证后构建正式页面；按用户要求重启实际服务，核对健康和线上资源摘要。不得用正式账号或历史数据做验收写入。
