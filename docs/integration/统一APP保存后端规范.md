# 统一 APP 保存优先后端规范

状态：2026-10-15 后端实现与隔离测试完成，正式服务加载和真实模型全流程另验。本页记录当前契约；不将旧验收倒写为新行为。

## 范围与顺序

面向用户的 APP 创建、改版、组合、导入及添加公共版本，在获得可保存的 `cd80.app/2` 定义后，首先写入当前账号的 `AssetApps`。返回精确 `assetId`、`versionId`，并使该版本 `verification.status=unverified`，不自动启用、执行或继承来源验证。空白入口和只有需求文字、尚无定义的创作会话不制造空 APP。保存允许静态缺口；运行和启用仍由底层 API 阻止不完整或未通过验证的版本。后续对定义的修改是同一 APP 的新不可变版本，验证与启用在已保存 APP 的详情中进行。旧已启用版本可继续保持启用，但新版本独立未验证。

统一对话创作的 `mode=prepare` 对 APP 仅执行生成、来源核实与静态整理，然后保存并结束；不启动两例测试或候选自动修复。用户说“生成后只保存为未验证”“不要运行/测试/启用”仍属 `prepare`，不能因“只保存”跳过生成；只有明确 `mode=draft_only` 或明确“仅记录想法、暂不生成 APP”才停留在文字草稿。追加消息和失败恢复遵循同一判别。会话进入 `phase=completed`，`session.result` 至少为 `{assetId,versionId}`，创建的异步首响应仍可为 `preparing`；详情与列表保存后持续返回该关系。APP 的旧 `confirm(save_and_enable)` 在服务端拒绝；客户端显示已保存未验证，并进入 APP 详情。`mode=draft_only` 仅保留尚无完整定义的创作请求，不承诺产生 APP。Skill/Tool 的独立保存规则另有规范。

技能池的自然语言入口直接建立 `kind=app` 创作会话，继续使用同一 `cd80.app/2` 生成器。模型可见的创作组件目录只列当前账号、未删除、静态内容有效且无凭据问题的 Skill/Tool 精确版本；未启用或尚未验证的版本可用于设计与冻结快照，但不能因此获得运行准入。目录只传名称、说明、接口 Schema、Skill 任务提示及运行状态，不传源码、完整资源或连接凭据；生成结果只能引用目录中给出的精确 `componentRef`。模型返回必要的具体问题时，会话进入 `awaiting_input`，用户回答与原问题一起进入下一轮。仅名称或没有可识别代码入口、精确组件引用的空候选不保存为 APP，而是要求补齐实现；已有具体步骤但仍有静态运行缺口的版本可以先保存未验证。此创作目录不修改平台现有的可运行组件准入目录。

手写 JSON、组件组合、文件导入及公共现代版本复制继续调用现有 `AssetApps` 保存路径。应用工坊生成后即调用同一保存路径；策略工坊的个人回测策略是独立专有策略实例，不冒充 `cd80.app/2`。仍可见的旧预置与旧发布版本“添加/复制”，以及旧运行接受保存、旧导入与改编接口，把完整固定流程/依赖转换成现代定义并纯保存；原旧运行和历史读取不迁移。旧 `/asset-apps/creator` 在实际形成具体定义后也立即保存，空白编辑入口不制造占位 APP。无法恢复完整实现时保留静态缺口，绝不构造可运行的假实现。旧接口回包保留必要显示字段，并新增顶层 `assetId`、`versionId`、`detail`，便于跳转统一详情。

## 数据身份与失败恢复

`asset_apps` 是 APP 的唯一现代个人目录；`asset_versions` 保存定义及冻结的 code、Tool/Skill 组件快照、资源、固定提示和绑定需求。个人连接配置与版本分离；源码、标准资源不依赖未来组件当前版本。`authoring_model_traces` 保存统一创作实际发给模型的 system/user 等消息，`asset_creator_traces` 保存旧 Creator 的真实生成请求；均按账号隔离，消息先用现有凭据清理规则脱敏，再以有界记录持久化。读取分别为 `GET /desktop/api/authoring-sessions/<sessionId>/model-traces/<traceId>` 和 `GET /desktop/api/asset-apps/<assetId>/creator-traces/<traceId>`，仅本人、`no-store`。版本的 `authoringProvenance` 关联会话、候选和 trace ID，旧 Creator 版本也关联自身请求摘要与 trace ID。凭据、Cookie、HTTP 头及推理内容不进入普通资产定义或公开导出；脱敏字段无法逐字还原。用户运行时临时产生的代码和模型消息只属于该次运行证据，不反写已保存 APP 的固定定义。

创作会话与现代 APP 表同属平台 SQLite。APP 保存与会话结果/来源收据在同一事务提交；幂等键固定到会话和候选，同键同内容重试得到同一版本，同键不同内容拒绝。已有 APP 改版同时核对账号、基础版本和 revision；并发更新返回冲突，不覆盖。未知结果先查询原会话或原请求，不生成第二版本。任何后端入口都不能直接把未验证版本设为启用；启用仍要求当前精确版本已有实际通过的双例证据且运行环境摘要匹配。

旧预置复制、固定流程导入/改编及旧运行接受保存与现代版本共用平台 SQLite 事务，一次成功返回一组旧身份和现代身份。旧研究应用发布副本还使用独立的 evolution SQLite，现代版本以 `publicationId + Idempotency-Key` 稳定去重；失败重试可补齐原请求，无法宣称跨这两个 SQLite 文件原子提交。研究应用包的完整便携原件保留在现代定义的来源字段，个人解析后的能力绑定只留本人资产元数据；由于原动态研究流程不能无损自动变成固定节点，静态缺口明确阻止验证/启用，用户须在已保存详情中实现。

## 验收边界

隔离库定向测试覆盖：创作即保存且不调用测试执行器；跨账号不可读；重复请求只保存一次；旧 `save_and_enable` API 拒绝；旧预置、公开复制、导入和改编纯保存；真实 provider 请求 trace 的账号隔离与脱敏、session/candidate/version 关联；已启用旧版改版后继续保持旧版启用，新版保持未验证。正式服务、浏览器、真实模型及重启验收单独留证，不能由这些测试推定。
