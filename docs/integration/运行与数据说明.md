# 最终版运行与数据说明

本说明以[根 README](../../README.md)、[Mac 本地指南](../../LOCAL-MAC.md)及[功能对应表](../../整合说明与功能对应表.md)为入口。来源 `../main-code`、`../应用1`、`../网站_v10121930` 仅作为只读参考；最终版从新账号与空私人历史开始，原目录的账号、对话、上传、个人应用、研究、回测记录不迁入。运行中新增的记录会保存在最终版，不能再把当前运行库描述成“仍为空”。

## 服务与端口

根目录的[启动](../../启动最终版.command)、[停止](../../停止最终版.command)、[重启](../../重启最终版.command)三个 Mac 脚本调用 `scripts/manage_local.py`，由它监督 `cd80-data-api/scripts/start_all.py`。该联合启动器先在回环地址启动金融数据服务，再启动 Flask 主站。默认主站 `127.0.0.1:8894/desktop/`，数据服务 `127.0.0.1:8897/docs`；健康接口分别是 `/desktop/health` 和 `/health`。进程记录在 `.run/server.json`，合并服务日志在 `.run/server.log`，仅停止由当前最终版目录启动且可核对归属的监督进程。不要依赖旧来源的端口或进程。

## 数据与配置边界

| 位置 | 性质与用途 | 处理规则 |
| --- | --- | --- |
| 根 `.env`、`cd80-data-api/.env` | 主站模型、搜索、金融服务地址、管理员与读取令牌等后端配置 | 私有文件，不在文档、浏览器包、公开源码或日志中展示秘密值；现有文件不覆盖。 |
| 根 `data/`（`DATA_DIR=data`） | 最终版账号、聊天、探索、策略、能力、应用制品等正式运行状态 | 新实例不导入来源私人历史；运行后的新数据需备份并保留。`IMPORT_LEGACY_HISTORY=0`。 |
| 根 `data/.capability-mcp-key-v1` | Mac/Linux MCP 连接凭据加密密钥 | 与相应数据库成套、私密备份；权限必须为 `0600`，丢失或损坏时加密凭据无法读取，不能生成新密钥冒充恢复。 |
| `cd80-data-api/data/cd80.sqlite3` | 可重用的公共金融数据 SQLite；数据服务的 `CD80_DB_PATH` | 与个人业务历史不同。服务目录中的相对路径为 `data/cd80.sqlite3`；管理员写入仍需服务密钥与明确允许的账号。 |
| 根 `data/strategy-workshop-market/` | 策略工坊公共行情源快照、`derived/normalized.sqlite3` 与标的映射 | 只作当前工程诊断；保留源数据血缘、派生库与映射一起核对，不误当原账号回测历史。 |
| 根 `data/agent-runtime/` | 固定版本的便携 WASI Python、完整性清单及本机编译文件 | 搬机后按[Mac 指南](../../LOCAL-MAC.md#wasi-运行时)重新校验和编译；`python.cwasm` 不能跨机器直接沿用。 |
| 根 `data/integration-acceptance/` | 真实模型和浏览器验收制品、隔离验收账号与数据库 | `browser/` 为浏览器业务库，`explore-live/`、`app-workshop/` 为各应用真实链路，`platform-live/` 为平台聊天、金融数据与新闻真实依赖证据；不作为正式用户历史迁移，成功与失败记录都保留。 |
| 根 `data/capability-validation/`、`data/strategy-workshop-validation/` | 能力库和策略工坊的隔离测试数据 | 测试用临时 `DATA_DIR` 不指向正式账号库，不把测试密钥当业务凭据。 |
| `.run/`、`.cache/`、`.venv/`、`frontend/node_modules/` | 本机进程记录、临时文件和安装依赖 | 不从来源项目复制其本机状态，不作为公开源码；虚拟环境与编译缓存可在目标 Mac 重建。 |

新实例初始化时的个人数据表核对（本地资料，未随源码发布）显示账号和各应用私人历史为 0，能力库仍有公共种子；来源核对（本地资料，未随源码发布）记录来源未改动。这是检查时点的证据，不表示运行后仍永远为空。具体数据库文件可随运行产生或变化；不要凭文件名推断它们已通过验收。历史文档中的来源机器绝对路径只作数据血缘记录，最终版的执行应使用本目录的资源路径。策略工坊源快照和数据服务库都来自公共行情资源，但分别供诊断与数据 API 使用；二者不是私人账号数据。研究新闻、行情覆盖、数据权利及正式报告资格仍须按实际数据源和业务门槛核验。

## 凭据与隔离

平台的 MCP 远程连接凭据在 Windows 继续使用 DPAPI；当前 Mac 使用固定依赖 `cryptography==50.0.2` 的 Fernet 认证加密，仅在最终版 `DATA_DIR` 内生成本实例的随机密钥。数据库保存带版本标记的密文，不保存明文；连接准入、HTTPS/DNS/TLS 检查和运行权限未因 Mac 支持而放宽。密钥文件权限、归属、格式或密文异常时操作失败，不自动修复或覆盖旧凭据。备份该密钥时视同备份敏感令牌，恢复时须与数据库匹配并保留文件权限。

金融数据服务的 `CD80_ADMIN_API_KEY` 和可选 `CD80_READ_API_KEY` 只供后端转发；前端不承载这些值。联合启动先加载数据服务 `.env`，主站随后只补充未设置的同名字段，因此金融数据的密钥及 `CD80_DATA_ADMIN_USERS` 以数据服务 `.env` 为共同配置来源。`CD80_DATA_ADMIN_USERS` 为空时普通账号只有查询能力。三个应用仍由平台 Cookie 鉴权，再检查各自 owner；跨账号验收要用隔离目录与至少两个测试账号，不读取正式业务库。前端显示的“已保存”“已验证”“已启用”是不同状态，未验证应用不可启用或正式运行。金融能力的外部令牌、数据权益与行情新鲜度不能由本地健康检查推断。

## 停服备份与安全回退

修改部署、搬机或恢复前先运行[停止最终版.command](../../停止最终版.command)，确认 `scripts/manage_local.py status` 不再显示本工程进程。停服后把正式 `data/`、金融服务 `cd80-data-api/data/`、两份 `.env` 和当前代码版本一起保存。`data/` 内可能包含大量公共行情与 WASI 文件，预留足够空间；备份目录应在最终版内单独放置、限制访问，并从任何源码分享包中排除。以下是**创建新备份**的示例，不覆盖旧备份：

```sh
cd /Users/jaylen/Desktop/26CD80_v1/最终版
./停止最终版.command
backup_dir=".local-backups/$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 -p "$backup_dir"
ditto data "$backup_dir/site-data"
ditto cd80-data-api/data "$backup_dir/financial-data"
cp -p .env "$backup_dir/site.env"
cp -p cd80-data-api/.env "$backup_dir/financial.env"
```

`.local-backups/` 是私有手工备份区，不能提交、同步到公开空间或当成可发布的源码。命令执行前核对两份 `.env` 和剩余磁盘空间；备份完成后核对副本存在与可读，并保护备份目录。由于 MCP 密钥包含在 `site-data` 中，仅复制能力库数据库而遗漏它会导致凭据无法恢复。

回退代码时，先再备份**当前新数据**；在另一个副本中放置旧代码并验证启动、迁移与权限，再决定是否切换。不要直接删除 `data/`、用旧快照覆盖当前业务库，或用带 `--delete` 的同步命令“恢复”代码。若确需回退数据，逐项确认所选时间点及受影响的账号记录，再在停服状态下从匹配备份恢复；保留回退前的新数据副本。验收用 `data/integration-acceptance/` 和正式库应分别保存，不能用验收库覆盖正式库。

本工程的专项记录位于整合验收记录（本地资料，未随源码发布）及三个接入文档。平台真实依赖小验收（本地资料，未随源码发布）同时保留旧 GLM-5.3 超时与用户授权切换后 GLM-5.3-Flash 的真实成功。Flash 是主站和三个应用当前新调用的统一型号；旧研究模型标记和旧验证证据不重写，受配置变更影响的资产须重新验证。浏览器 CSV 新 App 已完成两例验证、启用与新文件运行，一次解释格式失败的恢复保留了前置计算和产物。详见最终验收报告（本地资料，未随源码发布）。旧平台 `docs/archive/`、Windows 与来源模块旧记录仅证明当时状态。
