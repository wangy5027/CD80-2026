# Apps 双栏目录与创建

2026-10-14，用户已确认本轮界面与公开范围；实现、自动化、隔离浏览器和正式服务资源验证通过。适用于“最终版”技能池的 Apps 分类。证据见本轮验收（本地资料，未随源码发布）。

## 产品设计

上栏为“我的 APP”，展示当前用户已有的三个基础工作区、现代 App、个人策略及已有旧版应用。Explore、策略工坊、应用工坊默认已拥有。栏标题右侧显示“创建 APP”。下栏为“平台 APP”，展示平台内置应用和用户主动公开发布的版本，不枚举其他账号的私人草稿或未分享应用。两栏各有搜索、来源和状态标识；暂无公开用户应用时如实显示。

点击任意卡片打开详情悬浮窗，左上角为“添加为我的 APP”或禁用的“已拥有”。内容包括用途、来源、版本、工作流程、输入输出及必要的运行条件；内置应用说明其实际工作区功能。已拥有应用可打开工作区或原管理/验证/运行界面。添加公共 App 保存独立快照至个人库并更新两栏状态，不自动运行或继承作者的验证、连接与启用状态。添加同一公开版本不会产生重复副本。原作者撤回后不再提供新添加，既有个人副本保留。

“创建 APP”当前只提供「从外部导入」和「用自然语言创建」两个入口；2026-10-15 用户新要求取代原手写/上传/组件组合三选项。外部支持标准 JSON、带静态接口声明的 Python、声明源码和资源引用的 ZIP；自然语言使用统一创作会话生成同一个 `cd80.app/2` 定义。生成或导入后先保存为未验证版本，后续从详情修改、配置、验证。已保存版本的高级编辑保留。最新格式和下载文件见[两种创建入口](APP两种创建入口.md)。

现代个人 App 增加显式发布入口：只有当前精确版本验证通过且运行配置一致时，才可预览完整公开内容并由作者确认发布。公开快照不包含私人文件授权、凭据、聊天或运行历史。旧版公开应用沿用已有发布和复制规则。

## 技术规范

前端新增 AppsLibraryPanel 和 AppCreatePanel，SkillPoolPanel 负责挂载及事件上送。卡片按 source/id/versionId 识别，不能按名称判断拥有关系。内置项 owned=true；现代公开项使用后端返回的可信来源/个人副本关系；旧版发布沿用后端复制来源。账号切换关闭窗口、清理状态并中止请求；迟到响应不得写入新账号页面。

新增 `/desktop/api/community/apps`：GET 公开列表；POST `/preview` 以 appId、versionId 获取可共享完整包与 snapshotDigest；POST 根路径要求 confirmSharing 与相同摘要；GET `/{releaseId}` 读取公开详情；POST `/{releaseId}/copy` 幂等复制；POST `/{releaseId}/withdraw` 作者撤回。仅 published 版本可被其他账号读取。沿用能力错误结构和登录鉴权。发布及复制记录存同一平台 SQLite 的附加表，复制应用与来源记录保持原子；原资产表不迁移或覆写历史。

上传新增 `POST /desktop/api/asset-apps/import/file-preview`，multipart file，支持 Python/ZIP/JSON；返回标准 package、definition、issues、warnings 和 bindingRequirements。限制输入和展开体积、文件数量、重复/歧义入口、路径穿越、链接及加密条目；不解压至宿主目录。正常保存仍走 `/asset-apps` 或 `/asset-apps/import` 的原服务和验证门禁。上传保存结果未知时保留原提交和幂等身份，防止静默覆盖或重复创建。

上传限制为一个文件、9 MiB 请求文件/展开内容、64 个 ZIP 条目；应用定义原有 8 MiB 限制仍生效。单文件 Python 源码限 128 KiB。ZIP 入口可在根或一层目录，支持 codeFile/resourceFiles 显式引用，导入时完整转换为内嵌 code/files；未声明附加文件、重复引用、路径冲突及缺失文件拒绝。macOS 元数据可忽略并明确提示。创建页面提供规范、接口、代码与 ZIP 示例下载，旧标准内嵌 JSON 包保持兼容。任意框架 ZIP 需要按合同适配，不能假称可直接运行。

公开列表沿用分页 `{items,nextCursor}`，条目包括 `releaseId/title/description/sourceVersionId/versionNumber/owned/isOwner/personalCopies`。详情和预览返回完整 `package/definition`；发布增加 `confirmSharing: true` 和 `snapshotDigest`。发布、复制、撤回均携带 `Idempotency-Key`；复制返回 `appId/versionId/alreadyOwned`。不同请求键重复添加同一公开版本仍返回已有副本。旧版公开应用、平台预置流程沿用原复制接口与依赖要求。

数据库只在既有 `agent-platform.sqlite3` 增加 `asset_community_releases`、`asset_community_copies` 及索引，不批量公开或搬迁原私人记录；复制与可信来源在同一事务内提交。正式启动前已将该库一致备份到工程内私有 `.local-backups/`。旧代码可忽略附加表；回退不得覆盖当前用户数据，按[运行与数据说明](运行与数据说明.md)保留新记录并在副本中验证。

## 验收要求

检查两栏数据、三基础默认拥有、上下栏点击详情、左上角添加/已拥有切换、跨账号公开/私人隔离、重复点击不重复保存、撤回边界；外部导入和自然语言创建均须能找到未验证的个人资产并保留完整实现。构建后在隔离账号浏览器验证、核对小屏滚动和模态键盘；正式重启并核对健康与实际构建资源。模型质量和任意外部 APP 框架兼容性不属于本轮验收结论。
