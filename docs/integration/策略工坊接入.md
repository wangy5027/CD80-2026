## 服务与数据边界

策略接口前缀为 `/desktop/api/strategy-workshop`。路由从平台 Cookie 验证账号，后端将 owner 传入仓库查询；客户端提交的 owner 不成为授权依据。请求使用幂等键，会话、运行、个人策略、追加式对话与冻结包记录于最终版 `DATA_DIR/strategy-workshop.sqlite3`。进程关闭会中断活动运行，重启把未完成运行标记为 `interrupted`，不会自动重放。

最终版配置需要 `STRATEGY_WORKSHOP_SOURCE_DB`、`STRATEGY_WORKSHOP_MARKET_DB`、`STRATEGY_WORKSHOP_MAPPING_DIR`，以及运行/匹配超时、并发数和可选审核标的配置。公共源库、规范化样本与映射在 `data/strategy-workshop-market/`。当前可用行情仍为工程诊断用途；正式报告门槛由服务器强制为关闭，不能通过前端确认或映射布尔值解除。自定义规则由现有 `SandboxExecutor` 执行，必须有通过完整性校验的 `AGENT_RUNTIME_DIR`；缺失时失败关闭，不回退到宿主 Python 执行模型代码。

个人策略是独立的策略资产，保存在策略库，统一应用目录只聚合其索引和打开入口。它的配置、历史和执行仍由策略工坊接口处理，不转换成普通固定流程 App。`list_personal_apps(owner)` 返回目录项目；打开时带 `personalAppId` 至前端 `StrategyWorkshop`，后端读取冻结快照校验后创建新的配置会话。原运行和结果始终只读。

前端组件接收 `ownerKey` 和可选 `personalAppId`，发出 `saved` 与 `new-session` 事件。组件按账号更换、销毁和迟到响应清理轮询；草稿及表达风格按账号隔离。应用工坊推荐策略时采用原 `strategy-handoff` 键协议，仅传原问题作为新草稿，并保留此前草稿可恢复。页面、图表和历史对话已调整为平台浅色体系。
