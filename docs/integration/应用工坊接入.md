## 产品与候选边界

保留原三页流程：分析需求并推荐、使用推荐应用或重新检索组合、预览及保存。推荐候选为策略工坊、平台旧固定流程预置及本人旧个人流程，以及应用工坊自己保存后已经验证启用的新版 App。策略工坊只作跳转，不作为组合来源。组合候选为当前账号可访问的旧固定流程定义与应用工坊自己保存的完整新版 App 来源索引；不扫描平台所有新版 App、Explore、共创或能力库。工坊新资产未验证时可以按原创作规则成为组合来源，仍不能直接运行。若该资产在平台被修改为新版本，而索引无法证明版本实现一致，先暂停其创作来源资格；不能用旧侧存实现冒充最新版本。

生成仍使用原 AgentSpec 作为中间表示，原工具源码、技能正文与固定处理流程由平台 `asset_legacy.migrate_pipeline` 转换为完整 `cd80.app/2` 节点和组件快照。工坊生成调用显式把所选来源的完整 AgentSpec 及组合规划传给模型；平台通用 `Planner.generate` 只保留普通运行元信息，不能直接用于多来源生成。返回结果仍经平台能力引用解析、精确快照锁定和 AgentSpec 合同校验。展示预览前另检查工具 `inputFrom` 指向对象与目标工具 schema 的确定性不匹配，避免已知接线错误被当作完整草稿保存。实际执行正确性仍需后续独立验证。旧流程的外层输出包裹在新版应用中改为明确的节点输出（`result`、`step_1` 等）；工具与末尾解释步骤的实际实现保留，旧运行产生的文件 ID 不继承。新资产只写入平台 AssetApps。保存不触发工具、模型执行或验证。详情、验证、启用、运行均走平台原服务。来源标记与侧索引只用于工坊保持原候选资格，不授予运行权、文件、连接或历史验证。

## 接口与数据

保留 `/desktop/api/app-workshop/sessions`、`/current`、`/<id>`、`/refine`、`/create`、`/save`、`/handoff`。`save` 响应改为 `{session,appId,versionId,detail}`；会话公开字段为 `savedAppId`、`savedVersionId`，不再返回旧 `agentRef`。推荐新版 App 的 handoff 目标为 `{kind:'asset-app',appId,versionId}`，旧流程与策略工坊保留原目标类型。服务端始终从登录 Cookie 取 owner，忽略前端任何 owner 声明。

`app_workshop_sessions` 存完整私有生成稿及公开预览；`app_workshop_requests` 存各操作幂等结果；`app_workshop_sources` 将工坊创建资产的 owner、appId、versionId、当前定义摘要及完整原 AgentSpec 固定到源索引。所有表在最终版平台业务库中独立建表，不复制来源数据库。组合时服务端重读旧 AgentSpec 或资产当前版本，并核对摘要、归属和资格；模型返回的来源引用只是选择建议。

保存使用由会话 ID 与草稿摘要确定的稳定平台请求键。即使平台资产已保存而工坊会话提交失败，重试可取回同一个平台结果，再原子提交工坊会话、来源索引和幂等结果；不自动重做生成或运行。平台资产可能在工坊收据提交前短暂可见，此时重复点击保存即可关联同一资产。前端按账号保存输入草稿、取消迟到请求；正式会话在后端保存，刷新只读取。
