# 应用先保存与执行追踪

日期：2026-10-15。状态：已实现并验收。测试口径、真实示例、浏览器及正式重启证据见验收记录（本地资料，未随源码发布）。

用户确认：官方和已公开发布的 Skills/Tools 免重复验证；个人上传、手写、模型生成或修改的版本仍验证。APP（包括用户在策略工坊新增的个人策略）统一先保存为未验证，之后修改、验证和启用；来源能力的可信状态不代表组合 APP 已验证。

## 应用工坊

`POST /app-workshop/sessions/{id}/create` 生成完整定义后先持久化生成结果，再用稳定请求键调用统一 `AssetApps.save`，返回 `status=saved`、`savedAppId`、`savedVersionId`。保存不执行工具、不读取输入文件、不验证或启用。跨库保存中断时复用已持久化定义和请求键，重试不重生成、不重复创建。旧 `/save` 保留为幂等兼容入口。生成完成后修改转到已保存 APP 的版本编辑。

## 策略工坊

新增 `/strategy-workshop/sessions/{id}/personal-app` 纯保存规则快照。生成自定义规则时自动保存；选择已有模板时也保存个人版本。新版本显示 `verification.status=unverified`。定义与代码不可随验证结果变更，工程验证状态独立记录。保存前不运行代码验证或回测。

`GET /personal-apps/{id}` 支持没有回测的版本，返回 `run=null` 和规则快照。`POST /personal-apps/{id}/sessions` 从冻结规则打开后续验证/回测；编辑使用新会话和新保存版本，不覆盖已保存定义。验证通过指规则代码检查及对应诊断回测成功，不代表盈利或正式收益报告的数据门槛通过。旧回测记录与旧个人策略继续可读。

## 统一 APP 合同和记录

规范以 `cd80.app/2` 为现代 APP 合同，固定输入、节点、节点绑定、交付结构与输出。工具和技能保存精确内容快照及依赖，代码保存源码和资源。修改生成新版本并重置该版本验证状态；启用仍需明确操作。

创作会话、实际模型请求、保存版本、验证运行及正式运行按稳定 ID 关联，私有记录按账号授权读取。模型请求记录包含实际发送的 system/user 消息、阶段、重试关系和结果；凭据清理与大小截断必须明确标记。子代理运行记录沿用已有 `model_trace`，不得把仅模型调用元信息当作完整提示词证据。

## 验收

覆盖各可见创建入口、保存后重试、旧接口兼容、跨账号隔离、未验证无法启用、编辑版本失效、公开能力免验证与个人修改重新验证。提供一个基于官方已有 Skill/Tool 的本地 APP 包、自然语言调用文本和真实运行证据，明确是否已经导入正式账号。最终重启正式服务并核对健康及网页资源。
