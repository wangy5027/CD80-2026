# 技能池 APP 的两种创建入口

日期：2026-10-15。状态：已实现并验收；后端1242项、前端337项、真实模型与隔离浏览器通过，正式服务已重启。依据用户本轮要求，技能池“创建 APP”及“加入技能 → APP”只展示「从外部导入」和「用自然语言创建」两种创建方式。原 APP 版本的高级编辑仍在已保存详情中，不作为第三种创建入口。

## 共同合同

两条路径最终都形成既有 `cd80.app/2` 定义，复用现有版本、组件快照、输入绑定、输出、来源、提示词记录及幂等保存机制，不建立第二种 APP 运行时。新 APP 一律先保存至当前账号应用池，状态为未验证且未启用。这里的格式解析、路径与体积检查不执行用户代码、Tool、Skill 或双例验证；缺运行环境、连接或业务检查项可以在保存后解决。无法安全解析、丢失声明文件或格式不明的输入明确报错，不虚构完整实现。

## 从外部导入

提供标准 JSON 定义、平台导出包、Python 单文件和 ZIP 源码包四种运输形式，均属于同一个外部导入入口。

- JSON 沿用 `cd80.app/2` 和 `cd80.app-package/2`，完整代码及资源可直接内嵌。
- ZIP 沿用根目录或一层目录的 `app.json` / `application.json` 入口，并允许代码节点用 `codeFile`、`resourceFiles` 显式引用包内相对文件。加载时读取原字节并转为既有 `code` / `files`，保存后不依赖 ZIP 原路径；重复、逃逸、符号链接、未声明文件和引用歧义拒绝。详细字段以机器接口文件为准。
- 单个 `.py` 必须含静态字面量 `APP_INTERFACE`（名称、用途、输入 Schema、输出 Schema、规则）和 `run(payload)`。只用 AST 读取接口声明，不导入或执行 Python；声明转换为标准 APP 的一个 code 节点，输入字段显式绑定，输出固定映射。原源码完整保留。声明缺失或使用动态表达式时报出如何适配，不自动猜接口。
- 下载提供：完整规范及机器可读 JSON Schema、HTTP 接口描述、标准定义示例、Python 示例、源码 ZIP 示例。示例共享后端合同与模板，测试核对转换后满足 `cd80.app/2`，避免前后端各维护一份不一致的示例。
- 用户选文件后展示名称、来源文件和格式检查结果；允许纯保存可表示但尚有运行缺口的版本。运行连接配置、修改和双例验证移到保存后详情。格式成功不是验证通过，按钮明确“导入并保存”。

包来源的本人权限与文件路径安全仍检查；私有导入不以满足公开发布规则为前提，公开发布继续单独检查。不得因为无法公开分享而禁止私人保存合法定义。

## 用自然语言创建

在技能池直接进入统一 APP 创作会话，固定类型 APP。用户描述用途、输入和输出，后端用当前模型配置生成同一标准定义；必要歧义使用现有会话问答与恢复，不另建聊天或跳去无关页面。完整定义形成后立即按既有先保存逻辑入池，显示“已保存 · 未验证”并提供精确版本详情。

生成遵守代码入口、步骤绑定、Skill/Tool 精确快照和依赖合同；不能凭模型文字将虚构组件当作已接入工具。记录实际模型请求及保存版本关联。创建不执行生成的应用，不准备双例验证；后续改版从已保存详情发起。创作失败、刷新、账号切换和未知响应沿用持久会话及幂等恢复，不重复创建。

实际行为补充：`mode=prepare` 下的“生成后只保存为未验证 APP，不运行、不验证、不启用”仍要求模型生成具体定义并纯保存；只有明确选择 `mode=draft_only` 或明确要求“只记录想法、暂不生成 APP”才不生成。只有名称、没有具体 code 或精确组件步骤的空定义不得制造占位 APP；模型提出必要问题时，会话等待回答并带上原问题继续。模型可读取本账号静态有效的未启用 Skill/Tool 精确版本作为设计参考，生成时按版本冻结快照，运行准入不会因此放宽。

## 本轮补充：应用入口归并与创建后回池

侧边栏以“技能池 → Apps”的“我的 APP / 平台 APP”为统一目录，已移除重复的“应用”导航项和独立列表页。这只调整入口，不删除旧应用、个人策略、历史运行或其存储。旧 `#applications`、本地保存的旧视图和站内旧跳转归到 `#extensions` 的 Apps；旧版研究应用与固定流程留在池内折叠管理区，不把旧地址变成空白页，也不复制资产数据。

外部导入成功后立即返回“技能池 → Apps → 我的 APP”；自然语言创作仅在**本次账号、本次会话**被当前入口提交并成功保存时自动回池，重试恢复同一次已接收提交也可回池，查看历史已完成会话不会突然跳页。两条路径都刷新目录，并按服务端返回的 `appId/assetId` 聚焦刚保存的卡片；保存时记录 `versionId` 供后续准确检查，**用户之后手动打开卡片时以目录所示当前版本为准**，不把高亮误称为锁定历史精确版本。创建前缓存与同名卡片都不能代替服务端保存结果。

池内卡片弹层仍可进入该 APP 的管理详情，查看完整定义、运行缺口和历史版本，并使用原有双例验证、启用、运行流程；只保存的版本显示“未验证、未启用”，此时可进入测试，但启用和普通运行仍受验证门槛限制。旧版折叠区保留原运行记录、旧版升级入口与已有个人资产归属。创建失败、模型待回答或结果未知时保留当前会话和原提交身份，不制造成功跳转；账号切换清理待定位 ID、查询条件及上一账号卡片。

本轮已验收：隔离 8895 页面中，ZIP 导入及真实 GLM 自然语言创建各自成功回到“我的 APP”，卡片保持未验证；不用手动点开创建结果也能看到新卡片。卡片弹层可进入管理详情，测试按钮可用，未通过验证时启用和运行受限；桌面、窄屏侧栏均无重复“应用”，旧 `#applications` 在登录后重载变为 `#extensions`。修复创作会话卡局部变量遮蔽后，定向 7 文件 71/71 项通过，前端构建通过（仅有原有的分包大小警告），最终构建的浏览器错误日志为 0。正式服务最终重启的 supervisor PID 为 92485，`8894/desktop/health` 和 `8897/health` 健康；对外提供的 `index-_f8rf8WM.js`、`index-DpYTfWYo.css` 与构建产物逐字节一致。隔离验收实例已关闭，创建过程的 `plan=validate=appRun=0`；演示 APP 仅存在于隔离 `data/integration-acceptance/app-two-entry-r22ktjk9`，未添加到用户正式应用池。证据见定向测试（本地资料，未随源码发布）、验收记录（本地资料，未随源码发布）和桌面截图（本地资料，未随源码发布）。

## 实施与隔离验收

两种入口均已接到既有 `cd80.app/2` 保存链。根任务的独立浏览器验收中，真实 GLM-5.3-Flash 根据一条具体需求生成含 1 个 code 节点的 APP；创作会话为 `mode=prepare`、`phase=completed`，保存版本为未验证、未启用，期间 APP 运行次数为 0。浏览器下载的官方 Python 示例和源码 ZIP 示例分别成功导入，保存结果均为未验证 APP。该证据确认上述三条实际路径，不扩展为所有自然语言需求、所有导入文件或后端完整回归均已通过。完整回归结果与正式本机加载见最终验收（本地资料，未随源码发布）。

## 验收条件

1. 技能池两个入口进入相同两选项页面，手写定义和手动组件组合不作为第三选项出现。
2. 所有下载示例与机器接口文件实际可读取；JSON、Python、源码 ZIP 和旧导出包在隔离账号保存成功，均未验证/未启用，无模型、Tool、Skill 或代码执行。
3. 恶意路径、动态接口声明、缺失引用及超限包可读地报错；运行缺口不阻止合法内容保存，修改保留新版本语义。
4. 自然语言创作使用真实模型完成至少一个合成需求，结果落入统一应用池；保存时无验证运行，刷新能恢复精确版本。
5. 自动化及浏览器检查后构建并重启正式网站与后端，核对实际健康和新资源，正式用户数据不作为写入验收对象。


## 2026-10-15 主页面创建模式

主页面增加技能池自然语言创建的快捷入口：选中 Composer 的“创建模式”后，完整需求直接使用同一 APP 创作与保存逻辑；必要补充回答继续同一会话，成功后定位我的 APP。技能池本身仍保留外部导入、自然语言创建两种方式，没有增加第三种 APP 格式。所有创建仍先保存完整未验证版本，后续测试与启用在详情完成。规范与当前证据见[首页创建模式](../workbench/首页创建模式.md)。
