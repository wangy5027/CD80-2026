# 使用外部LLM构建并接入应用

更新：2026-10-14。本平台托管的是经过校验的应用定义与隔离Python计算，不是任意网站、Docker容器或公网服务。

本页保留旧`infinity-application`/recipe/pipeline资料包及兼容入口。新App/Tool/Skill平台创建、外部原件完整导入/导出与统一准备使用，优先阅读[统一创作开发与外部接入指南](../asset-authoring/开发与外部接入指南.md)。新原件保存和导出不以运行兼容、验证或启用为门槛；下文旧格式静态校验及逐步运行说明不能作为拒收未知外部原件的规则。

## 五分钟样例

1. 在应用页面下载“外部开发指南与样例”，解压。
2. 点击“导入应用包”，选择 `csv-summary.application.json`，核对预览后点击“导入并保存（不运行）”。此时只校验并保存，不计算、不联网。
3. 上传 `sample-a.csv`，选择应用并填写 `fileId`（从文件选择器选择）、`groupBy=category`、`valueColumn=amount`、`aggregation=sum`。
4. 核对输入与权限后运行。WASI实际生成summary.csv，期望A=15、B=7、总计22。解释文本来自模型，计算数值来自工具。
5. 换成 `sample-b.csv` 重新运行，期望A=1、C=10、总计11。不能仅用第一次结果判断复用成功。
6. 导出应用包，在另一账号导入。需要重新上传/授权文件；原账号输入与产物不会随包传递。
7. 成功运行后可预览发布至本平台共创目录，其他登录账号复制后独立改编。发布不开放公网地址。

`research-method.application.json` 是研究应用示例：参数化目标交由主/子agent重新执行。它不包含金融数据，也不保证用户库已有相应数据与能力。运行前按目标在扩展页准备、验证和启用工具；无数据时应明确报告。

## 用外部LLM创建自己的应用并部署

1. 下载并解压资料包。把本指南、`csv-summary.application.json`、`docs/agent-platform/应用包与组件复用.md`以及两个合成CSV交给外部LLM。不要上传平台Cookie、模型密钥或真实私人数据。
2. 明确输入、金融逻辑、输出及验收数值。例如：基于样例格式，创建“分类金额检查”，从CSV按category分组，对amount使用Decimal求和，返回每组金额和总额，生成summary.csv；末尾由模型解释结果和数据限制。测试一应为A=15、B=7、总计22，测试二应为A=1、C=10、总计11。
3. 要求LLM直接输出一个完整的 `infinity-application` JSON包，沿用示例所有必要字段、字符串版本号、文件权限及末尾model步骤，不输出只含自然语言的伪代码。将JSON保存为UTF-8的 `my-application.json`，移除包外说明和Markdown代码围栏；不把凭据或本机文件路径填进JSON。
4. 在平台选择“导入应用包”，检查名称、输入、步骤、源码及权限，再“导入并保存（不运行）”。若平台返回字段、Schema、依赖或权限错误，把错误和对应JSON交回LLM修正，再导入；静态保存不代表算法已经验证。
5. 上传sample-a.csv，填写参数并核对执行预览，授权运行。检查实际工具输出、summary.csv和解释是否一致，再换sample-b.csv复测。遇到失败查看具体步骤，不把失败输出当成有效结果，也不自动重复外部操作。
6. 需要改变逻辑时，将应用导出的JSON和新需求交给LLM，例如改为“每组平均金额”，并先写明新验收值。保存为新包重新导入或在平台改编；以新运行验证新逻辑，不引用旧输出作为通过证据。
7. 通过后可导出给其他账号，或预览发布到本实例共创目录。接收者复制后自行准备依赖、上传并授权自己的文件，再独立运行。至此应用已由本平台保存和托管执行；不需要把任意网站或容器部署到服务器。

上述步骤使用用户自选的外部LLM编辑文件；平台不要求其特定品牌，也不替用户把文件或密钥发送到外部服务。兼容格式与运行限制如下。

## 给外部LLM的开发要求

资料包同时包含 `capabilities/decimal-total.zip`（Tool）、`capabilities/summary-skill.zip`（Skill）、两者展开源码，以及 `docs/` 下的能力包规范、接口与Schema。无需克隆项目即可把这些文件交给外部LLM理解兼容格式。

Tool从扩展页导入后，先运行包内示例：`0.10 + 0.20`应返回`0.30`；验证通过再主动启用，换成`1.25 + 2.75`应返回`4.00`。Skill导入后执行包内摘要样例，按事实、缺失信息与结论的标准审阅，通过后启用。运行与发布均不继承样例作者的验证状态。

修改展开的Tool源码或Skill内容后，在资料包根目录执行 `python pack_capability.py capabilities/decimal-total my-tool.zip`（Skill相应替换目录）。脚本重新计算资源摘要并生成可导入包，不执行其中的代码；输出放在源码目录外，且不能覆盖已存在文件。也应更新source.identity、名称、说明、Schema与examples，保持作者预期与实现一致。打包成功只表示文件封装完成，效果仍在平台独立验证。

以随包样例为完整基础，只修改业务目标、输入Schema、标准库Python代码、Skill方法说明与顺序pipeline。保持协议字段及安全边界。不要将API密钥、Cookie、私人文件路径、文件ID、旧输出、真实私密样本或模型凭据写进包。

外层格式：`format="infinity-application"`、`formatVersion="1"`、`kind="pipeline"|"recipe"`、`definition`、`dependencies`、`provenance`。版本字段使用字符串 `"1"`，不能写成数字 `1`。未知字段会被拒绝，参考实际样例而不是凭空扩展格式。

### 固定流程应用

definition采用 `schemaVersion="1"`，包含 `version="1"`、name、description、goal、prompt、inputSchema、outputSchema、tools、skills、pipeline、permissions。应用、Tool、Skill的version均为字符串；应用保存时由平台分配本地ID和版本，包导出不携带个人运行授权。

- 输入为JSON对象。Schema只支持基础type/properties/required/items/enum/const及数量范围，不支持远端引用、表达式或类型联合。
- 1—8个Tool，0—8个Skill，2—8个顺序步骤。pipeline必须实际包含至少一个tool执行步骤，且末尾恰好一个model解释步骤，因此最小可用流程是“tool → model”两步；不支持并行、递归或循环。
- `inputFrom` 是 `run.input`、`steps.<已完成步骤id>.output` 或它们的数组。步骤输出是结构化对象，不应让模型手动复制大量原始数据。
- Python入口为 `run(payload)`。仅标准库，无网络、pip、子进程或宿主文件访问。输入文件只读；产物写入 `/output/安全英文文件名`。
- 文件输入使用 `fileId` 等公开参数，在permissions.files声明参数名；平台授权后注入 `filePath/filePaths/outputDir`。这些注入字段不能由调用者伪造。
- 失败抛出异常，不能把 `{error:...}` 作为成功业务结果。金额用Decimal与字符串输出，避免浮点舍入。
- 应用outputSchema描述平台结果：explanation、artifactIds、stepOutputs等；业务字段在Tool输出中。
- 使用个人能力时先调用 `/desktop/api/agent-components` 查看已验证/启用精确版本，通过创建界面选择组件。可移植包引用sourceIdentity/contentDigest/kind；导入时在接收者个人库重新绑定，不按名称猜测。
- 配置或验证失效、被禁用/删除的能力不能绕过准入继续执行。缺依赖时先引入精确版本；研究应用可先保存定义，实际运行前仍需验证启用；固定流程按其准入要求完成准备，不自动安装。

### 研究应用

definition包含name、description、goalTemplate、constraints。`{{参数名}}` 是纯文本占位符，参数必须全部提供，没有模板表达式求值。每次运行创建新子任务，按当前数据和能力重新执行及验收。修改通过“改编”产生独立应用，原定义不覆盖。

dependencies声明精确来源和内容摘要。当前不会将私人能力源码自动嵌进研究应用包；接收者需先从共创目录或能力包引入相同版本。一次成功研究只证明那次输入的结果，不自动证明所有参数组合。

## 本机API调用顺序

主站默认 `http://127.0.0.1:8894`。使用登录Cookie；所有请求须由合法本机Host/Origin发起。应用包导入：

```http
POST /desktop/api/agents/import
Content-Type: application/json

{"package": {"format":"infinity-application","formatVersion":"1","kind":"pipeline","definition":"此处替换为样例完整对象"}, "idempotencyKey":"每次新操作的唯一标识"}
```

上例只展示调用包装，不能直接执行；包完整字段以下载样例为准。成功响应含agentRef、spec和validationScope，只说明静态保存。调用使用 `POST /desktop/api/agent-runs`，body为mode=invoke、agentRef、input、fileIds、idempotencyKey。观察GET运行详情，遇到awaiting_confirmation时批准绑定的审批，失败/取消时停止后续动作，不自动重试外部效果。

研究应用导入：`POST /desktop/api/evolution/recipes/import {package}`，写接口带Idempotency-Key头。运行：`POST /desktop/api/evolution/recipes/{id}/run {input,fileIds}`。202代表接受请求；观察 `/desktop/api/sub-agent-runs/{id}`，不是立即完成。

共享：先POST `/desktop/api/evolution/publications/preview`，审阅package和summary，再将snapshotDigest及confirmSharing=true提交 `/publications`。发布要求成功运行证据；更改预览内容后必须重新预览。社区复制要求接收者自行准备依赖和输入。

工具/Skill接入继续使用 `cd80.capability/1`，接口和格式见项目 `docs/capability-library/接口规范.md`、`能力包规范.md`。金融数据接口见 `cd80-data-api/docs/CONTRACT.md`。主站不是公开第三方服务端API；公网部署、OAuth和商业托管需另行设计。

## 凭据与检查

模型密钥保留在后端环境，MCP个人凭据通过独立连接接口保护。导出与发布检查常见凭据、私人路径和运行文件引用；自动扫描无法证明任意文本绝无秘密，因此必须审阅实际共享源码与说明。导入包不能通过提示文字扩大权限。

本地运行WASI缺失时按现有启动指南准备运行时；不会回退宿主Python。修改前端后构建dist，后端改动需确认无活动任务再重启。此指南与样例使用模拟数据，不构成金融建议。
