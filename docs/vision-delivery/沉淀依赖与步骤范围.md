# 成果沉淀的依赖与步骤范围

日期：2026-10-14。状态：设计与实现完成，本轮验证见验收记录（本地资料，未随源码发布）。适用 `POST /desktop/api/evolution/captures/preview`，仍只读取本人成功任务，预览不保存、不验证、不启用。

## Skill 的依赖证据

加载过的 Tool 不能直接等同于实际调用过。沉淀依赖从本任务成功 `cap_<versionId>` 调用及成功的 Skill 资源/脚本操作确定，失败步骤和仅浏览目录不算执行依据。可解析版本只来自任务记录的精确 `loadedRefs`（旧记录回退显式选择）及其中 Skill 的精确 `dependencyLocks`，不能遍历个人库按名称或最新版本猜测。

Skill 间接提供并实际使用的 Tool 也必须写入新清单。实际使用某个来源 Skill 时，同时保留该来源方法声明的全部必需 Tool；按 `sourceIdentity/contentDigest` 去重，来源冲突、缺锁、锁与声明不符明确 `SOURCE_NEEDS_EDIT`。当前能力包 Schema 的 `dependencies[].required` 为 `const true`，依赖只支持 Tool；不把 optional 或嵌套 Skill 依赖默认为支持。异常旧记录出现这些声明时拒绝自动沉淀并要求外部整理。

同内容多个 Tool 副本仅在 `configurationId` 也相同时合并。若本任务使用了相同来源/内容但不同配置的副本，单个 Skill 依赖无法保留两份绑定语义，返回 `SOURCE_NEEDS_EDIT` 并要求整理；不扩大 Schema，也不导出个人配置或凭据。

新 Skill 是成功步骤目的、目标及约束的可编辑方法草稿，不能声称自动复制了来源 Skill 全部正文、参考资源和脚本。实际执行了来源 Skill 脚本的任务不自动转换为文字方法，返回 `SOURCE_NEEDS_EDIT`，避免脚本方法静默丢失。用户可将原 Skill 作为独立能力复用，或下载资料在外部整理。

## Tool 的单步骤范围

只捕获一个成功代码步骤，默认最后一个；失败代码不能被选择。返回 `selectedStepId` 和 `steps`，每项为 `{stepId,label,purpose,inputCount,inputs}`，输入项为 `{parameter,label,sourceType,sourceLabel}`。`sourceType` 区分 tool、code、upload、previous_run、unknown。步骤和原资源名称只供当前账号审阅，不写入能力包。

多个成功步骤时，界面可用相同接口携带 `stepId` 重新预览；有未保存编辑时先明确处理。提示必须说明未自动组合其他代码、前置取数或中间处理。原工件 ID 改为 `input_1` 等参数；来自工具或前一步的输入需在新运行中重新准备为同格式文件，不自动携带旧文件、结果、授权或依赖执行。

实际执行源码内嵌的绘图 helper 原文保留，不额外读取当前版本 `png_plot.py` 作为历史依赖。旧记录若仅包含 `import cd80_plot` 而未保存当时的 helper，明确返回 `SOURCE_NEEDS_EDIT`，不能用最新版补齐后声称保持原算法环境。

## Python 源码的私密路径检查

真实 subagent 源码内嵌平台绘图模块，Python 字节转义如 `\\x89PNG\\r\\n` 曾被文本 UNC 规则误认为共享目录。秘密扫描仍检查完整原文；仅私密路径扫描对 Python 进行语法分析，按已解码的字符串和 bytes 内容检查，并保留注释及其他源码中的路径检查。嵌入源码递归检查有深度及总大小边界；语法错误回退保守原文检查，不能利用解析失败绕过。真实 Windows 盘符路径、UNC、私人下载地址以及注释或 bytes 中的这些内容仍拒绝。

## 验收要求

- 原任务仅选择有 Tool 依赖的 Skill，通过其工具成功执行后，新 Skill 的依赖与源码快照精确一致；导出、另一账号导入、验证、发布和复制后仍保留。
- 仅加载或失败调用的独立 Tool 不成为新依赖；多个来源、同源冲突、可选/嵌套声明和缺锁明确处理。
- 多工具输出、多输入文件、失败代码和多个成功代码的选择均可复现；换全新输入后计算与预期一致，原工件 ID 不进入包。
- 实际含平台绘图 bootstrap 的捕获 Tool 可导出、导入、验证、发布、复制，再用新文件验证；真正私密路径、密钥和文件引用保持拒绝。
