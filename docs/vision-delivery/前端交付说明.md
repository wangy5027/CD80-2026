# 愿景闭环前端交付说明

更新：2026-10-14（Asia/Shanghai）。本页记录当前工作区实现与前端验证；跨模块产品和接口约束以本目录设计、技术规范及对应后端模块为准。

## 可见用户流程

1. 首页保留 Explore / Build / Evolve。Evolve 进入“共创”，浏览平台内用户分享的研究应用、固定流程应用、Skill 和 Tool。
2. 主对话的成功任务卡显示“保存为应用”“沉淀为 Skill”；存在成功代码工件时再显示“沉淀为 Tool”。这些入口读取实际任务的沉淀预览，不把成功记录直接当作新资产验证证据。
3. 研究应用编辑器展示名称、用途、参数化任务模板、约束、精确组件版本。双花括号变量支持中文。用户审阅保存后可用新的参数和本次文件授权执行。
4. Skill / Tool 沉淀显示可读的名称、用途、文件内容以及高级完整定义。审阅保存后沿用能力库检查、验证、启用流程。
5. 我的应用页分为研究应用与流程应用。流程应用保留原先输入表单及运行记录，新增独立复制、对话改编、个人组件组合、应用包导出与发布。
6. 导入应用包先读取并展示定义与依赖，由用户点击“导入并保存（不运行）”。研究应用与固定流程存在多个精确组件副本时均可明确绑定；候选保留精确旧版本。缺失组件仍由后端拒绝，不能依据名称近似匹配。
7. 个人应用或已验证组件点击发布后，先检查发布清单，再明确确认对平台内其他账号分享。组件发布按主包和依赖分别展示文件，用户可逐个展开完整源码及示例；只显示本次快照返回的内容，不重新读取最新版本。源文件未完整返回时确认入口不可用，允许重新检查。应用的成功运行前提与能力验证前提由后端再次校验。
8. 共创支持类型过滤、用途搜索、我的发布、详情、复制及撤回。目录跟随服务端游标读取完整结果，搜索与分类不会遗漏第一百项之后的成果。新的筛选请求或页面卸载会停止旧请求继续翻页。应用详情读取可移植包；组件详情读取发布快照。复制后的组件仍需接收方验证、启用。
9. 应用页提供“外部开发指南与样例”下载入口，连接后端开发资料包。

## 前端实现边界

- `App.vue` 负责页面和来源上下文，账号变化时清理沉淀上下文。
- `RecipeLibraryPanel.vue` 负责研究应用及应用包导入，`AgentPlatformPanel.vue` 负责固定流程。
- `CommunityPanel.vue` 聚合应用与组件发布目录；`ReleasePublisher.vue` 统一发布预览、内容确认及提交。
- `CapabilityLibraryPanel.vue` 保留既有资产、验证、导入导出机制，并增加成功任务沉淀预览、可读草稿编辑及发布入口。
- `useAgentPlatform.js` 新增精确组件目录读取、独立复制与改编，继续使用现有账号隔离、只读轮询和幂等动作协调。
- 新保存的研究应用只提交目标、约束、精确能力引用和来源任务标识。旧文件授权、运行输出、凭据及配置不随表单提交。
- 发布、研究应用写入、流程应用导入与社区复制在结果未知的请求失败后保留幂等键；明确的请求错误允许用户处理条件后重新提交。流程应用同时在请求体传递相同幂等键，兼容既有接口。
- 写请求结束后再次检查页面是否已卸载，阻止旧页面或旧账号的迟到结果触发任务跳转、发布通知等后续动作。

## 前端验证

### 2026-10-14 失败恢复与沉淀范围设计修订

本轮审计用隔离浏览器复现三个恢复问题，修复前证据见本机 `data/failure-recovery-audit/report.json`：组件复制成功但响应丢失后重试生成第二份资产；应用保存期间仍能编辑字段但迟到响应关闭草稿；已删除组件不在可选目录中，却仍隐含保留在应用引用内。

- 社区复制保留首次提交的完整请求体与幂等键。结果未知时，再次点击先恢复该次复制，不重新检查副本数或询问是否创建额外副本；只有明确成功或明确请求错误后才重新准备下一次操作。
- 保存研究应用期间禁用名称、用途、模板、约束及组件选择；失败后恢复编辑并保留全部输入。运行输入、导入绑定和能力草稿高级定义也在对应请求期间禁用，防止提交后的新编辑被响应覆盖。
- 已选组件在可选目录之外独立展示精确版本。目录缺失或不可用的引用仍可见、可取消；当前可用版本与锁定版本不同时，用户可明确替换。不会自动换版本或静默丢失引用。
- 应用包导入和社区应用复制按依赖 `bindingId` 分槽绑定，两个相同来源的组件可以分别选择个人副本。兼容旧研究包的 `sourceIdentity` 与旧流程包的 `kind:componentId`；服务端仍负责拒绝歧义和重复资产绑定。
- Tool 沉淀展示本次选中的成功代码步骤及各输入来源，可切换同一次运行的其他成功代码步骤。切换前如有未保存编辑则明确确认放弃；重新预览期间禁用编辑。清楚说明每次仅沉淀一个步骤、输入需重新准备，不把多步分析包装成自动完整流水线。Skill 继续展示后端返回的精确依赖和范围说明。

验收条件：定向复现复制响应丢失、保存失败重试和失效引用修复；检查同源多槽位选择互不串联、步骤切换保护本地编辑；保留既有 24 场景语义。设计先于实现更新；截至 02:13 已实现并完成以下验证。

失败恢复阶段 `npm test` 70 项通过，并于 2026-10-14 02:11:52（Asia/Shanghai）完成 Vite 构建，产物为 `index-Du7s2YYJ.js` / `index-D4LoVDk2.css`。最后发布提示增量现为 71 项通过，最新构建和单项浏览器证据见下文。测试覆盖：

- 中文、空格和短横线参数的有序去重；
- 研究应用保存时不继承凭据、原文件授权及旧结果；
- 两套发布接口的身份和撤回状态归一化；
- 改编创建独立流程，提交当前选择的输入和组件；
- 个人流程复制只保存定义，不启动运行；
- 账号切换后的迟到组件响应不能显示到新账号。
- 发布日期按 Asia/Shanghai 展示；
- 精确依赖候选保留多个个人副本与旧版本；
- 后端返回的歧义候选省略验证状态时，合并仍保留目录已有的可用状态，不把已验证组件误报为未验证；

- 页面卸载后的迟到写请求不会继续执行页面动作。
- 共创目录完整翻页、游标转义、过期请求停止翻页、重复游标错误提示。
- 未知复制结果保留原准备请求体和幂等键；明确错误后才允许重新准备，成功恢复后新的独立复制获得新键。
- 相同来源的独立 `bindingId` 与旧流程 Tool / Skill 同名组件使用不同选择键。
- 已选但目录缺失、或锁定历史版本的引用保持可见，替换需用户明确操作。

## 隔离浏览器验收

2026-10-14 使用 `tests/browser_evolution_fixture.py` 与 `tests/browser_evolution.mjs`：临时 DATA_DIR、独立作者/读者账号、合成数据、模型替身、真实 WASI。本轮验证不调用真实模型，不修改正式账号或数据。

实际浏览器通过的操作链：

1. 成功任务保存研究应用，编辑中文参数模板，填写全新参数并执行，结果明确反映本次输入。
2. 应用检查发布清单、确认分享；另一账号缺依赖时显示精确版本提示。
3. 成功代码打开可读草稿，修改 `source.py` 后保存；读取保存版本确认编辑已保留。使用新的三行 CSV 验证，真实输出价格变化 50%、最大回撤 25%，与原五行样例区别明确；验证后手动启用。
4. 外部流程包预览、保存不执行；模拟后端保存成功但响应丢失，点击重试仍只有一份应用。上传新 CSV 运行，实际输出 A=15.00、B=7.50；导出包不含本地应用 ID。
5. 既有流程进入对话改编，无需先满足原应用的旧文件输入，即可生成新流程并等待参数。
6. 接收者复制 Tool 和 Skill 后均默认停用，应用执行被准入检查阻止。接收者实际测试 Tool、审阅 Skill 结果并逐项启用，然后以新参数运行应用成功。
7. 同一 Tool 保存第二个个人副本后，研究应用社区复制和文件导入均要求显式绑定；用户选择原精确版本后保存成功。社区绑定选择在 390px 窄屏实际操作通过。
8. 作者导出的外部流程由读者导入；授权读者自己的新 CSV，输出 R=10.00、S=2.00，没有重放作者 A/B 数据。
9. 开发资料包可下载；桌面和 390px 窄屏检查覆盖共创目录、沉淀编辑与依赖选择，等待侧栏动画结束后截图，无横向页面溢出，无页面脚本错误。
10. 成功任务沉淀 Skill，实际运行验证并审阅后进入发布预览；展开主 Skill 的完整方法、依赖 Tool 的完整代码及示例 CSV，核对内容与来源一致。未勾选确认前发布按钮不可用；桌面和窄屏源码审阅通过。
11. 通过真实社区发布服务增加 101 项合成目录记录，确认原组件不在服务端第一页；浏览器刷新后仍能检索原组件，Tools 类型和“我的发布”筛选均可发现这一后续页结果。

## 当前限制

- 共创是同一平台实例内的账号间分享，不是公网托管站点。
- 导入检查和保存不证明业务效果；发布前仍需对应后端要求的有效验证或成功执行。
- 组件缺失时显示明确错误，用户需要先引入精确版本，不自动安装、替换或放宽权限。
- 研究应用按目标与规则重新执行；固定流程应用按已定义步骤运行。两者在页面上分开标识。
