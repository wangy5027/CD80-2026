# 主站接口规范

状态：2026-10-13 主站现状整理，能力库通过独立规范链接同步。基于 workbench/routes.py、service.py、auth.py 及 agent_platform/routes.py、service.py、repository.py。不是完整生成式 OpenAPI；新增或变化字段必须与实现一起维护。Tools/Skills 专项字段和事件以 [能力库接口规范](capability-library/接口规范.md) 及 [内置目录说明](capability-library/内置工具与Skill接入.md) 为准，避免复制两份契约。

## 通用约定

前缀 /desktop/api，使用 ficagent_session Cookie。注册登录返回 HttpOnly、SameSite=Lax、有效期 7 天的会话 Cookie。业务资源以登录用户限定；主站只允许本机 Host 和配置端口的同源 Origin。

JSON 成功结果没有统一包装；错误为 {"error":"说明","code":"可选业务码"}，能力和研究应用接口可带details。普通 JSON 对象请求体上限 2 MiB；统一资产App路由请求信封上限9MiB，内部定义/包仍限8MiB；2026-10-14已修正json_body的超限文案。普通文件请求另有单文件30MiB限制；数据管理用途文件为10MiB，不能混淆。

健康 GET /desktop/health（不在 API 前缀内）返回 ok、app、backend、instanceId。运行状态“已配置”不等于真实服务连通。

## 账号、工作台与文件

| 方法与路径 | 请求 | 成功响应与说明 |
| --- | --- | --- |
| POST /register | email、password，可选 name | {ok:true,user:{id,email,name}} |
| POST /login | email、password | 同上并设置 Cookie |
| GET /session | 无 | authenticated；未登录为 false，不把该探测当成业务鉴权 |
| POST /logout | 无 | 清除当前会话及 Cookie |
| GET /runtime | 无 | 公开模型运行信息，不返回密钥 |
| GET /state | 无 | 当前用户的工作台状态 |
| GET /tasks/{id} | 无 | 单个公开任务 |
| DELETE /tasks/{id} | 无 | 活动普通聊天或子任务队列返回409；不级联应用记录 |
| POST /projects | {name} | 201，项目对象 |
| DELETE /projects/{id} | 无 | 解除任务和文件归属，不删除内容 |
| POST /schedules | {title,at} | 201，{id,title,at,done:false} |
| PATCH /schedules/{id} | {done:boolean} | 仅更新完成状态，不是通用标题/时间编辑 |
| DELETE /schedules/{id} | 无 | 删除日程 |
| POST /files | multipart 的 file，可选 projectId、purpose=data | 201，文件元数据；data用途执行类型及10MiB校验 |

日程时间存 UTC，未带时区输入按 UTC 解释；客户端应传明确时区。日程只在浏览器运行时提醒，无服务端定时执行。

上传元数据包括 id、name、originalName、size、md5、sha256、type、projectId、createdAt。相同用户/项目/原名/大小/摘要及实际内容可复用，不能仅按显示名称判断内容相同。文件下载继续校验用户归属。数据管理用途增加source=data_management和有界dataInfo，允许CSV/TSV/JSON/XLSX；数据类型实际解析、私有文件复用及字段见[个人数据规范](financial-data/个人数据文件.md)。

## 普通聊天

POST /chat 核心输入：message（非空，最多 100000 字符），可选 taskId、agentId、modelId、projectId、fileIds。扩展字段不在此整理。普通文本附件最多前8个，单文件最多读取180000字节，总拼接文本250000字符；数据管理来源文件另按10MiB授权读取并生成每文件最多12000字符的明确有界预览，支持Excel解析，历史重建沿用同一规则。未选择文件不自动进入上下文，非数据用途的其他二进制不作为普通文本附件处理。

同用户同任务并发聊天返回 409。流开始前错误使用普通 HTTP JSON，开始后错误通过 SSE 传达，不能只看 HTTP 200。

响应 Content-Type: text/event-stream；每个事件以空行结束，data 为 JSON：
- meta：{taskId,title}
- token：{text}，增量文本
- error：{message}，流内错误
- done：{task}，最终持久化任务
- 其他扩展事件沿用其专项契约，客户端应允许未知事件。

示例：
```text
event: token
data: {"text":"示例"}

event: done
data: {"task":{"id":"任务ID"}}

```
最后一个示例仅示意事件包装，不是完整任务字段。断连或停止尽量保留部分回答，可带 partial:true；结束状态区分 done/error/stopped。停止时延需专项验证，不能只看按钮已停止。

## 应用分流、目录与运行

以下表格覆盖原应用链路。已实现的 capabilityRefs、replaceCapabilityLocks、taskRevision 及能力事件见能力库接口规范。2026-10-14固定应用已支持个人Tool/Skill精确引用，新增包接口见 [应用包与组件复用](agent-platform/应用包与组件复用.md)。

POST /agent-dispatch 依据 message 及任务/文件上下文分流为 chat、clarify、invoke 或 create；普通聊天分支由客户端随后调用 /chat。取消分类请求用 POST /agent-dispatch/{request_id}/cancel。分类不是所有请求都会执行应用的保证。

| 方法与路径 | 行为 |
| --- | --- |
| GET /agent-runtime | 执行器状态、maxSteps、并发等公开限制 |
| GET /agents | {agents:[...]}，可调用目录 |
| GET /agents/{id}/versions/{version} | 精确版本定义 |
| POST /agents | 保存成功运行对应的个人定义，201 |
| GET /agent-runs?taskId= | {runs:[...]}，最多 100 项、按更新倒序 |
| POST /agent-runs | 创建运行，202，返回运行文档 |
| GET /agent-runs/{id} | 观察运行 |
| POST /agent-runs/{id}/input | 补必要输入 |
| POST /agent-runs/{id}/approvals/{approvalId} | 批准或拒绝执行/文件授权 |
| POST /agent-runs/{id}/feedback | 终态反馈，不自动重跑 |
| POST /agent-runs/{id}/cancel | 取消，不删除 |
| GET /agent-runs/{id}/events | 可恢复的只读事件观察 |
| GET /agent-artifacts/{id} | 用户范围内下载产物 |

没有应用、运行和产物的 DELETE 接口。

创建运行输入：
```json
{
  "mode": "create",
  "idempotencyKey": "客户端唯一请求标识",
  "goal": "已明确的任务目标",
  "input": {},
  "fileIds": []
}
```
mode 为 create/invoke，默认 create。invoke 提供 agentRef（id@version）；可带 taskId。修订用新的 create 请求和 revisionOf 指向旧运行，不能覆盖旧结果。input 为对象，规范化 JSON 最长 40000，禁止客户端传 filePath/filePaths/outputDir。具体业务输入还需符合定义 schema。

新流程生成后进入 awaiting_input 或 awaiting_confirmation，预览不执行。已有应用本次直接调用可能进入 queued，不要求重新生成。运行中额外文件授权进入 awaiting_authorization。

补参：{input,fileIds?}，仅 awaiting_input 可接受，重新生成执行确认。
审批：{decision:"approve"|"reject",idempotencyKey,bindingDigest}。binding 绑定方案、输入、文件摘要及授权范围等，变更后不能沿用旧确认；拒绝转 cancelled。保存不能通过普通 execute/access 审批冒充。
反馈：{message}，最多 5000 字符，限终态，评价不自动修改并重跑。
保存：POST /agents，{runId,idempotencyKey,approvalId?,bindingDigest?}，仅 succeeded，可由显式保存请求建立保存确认；返回 {agentRef,spec}。同 owner/id/version 不同内容不得覆盖。

幂等以 owner/scope/key 隔离，同键同内容复用已有结果，不同内容 409。不能推导所有写接口都幂等：补参与反馈没有相同保证。

## 运行状态与事件

状态包括 generating、awaiting_input、awaiting_confirmation、queued、awaiting_authorization、running、cancelling、succeeded、failed、cancelled、interrupted。取消可能先返回 cancelling。服务重启不自动重跑，详见存储说明。

事件接口接受 Last-Event-ID（优先）或 ?after= 非负游标。格式为：
```text
id: 123
event: run.completed
data: {"eventId":123,"runId":"运行ID","taskId":"任务ID","type":"run.completed","at":"时间"}

```
具体 payload 随事件类型变化。等待时输出注释心跳；终态及等待输入/确认/授权时输出 done {runId,status}。一次连接有界，最多 100 轮、间隔约 0.2 秒，单批最多 500 条。断开观察不启动或重跑业务；恢复后按游标去重。现有前端主要轮询，不把 SSE 存在等同于前端已接入。

## 错误与其他模块

常见状态：400 格式/契约错误、401 未登录、403 来源/权限拒绝、404 资源不存在或不可见、409 状态/并发/幂等冲突、413 请求过大、502 上游失败、503 环境不可用、504 超时。具体业务错误以路由实现为准，不能把所有异常映射为同一种失败。

新闻契约见 [新闻规范](news/技术规范.md)；金融代理见 [金融接入规范](financial-data/技术规范.md)，独立数据接口字段以 [CONTRACT](../cd80-data-api/docs/CONTRACT.md) 和原 OpenAPI 为准。

## 2026-10-13：预置应用保存状态与独立副本

`GET /agents` 保留预置卡片并返回 `personalCopies: [{agentRef,name}]`。已保存的同引用应用在目录可同时有预置/个人项，前端键包含personal字段；分流候选仍按原有精确引用去重。内容一致比较包含定义及版本，排除ID、展示名称和origin。

`POST /agents/copy-preset`：请求 `{agentRef,idempotencyKey,confirmDuplicate?:boolean}`，仅允许平台注册的预置定义，保存不执行，返回201 `{agentRef,spec,personal:true}`。重复未确认409；确认后创建独立ID，重名递增后缀；同一幂等键重放不重复新增，不同内容同键409。沿用登录账号隔离。原成功运行后 `POST /agents` 保存流程保持不变。

## 主对话后台消息与子任务

新增/conversations/{id}/messages、queue及/sub-agent-runs、/sub-agent-artifacts；字段、幂等、修订和事件以 [子任务接口](sub-agent/接口设计.md) 为准。runtime新增subAgentAvailable布尔值。新队列占用期间旧/chat及应用dispatch/create返回409。旧/stop不替代子任务cancel。

子任务当前增加直接操作及动态委派、时间线字段和超时暂停语义，见 [修订](sub-agent/分流与会话体验修订.md)。无新增HTTP入口；不要再依赖旧应用分流决定普通分析请求的去向。

## 2026-10-14：研究应用、沉淀与共创

新增接口以 [愿景技术规范](vision-delivery/技术规范.md) 和 [社区组件契约](capability-library/社区发布设计与技术规范.md) 为准：

- `/evolution/recipes`：保存/列举研究应用；`/{id}/fork`改编、`/{id}/run`换参数执行、`/{id}/export`导出，`/import`导入。
- `/evolution/captures/preview`：从本人成功子任务生成可编辑的recipe/skill/tool预览，不保存或启用。
- `/evolution/publications`：应用发布目录与确认发布；`/preview`审阅、`/{id}/copy`独立复制、`/{id}/withdraw`撤回、`/{id}/export`取得快照。
- `/evolution/developer-kit`：下载兼容应用、Tool、Skill与标准库打包工具；不执行。
- `/community/capabilities`：Tool/Skill发布目录、预览、确认、复制和撤回；与官方目录分离。

以上仍需要账号Cookie，写请求使用Idempotency-Key。发布需明确确认预览摘要，应用需自身成功运行，能力需有效验证；复制不继承作者凭据、文件授权、验证和启用状态。依赖按来源与内容精确匹配，歧义通过dependencyBindings明确选择；不按显示名称匹配。


## 统一可复用 App（2026-10-14）

新入口 `/desktop/api/asset-apps` 以 Cookie 校验账号，支持草稿及版本、Creator、静态预览、双输入验证、启用、个人连接配置、运行/继续/取消、实际产物、完整包导入导出和旧资产升级目录。写操作使用 Idempotency-Key，修改和继续还要求 revision；单纯读取、预览、导入及保存草稿不执行资产。完整请求/响应、版本和错误语义统一维护在[接口与存储契约](asset-authoring/接口与存储契约.md)。旧 agent-platform 和 evolution 路由保留，不能混用旧定义与新版本格式。
