## 目标与范围

用户在主对话提出需要多步处理的目标后，由主 agent 确定交付、约束和验收要求，委派一个子 agent 完成执行并验收结果。用户不需要知道如何创建子 agent 或编排工具。

第一版覆盖金融数据获取、分析计算和可视化交付。框架服务于通用任务执行，不内置“某只股票应使用哪些指标、画哪种图”的固定业务模板。简单查询可由主 agent 直接完成；复杂任务由主 agent 判断是否委派。

每个复杂任务使用一个子 agent，内部顺序执行。多子 agent 并行、递归委派、自动交易、自动安装或发布新能力、自动把任务保存为应用，不在首版范围内。跨对话并发容量属于技术设计，不将同一对话串行误解为全站只能运行一个任务。

## 职责

| 角色 | 责任 |
| --- | --- |
| 用户 | 给出目标及限制，回答必要问题，可中断任务 |
| 主 agent | 理解目标、决定交付与验收要求、选择是否委派、指定优先能力、审批方案变化、向用户提问及最终答复 |
| 子 agent | 独立规划步骤、执行、管理中间结果、申请临时代码、检查并纠错，返回成果与限制 |
| 平台 | 强制执行权限、隔离、预算、串行队列、状态与持久化规则；模型声明不能代替平台检查 |

## 委派与能力使用

主 agent 传递目标、验收要求、必要对话摘要、用户约束、授权资源和优先能力；不必预先固定全部步骤。子 agent 可以调整执行细节，不能自行改变目标或降低验收要求。独立上下文不默认复制全部聊天历史，但用户明确约束不能遗漏。

子 agent 优先使用主 agent 指定的能力；可发现当前用户已经获准使用的能力。能力不足且用户没有要求必须使用指定能力时，向主 agent 提出替换方案或临时代码申请，说明缺口、资源、操作及输出。获准后才能执行，不允许先写代码执行再补审批。

用户强制指定能力时不得擅自替代。子 agent 不能自动导入、启用或修改能力，也不能借用其他账号的授权。现有官方能力准备流程与本任务执行是不同动作，本设计不授权子 agent 自动触发准备或启用。

主 agent 可自主批准原授权范围内的临时代码，无需逐步打断用户。新增费用、权限、依赖安装、数据来源或实质目标变化超出既有授权时，暂停并询问用户。能力包及数据返回内容不能自行扩大权限。

## 数据与交付

中间结果以实际结构化数据或文件引用传递，下一步直接读取获准使用的原结果；不让模型转抄完整数据充当计算输入。记录来源、输入输出关联及检查结果。

交付内容由主 agent 根据需求、Skill/Tool 与执行环境确定，可以包括分析、图表、数据和代码。需要图表时须能实际查看和下载，但框架不强制某种图表或文件格式。临时代码及成果随任务保存，不自动成为公共或个人能力。用户明确要求沉淀时，另行进入保存与验证流程。

后续“换一只股票”“改为另一个区间”等请求，可以参考之前的方法、代码和产物，但必须按新要求重新取数、执行与检查，不能把旧结果冒充新结果。

## 用户流程与队列

1. 主 agent 理解需求，必要时澄清；对不改变任务本质的默认方案可简短说明后继续。
2. 需要委派时创建子任务，展示实际阶段。子 agent 顺序执行，必要时申请主 agent 审批。
3. 运行期间不处理用户的新对话请求；新消息按顺序排队，可以查看和撤回，不能提前规划或调用工具。
4. 缺少必要回答时进入等待状态，通过专门入口接收回答并继续当前任务；普通队列不能绕过等待任务。
5. 子 agent 提交结果，由主 agent 验收；通过后统一答复，再执行下一条排队消息。
6. 用户中断时停止后续执行，保留未完成成果并标注状态；整个对话队列暂停，等待用户选择继续。

页面刷新或关闭不停止后端任务，重新打开可恢复查看。服务重启后未完成任务标记中断，队列暂停，不自动重放外部调用。普通失败或部分交付之后如何处理队列的工程默认方案见技术规范，与用户主动中断明确区分。

## 纠错与验收

模型请求详情及格式失败恢复按[模型请求记录与格式纠错](模型请求记录与格式纠错.md)执行。后续用户反馈明确普通界面只显示业务请求、输出节选和必要状态，系统/开发者提示词及原始JSON下载入口不展示；后台完整诊断仍按本人权限保留，见[摘要展示](模型请求摘要展示.md)。旧记录不能补造。格式错误只重试当前阶段，计入全任务纠错预算；模型验收建议与平台最终裁定分开，界面展示最终裁定。

子 agent 使用 ReAct 的行动、观察与调整循环。正常执行步骤不消耗纠错预算；首次失败后，修改并再次执行算一次纠错。整个子任务最多 3 次，不按步骤重新计数。主 agent 验收退回修改也计入同一预算，禁止重新委派同一任务绕过上限。

方案内参数及代码修正可自主进行；能力替换、首次临时代码执行及实质方案变化仍须审批。网络、权限和数据缺口不得全部当成可盲目重试的代码错误。不能通过错误重试自动改变数据来源、日期或标的。

主 agent 必须核对交付要求、实际执行依据、数据和计算检查、产物可访问性、遗漏及限制，不能仅凭子 agent 声称成功就标为完成。预算内可退回纠错；仍不满足时明确说明失败或部分完成。

## 进度与异常体验

默认展示真实阶段及停止入口；展开后提供能力调用、输入输出摘要、代码、产物、审批、错误、纠错次数及简短决策说明。不展示模型内部思维过程。

| 情况 | 用户体验 |
| --- | --- |
| 指定能力不足 | 明确缺口；范围内由主 agent 审批替代，强制能力不得静默替换 |
| 数据缺失或口径不明 | 明确来源、覆盖和限制，必要时询问，不捏造数据或擅自更换来源 |
| 等待回答 | 显示具体问题与回答入口，保留队列 |
| 规划阶段失败，尚未调用能力 | 任务卡直接展示实际失败原因；旧记录缺失用户消息时补齐会话显示顺序，不伪造执行步骤 |
| 达到纠错或执行预算 | 展示已完成成果、未完成内容及原因 |
| 上游无法立即停止 | 显示正在停止，不再发起后续操作，迟到结果不转为成功 |
| 刷新或服务重启 | 分别恢复查看或显示中断；不误报完成、不自动重跑 |

“平安银行 2022 年股价分析”是验收实例：主 agent 决定分析目标与图表，先核查真实数据覆盖及能力可用性；不因案例文字假定现有库必有该年数据或完整绘图能力。

## 验收条件

以下保留完整业务验收目标；TC-SA-001及补充边界已部分覆盖，不能视为全部AC的真实模型验收通过。逐项证据与未覆盖项见 实现验收（本地资料，未随源码发布）。

| 编号 | 条件 |
| --- | --- |
| AC01 | 简单请求可直接处理；复杂请求自动委派单个子 agent，交付由主 agent 定义，框架无固定金融模板 |
| AC02 | 子任务上下文独立且保留全部用户约束；不读取未授权用户、任务或文件 |
| AC03 | 优先使用指定能力；强制能力不可替代，禁用或验证失效能力不能执行 |
| AC04 | 临时代码申请具有缺口、范围和输出说明；批准前不可执行，越界必须询问用户 |
| AC05 | 多步读取同一真实数据或文件引用，来源及摘要可追溯；禁止模型转抄代替大数据输入 |
| AC06 | 隔离代码确实执行，结果和图表可读取；执行失败不能回退宿主 Python |
| AC07 | 首次执行不计纠错，跨步骤及验收退回累计最多 3 次；重复请求、刷新及重新委派不重置预算 |
| AC08 | 主 agent 对缺项、无执行依据或无效产物拒绝完成，预算内纠正，耗尽后如实交付 |
| AC09 | 同一对话一次一项，新消息只排队；顺序、撤回及多页面操作不造成重复执行 |
| AC10 | 等待回答的专用入口继续当前任务，普通排队消息不能被误当回答或提前执行 |
| AC11 | 用户中断停止后续步骤并暂停队列；上游迟到结果不覆盖取消状态，成果标明未完成 |
| AC12 | 刷新或关闭页面不取消后端任务；重开恢复状态、队列、进度与产物 |
| AC13 | 服务重启后未完成任务中断、队列暂停；不自动重放调用 |
| AC14 | 进度来自真实事件，可查看操作、审批与纠错记录，不暴露凭据或模型内部思维过程 |
| AC15 | 成果持久保存；后续改需求重新执行，不自动保存成应用、Tool 或 Skill |
| AC16 | 金融实例完成取数、分析和可视化及主 agent 验收；缺数据、能力不足和强制能力场景均有独立证据 |
