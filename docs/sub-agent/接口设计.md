## 通用约定

前缀/desktop/api，沿用Cookie、本机Host/Origin及owner隔离。conversationId等于工作台taskId；sub-agent runId与应用agent-runs ID属于不同资源。错误沿用{error, code?}，没有统一requestId/details。不可见资源404；无效参数400，修订/状态/幂等冲突409，容量429，产物过限413。执行中的错误写任务终态及answer，202不代表完成。

全部写接口必须携带1—150字符Idempotency-Key。同owner、操作、key重复且内容相同不重复执行，不同内容409。提交重放返回原任务的当前快照；控制命令重放返回原响应。记录随库保存，暂无过期清理。控制命令携带整数revision，使用run当前revision（resume使用queue revision），过期409及REVISION_CONFLICT。

## HTTP

| 方法与路径 | 请求 / 响应 |
| --- | --- |
| POST /conversations/{id或new}/messages | message必填；可选fileIds、capabilityRefs、skillNames、agentId、modelId、projectId、searchMode、replaceCapabilityLocks、taskRevision。返回202及完整Run（id、conversationId等），不是queueItemId包装 |
| GET /conversations/{id}/queue | {id, revision, paused, activeRunId, items:[Run...]}；无记录时返回空队列；历史项也保留 |
| POST /conversations/{id}/queue/items/{runId}/withdraw | {revision}；仅queued可撤回，返回Run |
| POST /conversations/{id}/queue/resume | {revision}；返回Queue（items为内部run ID列表）；随后GET获取完整项，不重跑终态任务 |
| GET /sub-agent-runs/{runId} | 完整Run，包含步骤、审批、观察、工件元数据与终态结果 |
| GET /sub-agent-runs/{runId}/model-calls/{callId} | 本人、本任务的单次脱敏模型请求记录；download查询参数返回JSON附件；no-store/nosniff；旧记录无详情返回404 |
| POST /sub-agent-runs/{runId}/cancel | {revision}；返回Run，可能cancelling；同时暂停所属队列 |
| POST /sub-agent-runs/{runId}/questions/{questionId}/answer | {revision, answer}；answer非空且最多10000字符；仅awaiting_user和当前questionId可用；返回Run |
| GET /sub-agent-runs/{runId}/events | after查询参数或Last-Event-ID整数游标；按顺序最多500条SSE事件，响应结束后重连继续观察 |
| GET /sub-agent-artifacts/{artifactId} | 实际字节；PNG/JPEG/WebP/GIF可安全内联，其他类型附件；带download查询参数强制附件；CSP sandbox、nosniff、no-store |

capabilityRefs格式为[{assetId,versionId}]，最多8项；fileIds最多8项，skillNames最多3项。附件/项目/模型归属及格式在提交时检查；能力在执行时按现有准入复查。新会话使用字面值new创建，重试须沿用原URL、正文和key。

旧/chat、应用dispatch/create在同对话有队列工作时拒绝409，不能绕过串行。旧/stop不是子任务取消API；子任务卡调用上述cancel。旧应用活动时新入口返回409，未把应用队列合并。

## 任务和内部模型契约

| 对象 | 实际字段与约束 |
| --- | --- |
| Run | id、conversationId、logicalTaskId、revision、status、kind、payload、message、correctionsUsed、rounds、steps、artifacts、approvals、reviews、observations、loadedRefs、createdAt/updatedAt；按阶段增加delegation、question、deliveries、answer、activeSeconds等 |
| Delegation | mode=delegate、goal、deliverables、acceptanceCriteria、constraints、contextSummary、preferredCapabilities、requiredCapabilities、allowTemporaryCode、requiredExtensions、assessment；requiredCapabilities为资产ID/内置工具名，requiredExtensions如.png但由任务确定 |
| Step | id、type、status、correctionIndex、inputRefs、startedAt、completedAt，以及name/result/error；失败无成功交付 |
| Artifact | id、runId、conversationId、stepId、name、size、sha256、mediaType、sourceRefs、complete、createdAt、downloadUrl、可选preview |
| Approval | id、reason、inputRefs、scope、decision、scopeDigest；由内部主agent批准/拒绝/提问，不存在客户端批准接口 |
| Question | id、prompt；绑定Run的revision和awaiting_user状态；回答进入observations |
| Review | decision为accept/revise/fail，及answer/reason；平台缺项检查可强制改为revise |

2026-10-14增量：plan的answer、finish及review可提供 `completion: "complete"|"partial"`、`missingDeliverables: string[]`（最多32项）、`adoptedStepIds: string[]`、`resultArtifactIds: string[]`（后两项各最多64项）。后两者必须引用本run成功步骤/实际结果工件，不能代替归属、状态和摘要核验。run的 `completion={status,missingDeliverables,reasons}` 记录平台最终交付结论；status为complete/partial，状态仍复用succeeded/partial，不新增终态。用户明确图表目标未交付时，模型accept会裁定为review fail及run partial，保留其实际缺数说明及已完成查询。

经校验的run.adoptedStepIds/resultArtifactIds及execution_evidence.adopted给出文字/文件采用闭包；没有显式依据时不自动采用全部成功步骤。新字段为兼容增量，旧GET不派生完成结论、不重写历史；候选步骤与目标完成分别由成果沉淀入口呈现。内部模型响应的completion字符串与持久化run.completion对象不可混用。

owner在数据库键和认证上下文中，不接受客户端/模型传owner。纠错计数、轮次、状态由协调器修改，模型不能写。没有executionEpoch、独立planRevision或外部accept接口。字段验证与行为测试已实现，但不是完整结构Schema验证器。

主agent规划有chat/answer/direct/ask/delegate/application六种结果；direct包含单个tool/read动作，完成后重新判断并可升级委派。assessment={needsInformation,dependentProcessing,explicitApplication,reason}；明确应用意图优先交接应用，非应用的dependentProcessing=true不能走简单回答。子agent每次tool/read/code/ask/finish一种动作。tool含name、arguments、可选inputRefs；code含reason、inputRefs、code，代码定义run(payload)，返回JSON并写/output文件；finish含answer和artifactIds。禁止传任意宿主路径。内部字段详细提示见 [model.py](../../backend/app/modules/sub_agent/model.py)。

## 观察和权限

事件含eventId、runId、conversationId、type、at、revision、payload。当前包括run.created、run.phase_changed、step.started/completed/failed、artifact.created、approval.requested/decided、question.opened/answered、correction.started、review.completed、run.completed、queue.changed及能力桥状态事件。队列以GET快照为准，非每次变更均单独发队列SSE。

GET和刷新不推进任务。UI每秒读取队列，按账号/会话代次丢弃迟到响应；无持续SSE心跳。操作记录保留可检查的动作和短说明，不要求模型输出内部思维过程。工件可下载实际源码和结果，不返回凭据；源文件中的用户业务内容仍按原owner访问。
