# 金融分析子任务端到端测试用例

用例编号：TC-SA-001。优先级：P0。更新：2026-10-13（Asia/Shanghai）。状态：第一版功能与夹具已实现，确定性模型替身＋真实WASI＋浏览器通过，见 验收记录（本地资料，未随源码发布）。

## 测试目标

验证用户在主对话提出金融分析需求后，主 agent 委派一个独立子 agent，优先调用指定能力，通过主 agent 审批补充临时代码，以真实数据引用完成计算与绘图，并在全任务累计三次纠错后通过主 agent 验收。运行中新消息只排队，页面刷新不停止任务，完成后再处理排队消息。

本用例规定的证券、公式、PNG与CSV格式仅用于构造确定性测试，不是平台固定分析模板。行情是合成样例，不是平安银行真实历史价格；通过本用例不能宣称真实金融上游或真实模型效果通过。

## 固定输入

测试夹具按UTF-8、LF换行、末尾换行生成下面的CSV；上传到测试资源区，并记录实际文件ID和SHA-256。此处名称是用例要求，不要求将测试文件安装进正式公共目录。

文件名：`pingan-synthetic-2022.csv`。

```csv
symbol,date,close
000001.SZ,2022-01-04,10.00
000001.SZ,2022-01-05,12.00
000001.SZ,2022-01-06,9.00
000001.SZ,2022-01-07,11.00
000001.SZ,2022-01-10,12.00
```

数据源元信息固定为：`source=synthetic-fixture`、`synthetic=true`、`currency=CNY`、`price_basis=synthetic_unadjusted_sample`、`row_count=5`。实际覆盖为2022-01-04至2022-01-10，不代表整个2022年或全部交易日。

主请求M1：

> 请分析测试数据源中标记为平安银行（000001.SZ）的这5条2022年合成价格样例。优先使用现有样例读取工具和分析Skill；分析或绘图能力不足时允许你安排临时代码完成。按日期升序计算样例首末收盘价变化率，以及运行最高收盘价到后续收盘价的最大回撤；画一张收盘价折线图。请交付PNG图、实际使用的CSV、Python代码和简短分析，明确是合成样例，不是全年真实行情或投资收益。不要联网、安装依赖、修改原数据，或保存成新应用、Skill、Tool。

运行中提交的消息M2：

> 上一项完成后，请只告诉我刚才用于计算的CSV有多少条数据，不要重新取数或生成文件。

由主 agent 根据M1形成交付和验收要求，主 agent指定上述两个测试能力为优先项，不设为不可替代的强制项。用户没有直接给子 agent临时代码执行授权令牌，内部审批仍必须发生。

## 可控故障安排

所有故障通过测试模型替身返回的代码或交付内容注入，正式沙箱必须实际执行并产生真实错误；不得直接伪造“执行失败/通过”的最终状态。

| 轮次 | 注入内容 | 应观察到的结果 |
| --- | --- | --- |
| 初始执行，纠错编号0 | 第一份计算代码保留一个确定的Python语法错误 | 执行失败，诊断包含SyntaxError，纠错计数仍为0，未生成有效分析产物 |
| 纠错1 | 修复语法，但读取不存在的列 `close_price` | 实际报KeyError，不能报告成功或用模型心算替代 |
| 纠错2 | 修复列名，完成正确计算和真实绘图；提交交付清单时故意遗漏Python代码下载引用，代码本身仍有执行记录 | 主 agent对照M1发现缺少代码交付，拒绝完成，要求补齐；不能自动忽略用户要求 |
| 纠错3 | 补齐正确执行版本的Python代码引用，重新检查全部交付；无需重复取数和计算 | 主 agent接受；计数为3，不能因只补交付而遗漏验收退回计数 |

主 agent测试替身不能无条件返回accept或revise：只有读取到对应实际工件和校验结果后，才返回相应决定。故障属于方案内纠错，不引入新来源、依赖或权限，不应重复请求同范围临时代码审批。

## 操作步骤与逐步断言

| 步骤 | 操作 | 预期结果与取证 |
| --- | --- | --- |
| 1 | 准备临时账号、两项能力和CSV；记录能力版本、启用状态、CSV摘要、已有应用及个人能力清单 | 只有测试资源；5行输入准确，初始清单可用于比较是否发生自动沉淀 |
| 2 | 登录账号A，在空白对话C提交M1一次 | 主 agent自动决定委派，无需用户手动创建子 agent；只创建一个逻辑子任务R1，纠错数0 |
| 3 | 读取委派契约与子任务上下文摘要 | 含目标、四类交付、公式、合成限制、禁联网/安装/写数据/沉淀、两个优先能力；不复制无关聊天，不创建孙agent |
| 4 | 允许子 agent加载Skill并调用读取工具 | 调用记录匹配指定版本和账号A；真实返回数据工件D1，含来源和5条记录；没有跳过能力直接编写全部取数代码 |
| 5 | 子 agent识别缺少可执行分析/绘图能力并提交申请；暂不释放主 agent批准 | 申请解释能力缺口、只读D1、所需临时代码、输出范围；此时临时代码执行次数为0 |
| 6 | 主 agent根据M1批准范围内代码执行；在第一次沙箱执行前设置屏障 | 审批绑定R1和有效方案修订；权限未扩大；不要求用户再次确认原范围操作 |
| 7 | 屏障保持期间提交M2 | M2显示排队，正文完整；没有针对M2的模型请求、工具调用、回答或提前解析“刚才”；R1仍占用执行位置 |
| 8 | 刷新浏览器并重新打开对话C | R1标识、审批、D1、队列M2均保留，纠错数仍为0；没有第二个R1，没有重复读取工具调用；刷新不释放或取消执行屏障 |
| 9 | 释放屏障，执行首份含语法错误的代码 | 真实沙箱产生SyntaxError；记录失败步骤，R1不转成功；模型接收有界错误观察而不是伪造成功产物 |
| 10 | 子 agent开展纠错1，执行错误列名代码 | 计数原子增加到1，真实KeyError被记录；输入仍引用D1，没有重新手抄CSV或更换数据源 |
| 11 | 子 agent开展纠错2并执行正确代码 | 计数增加到2；实际计算和PNG生成成功，数据摘要及公式符合独立基准；没有新增网络访问、依赖或能力启用 |
| 12 | 检查计算到绘图的数据传递 | 代码实际读取D1或其经记录的只读挂载；绘图使用相同数据/分析工件引用。步骤输入摘要可连回D1；即使只有5行也不能用模型重新填入的价格数组代替文件输入 |
| 13 | 提交故意缺代码下载引用的交付清单给主 agent | reviewing后判定未满足M1，记录缺项并退回；用户端不出现已完成，M2仍排队 |
| 14 | 开展纠错3，补齐已执行的正确代码引用 | 计数增加到3，执行侧不再重复扣减；下载代码与实际正确执行版本摘要一致，不能交付最初两份错误代码冒充最终代码 |
| 15 | 主 agent重新读取全部交付及执行依据并验收 | R1成为succeeded，正式答复明确20.00%、25.00%、5条、合成样例及实际日期区间；附可访问的图、CSV和代码 |
| 16 | 在主对话查看图并下载全部文件 | PNG可被独立解码器打开并人工核对五个点；CSV与实际计算输入语义一致，未转换时字节摘要一致；Python可读取且与最终执行版本对应 |
| 17 | 观察队列推进 | 只有R1成功及主 agent最终答复持久化后，M2才开始处理；根据R1的实际数据工件回答5条，不重新取数或产文件，不启动新的子任务 |
| 18 | 再次刷新并核对能力/应用清单和原数据 | 图、CSV、代码及纠错记录仍可查看，最终纠错数3；两项测试能力状态及版本未改，未增加应用/Skill/Tool；原CSV摘要不变 |

每一步都以实际后端状态和操作记录为主，截图仅补充页面体验。不要用固定睡眠推断任务完成；等待已定义事件或状态直到测试超时。测试屏障用于稳定观察先后关系，不是生产功能。

## 必须成立的顺序与数据断言

使用事件ID、任务revision和调用关联记录判定先后，不只比较可能精度不足的时间戳：

1. 指定能力实际使用在临时代码执行之前；申请、批准均先于第一次临时代码执行。
2. 刷新前后同一R1、同一D1，不增加重复任务或读取动作。
3. 所有计算输入可追溯到D1；图表可追溯到实际分析数据；数值不是主 agent在无执行依据时自行补写。
4. correction.started编号依次为1、2、3；第3次来自验收退回，R1和逻辑任务ID不变。
5. 主 agent最终通过先于R1完成；R1答复完成先于M2首次模型处理。
6. 能力清单、启用状态和原始CSV在前后核对中保持一致。

## 判定标准

通过：全部步骤与独立数值基准满足，三个纠错编号及审批/验收证据齐全，所有要求的产物实际可读，队列未抢跑。

失败：任何关键断言不满足，例如批准前执行、取数被跳过、模型转抄数据、数值错误、产物不存在、遗漏代码仍标成功、计数重置、M2提前执行或任务自动沉淀。记录首次失败及后续影响，不用重跑成功覆盖失败记录。

阻塞：功能、故障夹具、任务工件或隔离绘图能力未就绪，无法执行步骤。首次运行曾因WASI缺少zlib失败，改为标准库PNG方案后复验通过；保留失败和重跑事实，详见验收记录。
