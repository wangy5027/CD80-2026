## 2026-10-15 临时代码输入契约修复

临时代码的 `run(payload)` 接收普通 Python 字典；`payload["files"]` 将本次 `inputRefs` 的工件 ID 映射为已挂载的完整 `/input/<安全名>` 绝对路径，代码直接 `open(path)`。不能使用 `payload.files` 属性，也不能再次拼接 `/input/` 或扩展名。宿主既有 `_code`、执行器、文件归属/摘要检查及权限不变；本次修正 `model.py` 的错误说明，并将实际发送的可执行读取示例与真实 WASI 回归共用。

模型对 `tool-result.json` 应先核对实际 JSON 结构，再读取完整 `content.records`。分页数量按实际返回页累计，`provenance.dataReads[*].snapshot.rows` 仅表示底层源扫描数量；`has_more=false` 不证明市场交易日完整。规划 `dependentProcessing=true` 需完整委派，列表字段使用字符串数组；继续使用原阶段校验、审批和全任务3次纠错预算。实现及验证见本轮记录（本地资料，未随源码发布）。


## 2026-10-15 个人数据文件输入（当前实现）

本次消息显式选择的数据管理文件复用工作台文件 ID；服务端以当前账号 `open_file(owner, file_id)` 读取实际字节，只有 `source=data_management` 可使用单文件 10 MiB 输入上限。上传时已限定 CSV、TSV、JSON、XLSX 和 10 MiB；执行时再次按实际读取量限制，并由 `data_context` 核对 SHA-256、重新解析真实格式，字节变化不沿用旧摘要。普通附件复制成子任务工件仍限 4 MiB；所有输出及其他工件仍限单个 4 MiB，每任务合计 32 MiB、64 个。底层隔离执行器总输入 16 MiB 预算继续叠加。

数据文件以 `artifactRole=input`、`inputSource=data_management`、原文件 ID 的 `sourceRefs` 和当前字节摘要保存为任务工件；原始完整字节存于 `sub-agent.sqlite3`，供获准的 Tool 或经主agent批准的 WASI 代码读取。模型上下文仅含不超过 4000 字符的可读预览；`read` 动作重新从已保存字节生成不超过 8000 字符的预览并带 `truncated`，XLSX 展示工作表/列和样本内容，不把 ZIP 二进制当文本。工件后续读取仍校验 owner、conversation、complete 和 SHA-256。长展示名丢失扩展名时保留经上传校验的实际后缀。预览明确标注仅样本，不是全表统计或文件内指令。

源文件删除后不能再作为新的 fileId 附件选择；已经保存的同账号子任务工件及历史步骤暂不级联删除，仍受原任务的账号和会话权限控制。该存储取舍见[文件生命周期](../存储与数据生命周期.md#个人数据文件与任务快照2026-10-15)，整体入口与格式见[个人数据文件规范](../financial-data/个人数据文件.md)及[复用文件池决定](../decisions/2026-10-15-个人数据复用文件池.md)。历史首版预算表的“单个工件 4 MiB”应按本节的唯一数据输入例外理解。

后台线程执行不依赖浏览器连接。普通聊天由协调器消费原聊天流并复用消息保存，避免重复答复；复杂任务由主agent验收后保存答复，再释放队列位置。

## 队列与状态

同owner、conversation只有一个活动任务；等待消息最多20条，按持久列表顺序取出。提交只校验和保存快照，不为排队项调用模型。pending消息开始执行时才理解“刚才的图”等语义并检查能力。已完成历史项保留，可撤回queued项。

任务状态为queued、planning、running、awaiting_main_approval、awaiting_user、reviewing、cancelling及终态succeeded/partial/failed/cancelled/interrupted/withdrawn。队列另外维护paused、activeRunId和revision。

成功、非超时的普通失败及部分完成在答复落地后继续后续项。请求超时在同一3次预算内只重试当前模型阶段，不重放成功工具；整体超时或请求重试耗尽，终止任务并暂停队列。用户中断先暂停队列再发停止信号；不能接纳迟到成功。等待回答保留执行位置，只接受绑定questionId和revision的专门回答。恢复队列仅执行尚未开始项，不重跑取消或中断项。此处普通失败继续队列是首版工程默认值。

主对话使用新入口。旧/chat、应用dispatch/create及删除任务入口在同对话有活动或待执行队列时返回409。原有应用已运行时，新消息入口返回409，尚未将应用生命周期迁入队列。普通消息不再先经过旧应用意图分流，全部进入主agent统一判断；仅明确应用意图才交还应用流程，交接后暂停消息队列，应用完成后可手动继续。选择已有应用的入口保留，应用生成、确认和保存保持独立。

锁和调度按单服务进程设计，不支持多个服务进程共享该数据库并同时消费队列。并发槽全站4个，并不表示已完成高并发验收。

## 能力、审批和文件传递

复用ChatCapabilities、内置工具注册表及既有能力准入。选中/主agent指定能力先加载；每次个人能力执行复查owner、版本、验证、启用和配置。requiredCapabilities使用资产ID或内置工具名：Tool必须有成功调用，说明型Skill必须已加载；临时代码执行前与最终验收均检查，模型不能自行忽略。

规划的preferredCapabilities只接受个人目录的准确assetId/versionId；内置工具直接使用availableTools中的名称，不构造builtin:资产或latest版本。模型推荐加载失败时，先保存脱敏引用、来源和准入原因，按原全任务3次预算重新规划，成功加载后才提交委派；不把空研究步骤包装成已执行失败。用户明确选择的capabilityRefs继续在规划前严格准入，必须使用的引用不可用时明确停止；规划纠错不能删除先前requiredCapabilities或放宽归属/启用/验证限制。

上述requiredCapabilities保留只覆盖模型自行重试。尚未委派时，用户对规划澄清作出新回答后，模型可依据新回答重新理解需求；旧要求列表附于回答观察供审计，不重置纠错预算，不变更用户选中的能力准入。已有委派的强制约束继续保留，不能借执行期问答自动解锁。planning.capability_rejected事件及observations记录modelCallId、来源model.preferredCapabilities、脱敏rejectedReference/references和准入errorCode；这是纠错证据，不是能力已执行的步骤。

临时代码须委派allowTemporaryCode=true，再由主agent批准。申请记录原因、inputRefs和隔离执行范围；scopeDigest包含输入和不可变委派。同任务相同或更小输入范围可复用批准，新增输入需重新审批。模型权限判断不能开放WASI网络、安装依赖、宿主文件或业务写入。需要用户补充时进入专门问题；文字回答不直接产生权限令牌，也不解锁外部能力。

工具产生的真实JSON和文件存为工件，记录sha256与来源；后一步只传工件ID，服务端检验同owner、同conversation及complete，再映射为/input/<工件ID><扩展名>只读文件。可以复用同对话历史工件。任务文件通过能力服务内部task_files关键字参数传递，普通HTTP调用者不能直接注入字节或宿主路径；能力仍需声明inputFiles权限。

临时代码复用SandboxExecutor：CPython/WASI、无网络、不回退宿主；输出只写/output。执行成功后保存结果、输出与实际执行的完整源码。导出源码包含绘图辅助模块，已在全新WASI实例复跑验证。任何失败不伪装为成功结果；已保存产物可在执行依据中查看，失败任务不显示为最终交付。

当前WASI没有zlib、pandas、matplotlib。内置PNG辅助函数通过CRC32和未压缩deflate实现，可绘制2—1000个有限数值点，支持ASCII标题和标签；中文说明展示在对话中。这只是可用辅助能力，不强制所有任务采用折线图。中文图内字体、复杂图形和额外第三方依赖未覆盖。

## 验收与预算

2026-10-14 缺图与部分完成修订：用户原消息明确要求绘图/可视化时，平台保留该交付要求，模型把目标改写成“如数据支持”不能解除。仅用户原文或专门澄清回答中明确取消图表要求可解除；知识解释、否定表达不建立绘图要求。该保护不参与金融/非金融路由，也不把单条行情、两融或取数成功视为历史走势已完成。缺数据时保留实际说明和查询记录，不造图、不为缺图盲重试；没有真实可读取的图表交付即使用现有partial结束并列未完成项。

plan的answer、finish及review可声明 `completion: complete|partial`、`missingDeliverables: string[]`，文字结论可通过 `adoptedStepIds`、`resultArtifactIds` 显式引用采用的真实依据。平台核验引用属于本账号、本run及成功步骤，结果工件为完整实际结果/输出且摘要一致；无效引用按原纠错预算处理。最终run增加 `completion: {status,missingDeliverables,reasons}` 和已核验的采用引用；缺图可强制将模型accept裁定为partial，保留原answer。已采用步骤按显式引用及文件依赖闭包记录，不能把全部成功查询自动视为最终方法；部分完成也可保留采用依据供用户明确选步骤沉淀。旧记录不回填、不重写，其未标明采用的成功步骤仅能作为明确选择的候选。

该保护从原消息及实际用户回答中的明确表达建立要求，不采信模型条件化委派或工具结果中的取消说法；不宣称覆盖任意自然语言。存在性检查要求本run成功步骤产生、已选交付且字节与摘要一致的可读取图像/PDF或含SVG/canvas的HTML；格式内容校验不能证明图表语义、历史序列口径或金融结论正确，仍须主agent依据实际数据验收。独立Skill沿用App节点交付契约，不以全局任务文字覆盖其结构化结果范围。新增完成/引用字段保存在原run JSON中，无数据库结构迁移；回退前备份原DATA_DIR，保留历史记录与新字段，不自动重放。定向证据见缺图验收与文字依据（本地资料，未随源码发布）。

2026-10-14新增[模型请求记录与格式纠错](模型请求记录与格式纠错.md)：MODEL_JSON_INVALID / MODEL_SCHEMA_INVALID 在原预算内重试当前阶段；回传 validationFeedback，不重放已成功工具。认证、连接和截断仍按各自错误处理。脱敏诊断独立存于 records(kind=model_trace)，不进入轮询正文或模型下一轮上下文；重启同步未完成调用/记录为 interrupted。

平台检验交付引用归属、字节摘要、所需扩展名及强制能力执行记录，再把真实步骤、结果和交付交给主agent验收。缺项不能被accept覆盖；业务语义和数值判断仍依赖主agent与能力契约，不能仅凭此断言所有真实模型任务正确。

首次尝试编号0；每次动作失败或主agent退回，事务增加correctionsUsed，整任务最多3次；第4次纠错不会启动。没有重委派接口，刷新/回答不重置预算。失败后依据观察重新选择动作，不能无限修复。

## 持久化、迁移和恢复

DATA_DIR/sub-agent.sqlite3，user_version=1：records按owner/kind/id保存queue/run/request；events按自增ID排序；artifacts存元数据及BLOB。使用WAL、进程内锁及BEGIN IMMEDIATE，工件字节与元数据同库事务，不另建任务产物目录。

首次启动只创建新库，不迁移或删除原工作台/能力库数据。队列状态、步骤、审批、纠错与工件持久化；启动时活动任务（含等待回答）转interrupted并暂停队列，queued项保留。以不可变runId和状态拒绝迟到写入，没有独立executionEpoch字段。

工作台state.json和子任务库不在同一事务；消息用subAgentMessageId去重，正常结束先保存答复再释放队列。异常崩溃跨库一致性仍需进一步恢复演练。浏览器刷新仅GET，UI每秒轮询；事件接口为有界SSE快照，并非永久长连接。

前端兼容旧后端规划失败时仅保存助手回复的记录：按subAgentMessageId关联run，在该回复前补出用户消息与任务卡，不修改历史存储。failed/interrupted卡片直接显示answer或error；字段缺失时提供结束提示，不依赖会话回复刷新。终态旧记录不得展示仍在运行的步骤。

备份应先停止写入，或分别使用SQLite备份接口并保存完整DATA_DIR；不得只复制在线主库遗漏WAL。回退代码时保留新增库和原数据，旧版本忽略新库；不自动撤销历史答复。没有TTL清理、公开任务删除或工件垃圾回收；幂等记录随库保留。删除工作台会话不会级联删除子任务历史及工件，鉴权下载仍按owner限定。保留/删除策略与完整备份恢复演练列为后续工作。
