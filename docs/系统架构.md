## 服务与入口

Windows 通过 start-local.cmd 使用根 .venv 调用 cd80-data-api/scripts/start_all.py，先启动数据服务并检查健康，再启动主站。默认主站 127.0.0.1:8894，数据服务 127.0.0.1:8897；直接 main.py 默认 8893。两者只面向本机。

主站 main.py 加载配置，以 Waitress 提供 Flask；backend/app/__init__.py 组装业务服务和路由。前端 Vue 3 + Vite，Flask 提供 frontend/dist，开发时 Vite 代理 /desktop/api。没有独立的前端生产服务。

## 模块协作

| 模块 | 职责 | 核心源码 |
| --- | --- | --- |
| workbench | 账号、工作台状态、文件、普通聊天 | backend/app/modules/workbench/ |
| agent_platform | 应用定义、规划、确认、运行、产物及保存 | backend/app/modules/agent_platform/ |
| financial_data | 登录鉴权后代理本机数据库接口 | backend/app/modules/financial_data/ |
| news | 按需抓取、规范化、缓存财经快讯 | backend/app/modules/news/ |
| 独立数据服务 | SQLite 查询与受保护 CRUD | cd80-data-api/app/ |
| capability_library | 个人能力资产、导入导出、验证、准入、MCP和对话调用 | backend/app/modules/capability_library/ |
| sub_agent | 主对话消息队列、动态委派、工件、审批与主agent验收 | backend/app/modules/sub_agent/ |
| evolution | 研究应用、成功方法/代码沉淀、应用发布与复制 | backend/app/modules/evolution/ |

普通聊天：useWorkbench.js → /chat → workbench/service.py → graph_runtime.py → 模型流 → SSE。
应用：useAgentPlatform.js → agent_platform/routes.py → service.py → planner/contracts → 预览和确认 → executor → repository/产物。
金融数据：FinancialDataPanel.vue → financialDataApi.js → Flask 登录代理 → FastAPI → SQLite。
新闻：newsApi.js → Flask news/routes → service → 独立抓取进程 → AkShare。

应用编排由固定业务状态逻辑控制；普通聊天使用 LangGraph。应用前端约 2.5 秒轮询，运行 SSE 已有接口但不能假定页面已采用。

研究应用：RecipeLibraryPanel → evolution/recipes → 检查新参数、精确能力与本次文件 → sub_agent消息协调器重新执行。固定应用包导入走agent_platform，研究应用包导入走evolution；两者保存均不触发执行。社区组件复制依赖在能力库单库事务完成，应用发布快照保存在evolution；跨库操作通过稳定请求标识防止重放，不宣称分布式事务。

## 边界与部署限制

主站校验 Host/Origin，账号 Cookie 鉴权，业务方法继续校验资源所有者。财务数据为共享比赛库，写入需要管理密钥和用户 ID 白名单；只隐藏前端按钮不形成权限。

应用确认、执行、保存是独立动作，预览不执行业务；隔离执行及状态详见 [应用规范](agent-platform/技术规范.md)。状态观察不能触发执行。进程重启不自动续跑。

多种存储并存，见 [存储说明](存储与数据生命周期.md)。用户 JSON 状态使用进程内锁，不是多进程分布式锁；当前没有高并发、多实例和公网部署验收。

## 第一版能力库接入

CapabilityLibraryPanel → capabilityApi → /desktop/api/capabilities → CapabilityLibrary生命周期/准入 → WASI、内置只读适配或受审MCP。兼容工作台聊天经prepare_chat建立版本/配置锁，由ChatCapabilities适配后进入GraphRuntime，沿用主站持久化与SSE；chat_events用于能力库Skill测试。个人能力不注入旧全局注册表。


## 主对话子任务（2026-10-13）

工作台消息可进入独立sub_agent后台协调器：主agent委派/批准/验收，子agent逐步调用能力或WASI临时代码；SQLite持久化队列、事件及工件BLOB。前端轮询与执行生命周期分离。旧应用仍为独立流程，入口互斥避免同对话同时运行。实现边界见 [技术规范](sub-agent/技术规范.md)。


## 统一可复用资产增量（2026-10-14）

`AssetAuthoringPanel/useAssetApps` → `agent_platform/asset_routes` → `asset_apps` 协调不可变顺序定义、版本、验证、运行和恢复 → `asset_store` 写入平台 SQLite 增量表。固定代码走既有 WASI；Tool 通过 `capability_library/components` 固定完整快照执行；Skill 通过 `sub_agent/skill_runtime` 在单节点内动态调用其工具和脚本，一次交付后才进入下一节点。`asset_creator/asset_legacy` 从实际执行证据或旧完整流程整理可审阅草稿，新创作不会继承历史验证状态。

新 App 入口统一方法与代码详情，旧 recipe/pipeline 保留并提供明确升级路径。标准 Skill 文件、平台绑定、验证启用和运行结果分别管理。设计、接口和实际验收见[可复用资产入口](asset-authoring/README.md)。
