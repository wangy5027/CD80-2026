# 存储与数据生命周期

状态：2026-10-13 现状整理。包含第一版能力库的存储落点；未检查私人数据库内容，未执行迁移。

## 个人数据文件与任务快照（2026-10-15）

数据管理的私人上传复用 `users/<用户ID>/files/<文件ID>` 存放完整原始字节，并在该账号 `state.json` 的 `files` 中保存 `source=data_management`、SHA-256、有界 `dataInfo` 及文件身份；不进入官方 Tushare SQLite 目录，也不形成第二套个人文件池。只允许 CSV、TSV、JSON、XLSX，单文件不得超过 10 MiB。主问答和其他入口只通过用户本次选中的 fileId 取得授权，不因账号曾上传而自动附带文件；模型仅接收重新核对当前字节和格式后生成的有界预览。

子任务第一次处理本次附件时，会把数据文件完整字节复制到账号限定的 `sub-agent.sqlite3` 工件 BLOB，单数据输入最多 10 MiB，每任务工件合计最多 32 MiB；普通附件及输出仍分别按现有 4 MiB 单件限制。获准 Tool/Skill 的直接 `file_grants` 从当前账号原文件读取，数据管理文件单件最多 10 MiB，普通文件仍为 2 MiB，并核对 `inputFiles` 权限、owner 及实际字节 SHA-256。隔离执行器总输入 16 MiB 预算不变。输入工件后续读取也核对同账号、同对话和摘要。长展示名的扩展名由已校验格式恢复。

删除原文件移除该账号文件元信息和原始字节，之后不能再以旧 fileId 发起新授权或重建预览；已创建的历史子任务工件、运行结果和消息不会级联删除，同账号仍可能经原任务权限查看或下载已保存快照。能力调用当前持有的授权字节也不会被事后删除自动撤回。两处字节可能同时占用空间，目前没有自动保留期或跨存储清理；完整备份须包含该账号文件目录及 `sub-agent.sqlite3`。精确接口和产品边界见[个人数据文件规范](financial-data/个人数据文件.md)、[子任务技术规范](sub-agent/技术规范.md#2026-10-15-个人数据文件输入当前实现)、[能力库技术规范](capability-library/技术规范.md#2026-10-15-个人数据文件授权当前实现)及[复用文件池决定](decisions/2026-10-15-个人数据复用文件池.md)。

## 数据地图

主站路径相对于 DATA_DIR（默认项目 data/）；配置的相对路径以项目根目录解释。

| 位置 | 内容与维护者 |
| --- | --- |
| auth.sqlite3 | users、sessions、legacy_claims；LocalAuth 管理账号及会话 |
| users/<用户ID>/state.json | 任务、消息、项目、日程、文件元信息及 bindings |
| users/<用户ID>/files/<文件ID> | 用户上传原始字节 |
| graph-checkpoints.sqlite3 | 普通聊天按账号和任务隔离的检查点 |
| agent-platform.sqlite3 | runs、events、agents、requests、agent_metadata；元数据保留改编及发布来源 |
| sub-agent.sqlite3 | 主对话队列、任务、请求幂等、事件及工件BLOB；详见 [子任务技术规范](sub-agent/技术规范.md) |
| evolution.sqlite3 | 研究应用、运行关联、应用分享快照与幂等请求；独立SQLite，首次启动创建 |
| capability-library/capabilities.sqlite3 | capability_records逻辑资源与capability_blobs原件/产物，同库事务 |
| agent-artifacts/<产物ID> | 输出文件，元数据在运行记录内 |
| 项目 data/agent-runtime/ | 隔离运行时和机器相关缓存；与 DATA_DIR 可独立配置 |
| cd80-data-api/data/cd80.sqlite3 | 独立共享金融库；路径由 CD80_DB_PATH 控制 |

上传文件名和磁盘 ID 分离。应用定义内联保存在运行/个人版本中，不是每个应用一个源码目录。私人文件授权和所有权校验不能由显示名称代替。

## 写入和一致性

state.json 使用逐用户进程内 RLock、同目录临时文件、fsync 与原子替换；运行时内存缓存不会自动吸收外部编辑。不支持直接编辑在线状态文件作为正常管理方法。

账号、检查点、应用记录和用户文件之间没有统一事务。不能只备份其中一个数据库就宣称完整恢复。SQLite 的 WAL/SHM 属运行状态，在线备份应使用 SQLite 备份接口；不能只复制正在写入的主库文件。

金融库保留 source_rows，row_count 由触发器维护；业务写入和审计同事务提交。字段、类型、源数据口径见 [数据契约](../cd80-data-api/docs/CONTRACT.md)。

## 删除行为

| 操作 | 当前实际行为 |
| --- | --- |
| 删除项目 | 删除项目记录，清空关联任务/文件的 projectId；不删除内容 |
| 删除普通任务 | 活动普通聊天或子任务队列拒绝删除；删除工作台任务和检查点，不级联应用运行及产物 |
| 删除上传文件 | 删除字节及元数据，失败保留记录；历史引用不自动清除 |
| 删除日程 | 删除该记录 |
| 取消应用运行 | 改变运行状态，不等于删除 |
| 应用定义、运行、产物 | 当前无公开 DELETE 接口，不承诺自动清理 |

因此 UI 删除不一定等于彻底删除所有关联数据。没有统一保留期或垃圾回收策略；新增清理功能需单独设计和验收。

## 重启与恢复

加载旧工作台状态时，遗留 running 聊天转为 stopped。应用仓库将 generating/running/queued/cancelling 转 interrupted，错误码 process_restarted，不重跑；等待输入、确认和授权的状态保留。

备份与恢复步骤见 [运行维护](运行维护.md)。完整跨存储恢复演练尚未验证；更换机器需重新准备运行时缓存。能力库记录与工作台 capabilityLocks / capabilityRevision 一起纳入一致性考虑；DPAPI密文迁移至其他机器或操作系统账号后需重新配置。所有数据均未在本次文档同步中改动。

## 能力库生命周期补充

2026-10-14：社区组件发布快照、复制请求和来源关系保存在能力库记录表，应用发布/研究应用在evolution.sqlite3。撤回阻止新的获取和复制，已复制的个人资产保留。新增数据库也必须纳入完整备份；本轮没有宣称跨库恢复演练通过。

Store启动时将job/invocation/verification/trial的queued、running、cancelling改为interrupted，不重放远端请求。逻辑资源按owner/kind/id限定，原件与产物保存在BLOB表；旧草案的独立表和磁盘版本树未采用。未保存草稿可删除；资产通过禁用、归档、恢复控制，不等同于删除所有历史版本。详细范围见 [技术规范](capability-library/技术规范.md)。

## 子任务生命周期补充（2026-10-13）

新库首次启动自动创建，不改旧库。活动子任务重启转interrupted，相关队列暂停，queued消息保留；不自动重放。取消只变更状态，任务/工件/幂等记录暂不自动过期；工作台会话删除不级联新库。在线备份需使用SQLite备份接口，回退代码保留新库，跨工作台JSON与新库恢复演练尚未覆盖。详见 [子任务技术规范](sub-agent/技术规范.md)。


## 统一 App 增量（2026-10-14）

`agent-platform.sqlite3` 新增 `asset_apps`、`asset_versions`、`asset_runs`、`asset_artifacts`、`asset_requests` 五表和索引，启动时幂等创建；不转换或覆盖旧 agents/recipes。组件完整字节及依赖快照存于不可变版本，产物实际字节以账号隔离 BLOB 保存；运行固定引用版本、输入摘要和当前执行条件摘要。连接绑定属于本人运行配置，不随导出包传递。

启动恢复把活动 App 标为 interrupted，已完成步骤保留，可能产生外部效果的未完成 Tool/Skill 标记结果未知；用户明确继续时重新核对版本、输入、配置、环境和产物。未完成 Creator 请求转明确失败，不自动再调用模型。具体字段和继续条件见[接口与存储契约](asset-authoring/接口与存储契约.md)。

`python scripts/backup_asset_upgrade.py --data-dir <实际DATA_DIR> --destination <新备份目录>` 通过 SQLite 在线备份接口保存六个主站库，逐库检查并记录摘要，在独立副本上两次打开新增表并核对旧记录不变。此脚本不含用户JSON/上传、独立金融库或配置；不宣称跨库原子备份或全站恢复。回退保留新表和全部数据，旧代码不会识别新 App；如需恢复旧快照，先停服务并另存当前数据，避免丢失升级后写入。
