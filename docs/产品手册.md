# 成都八零产品手册

更新日期：2026-10-13。本文说明产品定位、阶段一能力和验收要求。当前已实现普通对话、应用调用、动态创建、确认执行与个人复用；实际验证范围及结果见阶段验收记录。金融业务应用进入第二阶段。

相关文档：[项目入口](../README.md) · [系统开发手册](开发手册.md) · [开发任务与评估](开发任务.md) · [阶段验收记录](阶段验收记录.md)

## 1. 产品定位

**成都八零 AI 原生金融应用平台：让每个人都能创造自己的金融工具。**

平台面向个人金融研究者、策略创作者、财经学习者和金融应用开发者，帮助用户将金融想法变成可运行、可验证、可迭代、可分享的应用。例如，把策略名称明确成规则并研究历史表现，或将新闻、相关资产与历史事件放在同一界面研究。

用户提出问题、确认规则与假设，并依据证据作判断。平台负责澄清需求、调用能力、生成与运行应用、记录结果并支持复用。产品由共用平台与可调度的应用 agent 组成；预期建设三个创新应用，目前仅明确量化策略方向，覆盖 Python 策略编写、修改和回测。另外两个应用尚未定型，早期提出的信息研究与创作社区只保留为候选方向。

建设重点包括：将表达转成明确规则；复用数据与计算能力；保留来源、参数、版本和运行记录。阶段一先用一个可明确判定对错的 CSV 任务验证通用执行底座，不以完成金融业务或社区作为交付承诺。

## 2. 术语与边界

| 术语 | 产品含义 |
| --- | --- |
| 主 agent | 固定的交互与编排入口，识别意图、澄清需求、选择已有 agent 或生成新的 sub-agent，并向用户报告结果 |
| sub-agent | 接收主 agent 委派、依据明确配置执行任务的对象；阶段一每次只调用一个，内部顺序使用工具 |
| agent 定义 | 描述执行方式的 pipeline、prompt、tools、skills 及必要输入输出约定；不是一个角色名称或提示词下拉项 |
| tool | 可实际调用的能力；可以是平台已注册查询，也可以是生成并隔离执行的 Python tool |
| skill | 供执行过程加载和遵循的任务说明；按需加载并记录；工具无需 Skill 也可以独立工作 |
| 应用 | 用户可理解和调用的一项任务能力，包含 agent 定义、输入说明和结果展示；阶段一采用简单样例验证公共应用契约 |
| 流程预览（dry-run） | 展示步骤、输入、预期输出与工具。它不执行工具、不运行业务、不使用样本或 mock 工具，也不证明验证通过 |
| 实际运行 | 用户授权范围内对真实输入执行工具，并形成真实结果和执行记录 |
| 个人应用 | 用户明确保存供以后调用的 agent/应用定义；保存不等于发布到社区 |
| 复用 | 使用保存的定义处理另一次输入；阶段一须用另一份 CSV 证明复用，而非仅重新打开旧结果 |

本轮新增网页搜索与 13 类南财查询。独立工具无需 Skill 即可调用；Skill 提供可选操作指引。完整支持范围见 [工具与 Skill 接入](工具与Skill接入.md)。

## 3. 当前平台能力

平台已接入以下能力。开发者回归、浏览器交互和真实模型验收分开记录；样例成功不代表任意生成应用都已验证正确。

| 能力 | 当前实现 | 使用边界 |
| --- | --- | --- |
| 账号、聊天、历史任务 | 本地账号、流式回复、历史和项目归属 | 主助手可识别任务；也可显式选择普通对话 |
| 附件与日程 | 文件上传下载、浏览器到期提醒 | 日程不是后台自动运行应用的服务 |
| 原提示词角色 | 通用、编程、视频脚本角色 | 与下方具有执行定义的应用 agent 分开 |
| 主 agent 与 sub-agent | 意图识别、澄清、调用已有应用、生成新定义 | 每次一个 sub-agent，内部顺序执行 |
| 动态生成与预览 | 生成 pipeline、prompt、Python tool、skill；展示定义与参数 | 预览不执行工具，不测试数据；用户确认后运行 |
| 实际运行 | WASI 隔离执行、步骤状态、结果文件、错误日志、停止和授权 | Python 标准库；无联网、pip、递归或自动修复 |
| 应用目录与个人保存 | 内置 CSV 样例、显式保存、版本查询、换文件复用 | 保存独立于执行；下次调用不默认携带旧文件 |
| 金融功能与社区 | 尚未实现 | 量化应用属于下一阶段，另外两个创新应用待定义 |

用户在对话区进入主助手流程，或从侧栏“应用”选择预置及个人应用。流程卡明确区分待确认、待授权、运行、成功、失败、取消和保存，刷新可恢复等待处理的事项。

## 4. 已确认的阶段一决策

1. 由两位同学同步开发：一位建设主 agent 可调度的预置应用，一位建设主 agent 动态生成 sub-agent 的能力。首期预置应用使用简单 CSV 样例，金融量化应用进入下一阶段。建议的工程分工是 A 负责样例、定义注册表、前端及个人应用保存接线，B 负责生成调度、运行确认与隔离执行；这一细分属于开发评估建议。
2. 主 agent 固定承担意图识别和编排，区分普通对话、调用已有应用与创建新应用。
3. 新生成 agent 先展示流程预览，用户确认后才实际运行；预览不进行任何业务执行。
4. 执行结构限定为“主 agent → 一个 sub-agent”；sub-agent 内可顺序调用多个工具。没有递归、并行委派或自动反复修复。
5. 工具或步骤失败时停止后续执行并反馈，保留已完成步骤的信息；不能把部分结果包装成整体成功。
6. 实际结果交付后接收反馈，再询问是否沉淀为个人应用。修改后的执行方案应让用户理解其变化及后续执行范围。
7. 已保存 agent 在参数齐全且请求处于授权范围内时，下次可直接调用；需要新增额外信息必须先取得用户授权，不可因曾保存而扩大使用范围。
8. 首个验收任务是：读取用户 CSV，按指定列分组汇总，产出结果 CSV 和文字说明。动态创建路径中的 Python tool 必须真实运行，skill 必须实际加载；保存后使用另一份文件完成复用。

## 5. 用户流程

### 5.1 普通对话

用户询问概念、解释或进行无需执行任务的交流时，主 agent 直接回复。界面保持现有对话体验，不为每条消息创建应用。若问题转为处理文件或执行计算，主 agent 应先明确输入、目标和必要参数，再进入调用或创建路径。

### 5.2 调用预置或已保存应用

1. 主 agent 判断请求是否匹配已有能力，识别应用和所需参数。
2. 缺少分组列、汇总列或文件等必要输入时，向用户澄清，不自行编造。若涉及新增额外信息，先取得授权。
3. 参数齐全且范围内时调用已有 agent，展示实际运行状态。
4. sub-agent 顺序执行工具，主 agent 汇总结果、提供文件和说明；失败时停止并解释失败位置。

已有应用无需每次重新生成。个人应用的直接调用仍受本次请求和已有授权范围约束。预置样例和动态生成应用必须遵循同一个输入、运行状态、产物和错误约定。

### 5.3 动态创建与首次运行

1. **需求澄清**：确定输入文件、分组列、汇总列、计算方式和期望输出；没有明确的业务规则时先问用户。
2. **生成定义**：主 agent 生成 sub-agent 所需 pipeline、prompt、tools、skills。可生成可执行 Python，也可引用已注册工具；Skill 为可选的任务说明。
3. **流程预览**：展示将要处理的输入、顺序步骤、每步工具与预期输出，清楚标为“尚未执行”。这里不能读取样本进行业务计算、调用 mock 工具或声称结果正确。
4. **用户确认**：用户可修改或取消；只有确认后进入实际运行。确认对象是可见的方案及其范围，不是一个模糊的“同意 AI 自由操作”。
5. **实际运行**：创建运行记录，加载选用的 Skill，调用已确认的注册工具或隔离 Python，展示步骤状态。
6. **结果交付**：提供结果 CSV、汇总说明和可核查的输入/参数/执行信息。失败则报告错误和已有结果，不自动反复修复。
7. **反馈与保存**：用户反馈后，询问是否保存为个人应用；同意才保存，拒绝不影响查看本次结果。

### 5.4 三个动作必须区分

| 动作 | 用户确认什么 | 不代表什么 |
| --- | --- | --- |
| 修改/确认生成方案 | 需求和流程是否符合意图 | 不代表工具已经执行或结果已验证 |
| 开始实际运行 | 使用可见方案、输入和授权范围执行 | 不代表同意永久保存为个人应用 |
| 保存个人应用 | 将该能力保留供后续调用 | 不代表发布社区、立即再运行或扩大数据授权 |

首版使用预览卡上的“确认并运行”按钮完成方案确认与启动。若修改执行范围、参数或规则，则生成新的流程和确认，保留旧运行记录。

### 5.5 反馈与复用

反馈可以是对结果的评价，也可以是修改需求。评价不应自动触发重跑；修改需求应产生明确的待执行变更。保存时让用户知道保存的名称、用途、输入要求和可调整参数。下一次用户上传另一份 CSV 并指定参数，主 agent 可匹配个人应用并直接调用；执行记录应能区分两次输入和结果。

首版保存不可变的应用定义版本，并独立保留各次运行记录；参数表单按定义生成，文件选择初始为空，不把某次私密输入自动作为以后默认数据。详细结构见开发手册。

## 6. 最小界面与状态

| 界面元素 | 必须传达的信息 |
| --- | --- |
| 对话区 | 当前是在交流、澄清需求、调用已有应用还是创建新应用 |
| 流程预览卡 | 输入、步骤、工具、预期输出；“尚未执行”的明确状态；修改、取消、确认运行入口 |
| 运行面板 | 调用的应用/sub-agent、当前步骤、等待/运行中/完成/失败/取消等状态及实际产物 |
| 结果卡 | 结果 CSV 下载、文字说明、输入与参数摘要、错误或不完整项 |
| 保存入口 | 与执行确认分开，明确保存为个人应用及保存结果 |
| 个人应用入口 | 已保存能力、输入要求及再次调用方式 |

建议采用状态：澄清中 → 生成中 → 待确认预览 → 运行中 → 成功/失败/取消 → 等待反馈或保存。已保存应用的范围内调用可以直接进入运行中，不经过重新生成。此状态表是产品展示建议；具体持久化状态和事件协议以开发手册为准。

失败必须说明停止在何处、哪些步骤已完成以及用户可如何继续。取消入口必须真实终止正在执行的工具并停止后续步骤，保留已有结果；取消能力和底层进程中止机制须在任务评估中明确验收，不能沿用“停止聊天”名称便认为已支持。

## 7. 可验收产品需求

| ID | 需求 | 验收观察 |
| --- | --- | --- |
| PR-01 | 区分普通对话、已有应用调用和动态创建 | 对应三个请求分别进入正确路径，普通对话不无故创建应用 |
| PR-02 | 澄清任务必要参数 | 缺少 CSV、分组列或汇总规则时提问；不编造列名和计算规则 |
| PR-03 | 支持预置简单样例应用 | A 的样例通过公共调用契约产生真实输出，主 agent 可调用并展示结果 |
| PR-04 | 动态生成可执行定义 | 能查看 pipeline、prompt、生成的 Python tool 与 skill，关联到本次应用 |
| PR-05 | 流程预览严格不执行 | 展示步骤/输入/预期输出/工具；确认前无实际工具或业务调用，无样本/mock 执行，也无“验证通过”结论 |
| PR-06 | 确认后才进行首次实际运行 | 拒绝或修改时不启动原方案；明确确认后才执行该方案 |
| PR-07 | 生成的 tool 和 skill 真实参与运行 | 执行证据能定位生成 Python tool 的实际调用，以及生成 skill 的实际加载；不能用硬编码替代路径冒充动态执行 |
| PR-08 | 单 sub-agent 顺序执行 | 主 agent 仅委派一个 sub-agent，工具按顺序执行，无递归或并行委派 |
| PR-09 | 失败停止并反馈 | 人为触发一步失败，后续步骤不再执行，界面报告失败点，不自动循环修复 |
| PR-10 | CSV 分组汇总结果正确 | 使用已知输入与明确规则，结果 CSV 的分组和数值符合人工可计算的期望，文字说明与结果一致 |
| PR-11 | 接收反馈并独立询问保存 | 结果交付后可反馈；保存明确征询，未同意不进入个人应用列表 |
| PR-12 | 保存后处理另一份文件 | 选择已保存能力，用不同 CSV 输入完成真实运行，结果随新输入变化且可与原运行区分 |
| PR-13 | 范围内直接复用、额外信息需授权 | 参数完整且范围内无需重新生成；需要新增额外信息时先询问授权，未获授权不擅自使用 |
| PR-14 | 不混淆预览、成功与保存 | UI 能区分预期输出与实际结果、失败与成功、一次运行与个人应用；不得把生成文本当成功执行 |

这些条目是验收标准；对应测试和实际通过记录统一保存在 [阶段验收记录](阶段验收记录.md)，避免将预期能力误当成测试证据。

### 首期联合验收场景

用户上传带有分组列及数值列的 CSV，要求按指定列汇总。先验证预置样例可完成该任务，再验证动态创建路径：澄清规则 → 生成 Python tool 和 skill → 只展示流程预览 → 用户确认 → 实际加载和执行 → 下载 CSV 并核对数值 → 用户反馈 → 明确保存 → 上传另一份 CSV 直接复用。另验证拒绝确认、缺参、执行失败和新增额外信息的授权分支。

汇总函数、空值/非数值、编码和输出顺序等细节应在实现契约中明确；不得把工程默认值写成用户已经确认的业务要求。用于验收的输入和期望结果需事先确定，以便独立核对。

## 8. 阶段一不包含与后续展望

阶段一不以金融行情接入、量化策略回测、自动交易、新闻事件研究、社区发布、多人协作发布、多 sub-agent 并发/递归、自动反复修复或线上部署为验收门槛。现有浏览器日程也不扩展解释为后台自动任务服务。

下一阶段明确的方向是量化策略应用：编写和修改 Python 策略代码、运行历史回测。另两个创新应用仍需单独定义；金融信息研究、带证据的分享复用可作为候选研究方向。所有金融能力的数据来源、验证标准、计算规则与交付计划届时再确认，不作为第一阶段隐含需求。
