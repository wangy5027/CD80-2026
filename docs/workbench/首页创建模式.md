# 首页创建模式

日期：2026-10-15。状态：已实现，测试与服务加载结果见本轮验收。依据：用户要求在主页面对话输入处增加“创建模式”；开启后所发需求必须使用技能池的自然语言 APP 创建逻辑，生成并保存 APP，已有示例需得到同样的功能、接口和保存结果。

## 产品与交互

主页面的首页输入框和已有对话输入框共用“创建模式”开关，默认关闭，选中状态明确可见。开启时说明“生成 APP 并保存到我的 APP，初始为未验证”。发送按钮和回车走同一创建处理，不再先让普通问答判断是否值得创建。关闭后恢复原问答行为；不改变已开始的后台创作。

提交使用完整原始需求及当前明确选择的文件引用，不截断长示例、不改写需求为固定演示模板。使用既有统一创作详情展示进度、必要问题、失败和恢复。成功保存后复用技能池的创建后回池逻辑，刷新并定位本次账号、本次创作生成的 APP；未成功不显示入池成功，不创建占位 APP。保存不执行应用、不验证、不启用，原任务用例随保存版本保留。

当前模式属于账号内的输入行为；切换账号或登出清除模式及未完成的客户端提交关联。提交期间防重复；接受后仅清除与发送快照一致的草稿，保留用户在等待期间的新编辑。结果未知时沿用原幂等提交恢复，不能再次制造相同 APP。所选“运行应用”和旧草稿修改上下文不能把创建发送转回运行或修改。

## 技术契约

复用 `POST /desktop/api/authoring-sessions` 和现有 `useAuthoringSessions`：`kind=app`、`intent=create`、`mode=prepare`、原始 `instruction`；按现有契约传递可用的 `conversationId`、`sourceRefs`。生成和保存共用后端既有标准 `cd80.app/2`、组件快照、原任务用例、预算、版本及幂等规则。已有技能池入口与首页共享提交参数构造，避免两套规则漂移。

APP 保存结果以服务端返回的 `result.assetId/versionId` 为准。`awaiting_input` 通过既有回答接口继续同一会话；失败与未知提交通过现有恢复方式处理。按钮仅新增前端入口，不更改后端 APP 准入和验证门槛。统一错误文案、已验证才能启用、账号隔离保持。

## 验收

- 默认关闭、可切换，首页和已有会话均可发送；创建模式禁止误调用普通问答、运行旧应用或自动选择 Skill/Tool 类型。
- 技能池与首页构建相同创建参数；用户之前交付的创建示例逐一识别并验证，按功能/接口/原用例结果核对，不要求模型源码逐字一致。
- 成功保存未验证/未启用、原例存在、创建时无执行；补充回答、异常恢复、提交去重和账号切换不破坏已有流程。
- 桌面与手机浏览器实际检查；相关自动化与构建后重启正式服务，并核对健康和实时资源。隔离模型与真实模型证据分别记录，不使用正式账号作为写入测试对象。


## 实施细节与证据

首页与技能池通过 `authoringCreateRequest.js` 构造同一请求；APP 创建固定 `app/create/prepare`。当前 Composer 的 Skill、Tool 和运行 APP 选择是普通问答上下文，创建模式下隐藏且保留，所需能力由需求原文描述。文件引用复用既有来源授权与元数据语义，不承诺在创建时自动解析整个附件。

页面用账号隔离的 `sessionStorage` 保留开关、创作 ID 与未知提交快照；刷新能恢复，登出/换账号清理旧关联。开始新任务保留当前模式、解除上一任务关联。等待必要问题时向同一会话回答，不另建 APP。提交草稿按账号、上下文和发送快照有条件清理；迟到响应受账号与请求序号约束。明确的 HTTP 拒绝会保留可编辑需求；仅结果未知时保留原请求进行幂等恢复。界面错误沿用“当前网络连接失败”。

产品代码只调整前端入口与统一创作控制器，不增加后端接口、模型专用模板或数据库迁移。自动化、浏览器与加载记录见本轮总验收（本地资料，未随源码发布），两份旧 Prompt 的真实 GLM 与 WASI 证据见真实示例验收（本地资料，未随源码发布）。
