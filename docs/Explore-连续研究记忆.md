# Explore 连续研究记忆

每条研究链有一份当前记忆和可追溯的历史版本。完成“理解事件”的第一步解释后生成 v1；选择“进一步解释”后，在同一次运行中依据 v1 生成 v2。随后点击“发现关联”时，新运行冻结 v2 作为输入；报告保存后生成 v3。“历史验证”以同样方式取得 v3，保存报告后生成 v4。独立开始的问题创建另一条链。

```text
理解事件初答 ── v1 ── 进一步解释 ── v2 ── 发现关联 ── v3 ── 历史验证 ── v4
                               └── 每次请求 GLM 时直接带入本轮冻结的记忆正文
```

## 保存与更新

记忆版本存于 `DATA_DIR/explore.sqlite3` 的 `research_memories` 表。每版记录 `id`、`parent_id`、`chain_id`、`version`、`run_id`、阶段、Markdown 正文、正文 SHA-256、结构化状态，以及它依赖的文件编号和内容指纹。版本创建与回答或报告的发布处于同一数据库事务；失败、取消或尚未完成的运行不会发布新版本。旧版本不原地改写。

摘要由后端从**已保存**的初答或报告确定性生成：保留研究目标、用户澄清、最近阶段的问题、回答、关键发现、不确定性、来源编号与链接。最近保留最多 5 个阶段，更早阶段压成短进展；最终 Markdown 上限 10,000 字符。它是接续研究的背景，不将旧 AI 推断升级为本轮证据。精确事实仍应回查原材料。

`run.memory_input` 是创建新运行时冻结的父版本，`run.memory_output` 是当前运行最新发布的版本。同一事件运行从第一步进入深入解释时，深入解释会读取该运行刚发布的第一步版本。来自报告的追问继承该报告所属运行的最新版本；只有第一步解释而没有正式报告时，可用 `source_run_id` 接续。重试沿用原运行冻结的父版本。

## 模型输入

后端在每次模型请求的**第一条 user JSON 消息**中设置 `research_memory`：新链首次调用为 `null`，后续为含版本编号、正文和正文指纹的对象。理解事件的深入解释、发现关联的实体选择及报告、历史验证的研究循环和写作都使用同一轮冻结版本。服务端在发送前校验版本及依赖文件，并记录 `model_memory_trace` 中的版本、指纹、字符数和阶段；该追踪记录不重复存放正文。

删除记忆依赖的文件后，后续请求在发送旧记忆给模型之前失败，要求用户重新选择研究起点。界面的旧文件手动选择是另一种上下文控制；选择空文件列表不清除当前研究链的记忆。

## 查看与下载

研究正文和输入区不展示记忆管理信息。当前记忆、历史版本切换和下载只在会话文件池中展示；后台始终自动传入并更新，不要求用户手动选择。

- `GET /desktop/api/explore/sessions/<session_id>/memory?run_id=<run_id>`：按该运行的父子链顺序返回 `latest` 与 `memories`。不传 `run_id` 时返回会话中的全部版本。
- `GET /desktop/api/explore/sessions/<session_id>/memory/<memory_id>`：读取指定历史版本。
- `GET /desktop/api/explore/sessions/<session_id>/memory/<memory_id>/download`：下载该版 Markdown。

这些接口只读取已保存的内容，不调用模型；均校验当前用户对会话与版本的访问权。

## 本地验证

在本项目目录运行：

```bash
.venv/bin/python -m unittest tests.test_explore_memory_chain -v
```

该测试使用临时 SQLite、本地检索与网页工具替身、模拟 GLM。它通过真实后端接口运行“理解事件 → 发现关联 → 历史验证”，检查**实际发送到模拟模型的消息正文**包含正确版本，同时检查历史版本、独立研究链、失败/取消、重试和删除依赖文件的行为。不会发起真实网络请求，也不会产生模型费用。
