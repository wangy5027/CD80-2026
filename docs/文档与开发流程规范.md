# 文档与开发流程规范

状态：已确认，自 2026-10-13 起适用于后续开发。依据：用户逐项确认。临时保护只适用于对应任务；能力库开发完成后已按用户授权同步文档，历史记录仍保留。

## 先设计再实现

新功能先建立 docs/<模块名>/，完成产品设计与技术规范，明确用户、场景、范围、不包含项、输入输出、权限、异常与验收条件，再进入实现。已有功能小修复更新所属模块文档，不机械地新建整套文件。需求未决时写出待决项，不把假设写成已经确认的需求。

目录名称使用稳定的小写英文名，文档正文使用中文。模块拆分、合并或接口兼容性变化时同步修改规范和链接。

## 模块标准结构

| 路径 | 必须包含 |
| --- | --- |
| README.md | 模块职责、源码位置、文档导航、依赖及范围 |
| 产品设计.md | 用户需求、流程、范围、错误体验、可验收条件 |
| 技术规范.md | 架构、接口与存储、权限、状态、边界、源码依据 |
| 开发进度.md | 更新日期、负责人/待分配、任务、实现状态、验证状态、阻塞及下一步 |
| 验收记录/ | 按日期和事项保留证据；没有新验收时仅提供说明，不伪造报告 |

接口体量大时拆出 API、Schema 等文件，并从技术规范链接，字段只维护一个权威来源。运行时代码读取的示例、Schema、SKILL.md 不属于可随意迁移的说明文档；位置变更必须作为独立实现任务评估，不在纯文档整理中操作。回溯当前代码补的文档必须写“现状整理”，不伪装为开发前设计。

## 进度同步

每次更新模块进度，同一次交付同步 docs/项目状态.md 的对应行、日期、阻塞与证据链接。总状态不复制完整任务清单，模块进度负责详细事实。

状态分别记录：
- 实现：未开始 / 设计中 / 开发中 / 已实现 / 阻塞。
- 验证：未验证 / 部分验证 / 通过 / 未通过。
- 真实上游：未验证 / 已验证（需环境和时间）；本地替身通过不能替代真实调用结论。

不能只用“已完成”掩盖未验证项。负责人未知写“待分配”，不擅自指定人员。没有自动同步系统；当前由每次变更的提交者人工同步并复查。

## 文档变更与验收

设计改变先更新规范；代码完成后更新模块进度、总状态和 CHANGELOG。重要跨模块决定使用 decisions 记录。测试结果按验收模板保存，代码版本用实际提交或明确工作区快照；保留失败、跳过和限制。已知问题闭环需链接修复与验证，不仅引用实现文件。

当前规范、未来设计、历史记录必须有明确状态和日期。冲突时先区分版本与环境：当前行为核对代码和当前环境；目标需求核对已确认设计；历史验收仅证明记录时的范围。发现规范与代码不一致时登记问题，不能静默改写需求。

## 文件与归档

使用 UTF-8，链接用仓库内相对路径；正常文档不写个人机器绝对路径、私人账号或密钥。示例用占位符。修改前检查并行变化，文件移动同步修复允许修改的引用。

历史材料归入 docs/archive/<日期>-<事项>/，正文和证据保留原样，以旁置 README 解释环境、来源、过时入口和未完成核验。历史报告中的断链记录而不篡改原证据；导航提供可用的新入口。

涉及其他任务保护范围时，不移动、不修改、不覆盖、不新增。共享文档只改允许的独立段落；无法分离则暂缓并登记。不能通过复制受保护材料到新位置绕过保护。
