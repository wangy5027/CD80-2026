# 统一对话创作与使用

状态：2026-10-14（Asia/Shanghai）已正式定稿，新增业务实现未开始。依据：用户在grilling中依次确认Q1–Q4、Q5–Q9、Q10–Q14，审阅整合稿后明确回复“可以，定稿”。产品权威为[产品设计](../asset-authoring/产品设计.md)，机器契约以[接口与存储契约](../asset-authoring/接口与存储契约.md)为准。

## 背景

已有App、Tool、Skill具备完整实现、版本、保存、验证和运行能力，但主对话、旧应用、统一App及能力库组织流程不同。聊天文字生成与实际执行沉淀分离，用户需要切换页面、拼接上下文和填写测试预期。2026-10-14 14:31保存流程修复已交付，本决定在该基线上统一完整创作和使用流程，不能与按钮修复的已完成状态混淆。

## 已确认选择

1. 所有个人资产入口进入持久创作会话。创建、沉淀和修改默认整理实现、资源、依赖和用例，在授权范围内验证并有限修复；明确只保存时不执行。三类资产保持不同的执行语义。
2. 系统自动组装本会话和明确关联的历史、文件及实际执行依据。历史不完整时允许推断范围或生成新内容，标记来源并重新验证；重要业务歧义才询问，原历史不改写。
3. 最后一次审阅可以保存并启用相同候选内容。后台保存、验证、启用状态继续独立，不要求用户逐步点击；客观失败不能被人工确认覆盖。准备失败保留草稿及下一步。
4. 普通请求主动复用适合且已启用的个人资产，显示真实版本；强制指定不可用时不静默替代。正常运行不能自动重写固定实现，行为修改形成候选和新版本。
5. 每轮创作统一600秒有效时间、32次实际模型请求、2轮自动修复。重试和嵌套调用共同计量，第33次请求及第3轮修复启动前拒绝；已获准工作仍受剩余时间约束。恢复不加额，明确追加额度幂等记账，刷新及追加要求不重置。
6. 默认仅在授权数据、只读上游和隔离环境中测试，外部业务写入用隔离或可验证模拟；真实与模拟证据分开。模型费用未具备准确汇总条件，不能承诺金额上限。
7. 纯展示元信息静态检查，发现/选择变化验证匹配，执行行为变化重新验证。处理中可追加同一草稿要求，停止过时检查并拒绝旧回调覆盖。
8. 主对话资产卡与统一详情承载编辑、结果和审阅；高级实现默认收起，手机全屏。默认只增加用户要求的可见资产，内部依赖完整保留，明确提取才新增独立组件。

本轮14项逐项映射见[产品设计的CA-Q决策](../asset-authoring/产品设计.md#决策追踪与验收)，完整审阅稿留在[原稿存档](../asset-authoring/统一对话创作修订草案.md)，该存档不再作为长期平行规范。

## 与既有决定的关系

[0006 可复用资产与统一应用](0006-可复用资产与统一应用.md)的三类资产语义、完整实现、标准Skill、快照、固定规则、版本和执行隔离继续有效。下列交互和整理规则按本决定修订，历史决定及验收保留原意：

| 原规定 | 本轮规则 |
| --- | --- |
| 验证需要另一个明确按钮，保存与启用逐步操作 | 创作请求包含默认验证授权，最后一次审阅可保存启用；纯保存仍不执行，后台状态继续分离 |
| 缺少采用关联时由用户明确选步骤 | 系统推荐整理范围并标来源，重要歧义才问；高级明确选步保留 |
| 主对话明确应用意图交给原应用流程 | 新统一创作目标接入协调层，旧资产运行按兼容适配保留 |
| 不能自动修改能力 | 普通执行继续遵守；明确创作期间允许候选技术修复，不改用户指定业务规则 |
| 双用例和准入门槛已具备，用户填写及组织 | 保留双例与客观检查，系统自动生成有独立依据的用例和准备输入 |
| 各执行模块拥有局部预算 | 创作场景在保留更严格局部限制的同时共享总预算，普通运行不冒称已接新预算 |

[0005](0005-可移植资产与研究应用.md)继续解释旧包与发布行为。本轮不改社区发布规则，也不自动批量迁移已有资产。

## 取舍依据

只统一按钮无法解决上下文、证据和测试准备的分裂。将每个内部步骤都保存为个人组件会使资产库堆积；本轮保留内部完整快照，仅新增用户要求的对象。取消验证门槛不能证明资产可靠；本轮把准备工作交给系统，继续客观检查并让用户审阅实际效果。

候选先测再正式提交可以减少无意义的正式版本，必须由平台证明最终内容与受测内容一致。自动修复限于候选，不把普通运行扩展为自动修改生产资产。上下文推断用于生成新草稿，不能代替真实历史事实。
