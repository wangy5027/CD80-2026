# 0008 APP 统一先保存与标准创建入口

日期：2026-10-15。状态：用户需求已确认，接口包装细节由工程实施确定；实现和验收以模块进度为准。

用户要求全部 APP 创建先入应用池、显示未验证，后续在保存版本上修改和验证；明确包含策略工坊新增策略。官方和其他用户主动公开的 Skills/Tools 免个人重复验证；私人上传、生成及修改版本继续验证。用户随后将技能池 APP 创建限定为外部导入和自然语言两种入口，并要求提供外部开发规范、示例与数据接口文件。

继续使用 `cd80.app/2` 作为现代 APP 的唯一运行定义，不把上传原件、创作会话或模型一句说明冒充完整 APP。外部 Python/源码 ZIP 只是运输适配，解析后必须落到同一输入、节点、组件、资源、输出和版本结构；不在导入时执行实现。自然语言使用已有持久创作会话，完整定义形成后保存，不自动准备双例测试。空白或缺实现的请求保留会话并询问，不产生空占位应用。

来源信任按服务端精确内容授权，不能由用户包自称官方获得；可信能力的免验证不授予新权限，也不让新组合 APP 自动获得验证状态。历史版本与运行保持可读，编辑保留新版本，正式启用只针对已验证的准确版本。

本决定修订 [0007](0007-统一对话创作与使用.md) 中 APP 自动验证后最终保存启用的顺序，旧记录保留为历史；不废除 Skill/Tool 的对应创作流程或既有运行隔离边界。技术细节见[创建入口](../integration/APP两种创建入口.md)、[保存与追踪](../integration/应用保存与执行追踪规范.md)、[接口与提示词](../integration/APP接口与提示词存储.md)及[能力来源免验证](../integration/SkillsTools免验证规范.md)。
