# 主对话子 agent 执行

状态：业务选择已确认，第一版已实现并完成确定性验收。日期：2026-10-13（Asia/Shanghai）。依据：本次用户逐项回答及对最终需求汇总明确确认；详见 [产品设计](../sub-agent/产品设计.md)。替代记录：无，不废止既有应用平台或能力库规则。

## 背景

主对话已有多轮工具调用；应用平台已有固定顺序pipeline与隔离执行。复杂临时任务仍缺独立上下文、任务专属代码申请、可靠中间工件传递、有限纠错和主 agent 验收。

## 决定

- 主 agent 定目标、交付和验收；子 agent 自主安排顺序步骤，不固定股票分析指标或图表。
- 每个复杂任务单个子 agent，不递归、不并行创建子 agent。
- 优先使用主 agent 指定的能力；非强制能力不足时申请主 agent 批准临时代码，用户强制约束不可绕过。
- 中间数据通过真实引用传递；临时代码只在隔离环境执行，成果不自动沉淀为应用或能力。
- ReAct纠错全任务最多3次，包括主 agent 验收退回；不得通过重委派重置。
- 同一对话串行，运行中新输入排队；用户中断暂停队列，必要回答走专用入口。
- 后台执行独立于页面连接；进程重启标记中断、不自动重放。

## 已讨论的替代选择

仅依靠现有工具串联无法覆盖临时代码及可靠工件传递，故新增任务执行边界。将固定股票分析方案写入框架被用户纠正，具体交付由主 agent、需求及能力共同决定。运行期间允许继续交流的建议被用户否决，改为只中断或排队。

## 影响

工作台需要统一调度与队列；能力库需要任务授权下的调用适配但不放宽准入；底层执行器需支持任务工件及可行的图表输出；存储需要持久任务和事件。已有应用创建、确认、保存仍独立，不能把新子任务视为已经保存的应用。

已确认业务规则不能因实现方便而静默改变。当前实现、迁移回退与剩余边界见 [技术规范](../sub-agent/技术规范.md)。第一版新增独立SQLite（含工件BLOB）和后台队列，旧应用生命周期不迁入队列；真实模型尚未验收。

## 2026-10-13 分流修订

用户确认以任务步骤依赖及是否需根据实际结果继续处理作为委派标准；单次明确操作可由主agent执行，发现复杂性后同任务升级。普通主对话不再先走应用分类器，只有明确应用意图交给应用流程。Tool/Skill/应用的沉淀仍须另行提出。见 [设计](../sub-agent/分流与会话体验修订.md)。
