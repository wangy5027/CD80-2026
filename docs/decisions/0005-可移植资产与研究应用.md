# 可移植资产与研究应用

状态：2026-10-14本轮实施决定。来源为用户要求完善调用、导出、引入、保存与发布的整体授权；工程取舍由本轮提出，不冒称用户逐条确认。原始SWUFE愿景Markdown已于后续审计找到并读取全文，C01–C05及体验/能力的对应见[原文核对](../vision-delivery/原始愿景逐项核对.md)。

固定流程应用与研究应用并存。固定流程保存可审阅的顺序步骤；研究应用保存目标模板、参数、约束和精确能力引用，再由主/子agent执行。研究应用运行上下文由服务端设置，防止被误分流为再次创建应用，不增加任何权限。

导出/发布使用可移植定义、必要源码及内容摘要，不复制账号ID、原文件授权、连接密钥、历史结果与验证。接收者建立独立资产，重新绑定精确依赖、配置、测试和启用；多副本不按名称静默选择。已复制资产不跟随发布者更新或撤回被删除。

相同源码的两个组件副本仍可能承载不同配置与精确Tool依赖，来源摘要不能代替组件位置。研究包以独立bindingId保留槽位；固定流程按类型和组件id分别绑定。缺少槽位的旧重复来源包明确拒绝并提示重新导出，不静默丢失合法组件。

成功执行、保存资产、验证启用、发布共享是分开的动作。完整共享源码先按快照预览，再确认发布；内容超过512文件或4MiB不能仅展示截断文本后允许确认。共享范围限同一平台实例账号，不等于公网部署。

沿用各模块SQLite存储；组件与依赖复制在能力库单库事务内，跨模块行为使用稳定请求标识和可重放结果，不能声称跨库分布式事务。设计与证据见[愿景模块](../vision-delivery/README.md)、[接口](../vision-delivery/研究应用与发布接口.md)及集成验收（本地资料，未随源码发布）。
