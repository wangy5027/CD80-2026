# 0002 本地金融可插拔能力

状态：已确认并于同日第二轮需求确认后实施。日期：2026-10-13。

## 背景与依据

用户在本次需求对接 Q6 修正早期接入方案：金融功能应是可插拔公共 Skills/Tools，而非平台业务代码；Q13—Q15 确认通用受控连接、以前置支持作为启用门槛及本平台包规范的可移植范围。最终确认稿已接受并授权文档落地。

## 已确认选择

金融逻辑保存在能力包，平台只提供通用执行与连接授权。包通过接口访问本地数据服务，不直接导入现有业务代码或读取宿主数据库。结构化金融数据不回退南财；首批 AkShare 新闻通过现有本地接口联网获取，是明确例外。

公共包复制到个人库后独立管理，沿用验证、启用、精确依赖和版本锁定。普通数据更新与能力变更区别处理；不建设完整数据快照系统。

## 考虑过的方案

- 将金融查询注册为平台 builtin：不采用，金融逻辑会成为业务代码，违背用户修正后的边界。
- 原南财脚本改地址后直接导入：不采用，当前 WASI 无网络/宿主数据库访问，第三方依赖也不自动具备。
- 通过通用受控连接执行 Tool 包：采用；本轮以python_connector分轮请求协议落实，WASI不开放网络。

## 影响

能力池需要单独实现并验收通用执行支持。未就绪时能力包可独立开发测试，但不能正式启用，不以金融 builtin 作为临时替代交付。首批只对话表格，文件及图片产物后续设计。

最初仅作为设计输入；用户随后授权实现，现已同步能力池Schema及接口，见本地金融执行协议。替代早期迁移规划中公共适配层/内置 handler 的接入设想，不废止现有能力池运行行为。
