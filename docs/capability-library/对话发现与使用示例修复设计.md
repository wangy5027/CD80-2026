# 对话发现与使用示例修复设计

后续范围补充：用户已确认自动发现、输入框「+」选择及 Application 等五项业务决策，统一见 [更新方案](主对话扩展接入与使用体验更新方案.md)。本页保留问题定位及原方案依据；已确认规则以上述更新方案为准，技术建议不自动视为已批准。

## 问题与依据

用户反馈：扩展缺少清楚的使用示例；在主对话要求“使用文本总结 skill，总结提供的《红楼梦》片段；找不到就直接回答找不到”，助手称只能找到财经内置技能，随后仍自行总结。

| 问题 | 静态核对结果 | 影响 |
| --- | --- | --- |
| CAP-02 使用示例不完整 | CapabilityLibraryPanel.vue 的 detail() 按参数类型生成空值；数组为 []，expectedText 初值为 {}，Skill 的 prompt 初值为空。详情没有完整使用示例区 | 用户不清楚输入、预期结果、验证和用于对话的区别 |
| CAP-03 主对话缺少个人能力自动发现 | workbench/service.py 仅在请求包含非空 capabilityRefs 时调用 prepare_chat，且仅 selectedCapabilities 非空时进入 capability_library.chat_events；否则走原 runtime.stream。graph_runtime.py 的目录来自旧 SkillRegistry | 用自然语言指名扩展不会自动把它接入本轮；与产品设计“未指定时按需选择已启用个人能力”不符 |
| CAP-04 缺失能力时未遵守停止条件 | 用户提供的真实回复在声称找不到后继续总结；本轮未重放该会话 | 不能把模型自行完成任务当作 Skill 已使用，也不能忽略用户的条件式停止要求 |

源码依据：[工作台协调](../../backend/app/modules/workbench/service.py)、[原对话运行器](../../backend/app/modules/workbench/graph_runtime.py)、[能力执行](../../backend/app/modules/capability_library/service.py)、[扩展详情](../../frontend/src/modules/workbench/components/CapabilityLibraryPanel.vue)、[发送入口](../../frontend/src/modules/workbench/useWorkbench.js)。

公共样例清单的真实名称是“资料摘要方法”，来源 org.example/summary-skill；Skill 正文内部名称为 summary-skill，英文描述提到 financial notes。用户所说“文本总结”不能直接当作准确资产名称。本轮未读取用户个人能力数据库，不能确定其副本名称、验证和启用状态，也不能断言其测试当时属于哪个状态。目录接入缺口是代码事实，具体会话状态仍待隔离环境复现。

前端平台模式还会先请求 agent-dispatch，由其分类决定是否回到聊天；本轮没有证据证明该分类器在用户这一次请求中误分流。修复需覆盖此入口，不能只测直连聊天接口。

## 使用示例的目标体验

公共能力与个人能力的详情均展示“如何使用”，位于原件与完整清单之前，无需阅读代码。包含用途、前置条件、可复制的对话示例、输入解释、预期输出或判定标准、失败后的下一步。示例绑定具体版本，明确来自包作者、平台维护还是仅按参数规范生成的输入模板。

Tool 提供完整的样例输入和预期输出；“填入验证示例”只填写表单，不发起调用。Skill 提供完整资料、测试提问和人工验收标准；不将生成式文本当作必须逐字一致的结果。“用于对话”展示已选能力标签并保留用户已有草稿，不自动发送。未验证或未启用时说明具体操作，不用一个灰按钮代替解释。

自定义能力没有作者样例时明确显示“尚无经过确认的使用示例”。可根据 Schema 展示字段名称、类型、必填项、说明和默认值，但不得把空数组或猜测结果标记为有效业务示例。未知 Tool 不能编造预期输出。敏感凭据、私人附件及用户历史记录不得进入公共示例。

### 十进制求和：可直接照填的示例

用途：对十进制字符串相加，避免先将输入转换成二进制浮点数。输入 values 是字符串数组，每个数都要加引号。

输入参数：

```json
{"values":["0.10","0.20"]}
```

预期结果：

```json
{"total":"0.30"}
```

当前操作：扩展 → Tools → 公共能力 → 十进制求和 → 保存个人副本；在个人副本填入上述输入和预期结果 → 开始验证 → 验证通过后启用此版本 → 用于对话。已拥有个人副本的用户从该副本继续，不必再次复制。

对话示例：“请调用已选中的十进制求和工具，计算 0.10 与 0.20 的和，并报告工具返回的结果。”结果必须有真实调用事件与记录，模型口算为 0.30 不能证明工具成功。以上结果来自样例代码逻辑与既有验收，本轮未重新执行。未实现自动发现前，仅在消息里写工具名不能替代“用于对话”。

### 资料摘要方法：测试示例

测试问题：“请按资料摘要方法总结：本周收到客户反馈 12 条，已处理 9 条，其余 3 条等待确认。仅根据所给资料，区分事实、缺失信息和结论，不补充原因。”

验收标准：准确保留 12、9、3 及其含义；不编造等待原因、负责人或完成日期；区分事实与推断，缺失项明确未提供。参考结构为“事实：收到12条、处理9条、3条待确认；缺失信息：原因和处理期限未提供；结论：仍有3条待确认”。不要求逐字一致。

当前操作：保存个人副本 → 填测试问题和验收标准 → 开始验证 → 核对结果 → 确认符合预期 → 启用此版本 → 用于对话 → 输入要总结的原文。包内 reference 要按声明路径加载，不能只靠模型本身的总结能力冒充执行了方法。

后续实现需统一样例名称、用途说明和内部描述的含义；如调整包内容，创建新版本并重新验证，不能改写已有不可变版本。本轮不改 examples/ 中的任何资源。

## 主对话发现与执行设计

1. 所有主对话入口使用同一份当前用户能力目录：保留内置能力，补充个人库的可用版本。公共库中未加入个人库的能力只可作为安装提示，不直接调用。
2. 目录只提供有界的名称、描述、来源、类型、资产及版本标识。按需检索并加载正文和工具参数，不能将全部包文件塞进上下文。目录应有分页或检索，不能默默只覆盖前100项。具体上限与接口字段在实现前确定并同步接口规范。
3. 显式选择的 assetId/versionId 优先，继续遵守会话锁。自然语言“文本总结”可按用途检索到“资料摘要方法”；检索结果必须解析为实际资产及版本。多个同样合理的候选需澄清并展示来源，不凭相似名称静默替换。该检索不改变依赖的精确身份匹配规则。
4. 对明确指名但不可用的能力，区分未安装、未验证、未启用、验证失效和归档；只向本人展示有权访问的状态。不能将“存在但不可调用”报告为“不存在”。无匹配时明确找不到；用户要求找不到即停止时，不继续原任务或自动改用模型自身能力。
5. 选定后经 admit 重新核对权限、验证和依赖；加载 Skill 正文及需要的参考资源，Tool 使用真实执行链。目录可见性不等于执行授权。禁用、配置变化、版本锁冲突和当轮文件授权继续生效。
6. 复用统一主对话运行链中的历史、主智能体提示、模型选择、搜索、文件授权与取消语义；不得简单把所有对话转到另一条循环而丢掉现有能力。旧内置与个人能力采用不同标识空间，不将导入代码注册到全局目录。
7. 分开展示发现/选中、已加载、已调用与失败。Skill 的加载不是独立 Tool 调用；工具执行成功必须有真实结果和调用记录，检索失败也不得伪造加载成功。
8. 应用分流需识别“使用某扩展完成当前对话任务”，保持在主聊天流程；明确创建或运行应用仍按原产品规则处理。本次目标不扩展为应用编排执行任意个人能力。

建议实现位置：工作台 service.py 与 graph_runtime.py 处理统一目录和主循环，能力库 service.py 提供用户隔离的检索、加载和执行桥接；前端 useWorkbench.js 核对分流及事件状态，CapabilityLibraryPanel.vue 展示示例。实现前确认最终边界，避免复制两套准入逻辑。

示例数据的存储方案建议采用版本关联的结构化使用指南，允许历史包缺省。字段覆盖对话问题、输入、预期结果或人工标准、来源与适用版本；前端与验证表单消费同一份数据。如扩展包契约，需同步两个 Schema、导入导出和兼容测试。当前没有新增此字段或接口，不应把设计当作现行机器契约。

## 验收条件

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| DISC-01 | 不点“用于对话”，要求使用已验证且启用的摘要 Skill 总结用户提供的《红楼梦》片段 | 主对话发现正确版本，加载正文及所需参考资料，有事件证据；总结只基于原文 |
| DISC-02 | “文本总结”与真实名称“资料摘要方法”不一致 | 按用途检索；唯一明确候选可选用并展示真实名称，多候选澄清 |
| DISC-03 | Skill 不存在，且用户要求找不到即停止 | 只报告缺失，不继续总结，不谎称使用 |
| DISC-04 | 存在但禁用、未验证、验证失效、已归档或仅在公共库 | 准确说明状态和操作，不绕过准入；与当前历史版本规则一致 |
| DISC-05 | 不显式勾选，要求调用十进制求和计算 0.10+0.20 | 有真实调用和返回 total=0.30；仅模型口算不通过 |
| DISC-06 | 两个账号、同名资产、超过单页目录、旧会话锁、切换版本 | 用户隔离，来源可区分，无分页遗漏，不自动升级锁定版本 |
| DISC-07 | 搜索、历史、附件、指定模型、停止、旧内置技能及应用分流 | 相关行为无回归；未授权文件不可读取；从正常前端入口验证 |
| EX-01 | 公共和个人详情 | 新用户不看源码即可理解并复制完整样例；个人验证表单可填入样例但不自动执行 |
| EX-02 | 十进制工具与摘要 Skill | 按页面步骤分别完成验证、启用和真实对话；按钮解释清楚 |
| EX-03 | 无示例的自定义能力、旧包、新版本、导出再导入 | 无虚构预期结果；指南来源与版本正确；老包兼容且原件不被覆盖 |

验证分三层：后端回归用可控模型替身检查目录、准入及事件；浏览器测试覆盖正常主对话入口和详情；隔离测试账号真实模型复现用户案例及工具调用，记录模型、版本/工作区摘要和结果。当前这些新增场景均未执行，不增加原验收通过数量。
