# 能力库接口文档

## 2026-10-15 可信版本启用补充

`PATCH /assets/{assetId}` 的字段与 `If-Match` 保持不变。显式 `enabled:true` 且根版本有服务端可信来源时，同一事务内按当前配置检查根版本和精确依赖，启用默认关闭的合格依赖；主动禁用、归档、删除的依赖返回 `DEPENDENCY_DISABLED`，全部写入回滚。私人版本原验证与过期配置拒绝规则不变。`POST /assets/{assetId}/recheck` 保留已删除依赖的旧精确锁并返回检查问题，不能静默换到同内容副本。详见[技术规范](技术规范.md#2026-10-15-可信版本与精确依赖启用)。


## 2026-10-15 技能池详情标准格式导出

技能池统一详情使用只读 `GET /desktop/api/skill-pool/standard-export?kind=skill|tool&source=personal|official|community&id=<assetId或releaseId>&versionId=<versionId>`。个人与官方必须提供当前详情的精确 `assetId`、`versionId`；社区以公开 `releaseId` 指向冻结的精确发布，`versionId` 可省略。响应为浏览器附件下载：展示名称加 `.zip`，不会安装副本、执行、验证或启用能力。该统一 HTTP 路由由技能池注册，能力库负责 `standard_exports.export_standard(library, owner, kind, source, id, versionId)` 的读取和组包。

Skill/Tool 外层 ZIP 本身可直接交给现有 `/imports/preview`、`/imports` 或“导入原件→准备”入口，不必手动选内层文件。根 `component.json` 是包含精确依赖闭包的 `cd80.component/1`，可选 `test-cases.json` 保留原用例及独立预期并清空账号 `fileIds`，根 `readme.md` 含完整说明、清单、示例、用例及所有可读 UTF-8 原始源码正文。原资源逐字节保存在组件快照和 `implementation/source/`；同名原 README 不会被生成的根说明覆盖。纯标准 Skill 目录在 `standard-skill/`，Tool 的调用接口在 `standard-tool/tool.json`，后者单独不携带可执行实现。

根 `standard-export.json` 的 `format=cd80.standard-export/1`，`files` 为其余全部成员的 `{path,sha256,size}` 精确索引。导入器只允许索引吻合且附属路径属于 `readme.md`、`standard-skill/`、`standard-tool/`、`implementation/source/` 的外层包；普通旧 `component.zip` 仍只接受原有的 `component.json` 与 `test-cases.json`。导入只采纳已校验的组件快照及用例，旁置资料不进入可执行资产。个人内容限本人，官方限公共精确版本，社区只读发布时冻结的公开源码和示例，不读发布者私人测试用例。疑似秘密、私人引用或无法完整表达的依赖明确拒绝，不以省略文件伪装完整导出。旧的 `original`、`agent_skills`、`platform` 和接口转换导出保持原语义。

## 2026-10-15 版本原用例增量（后端已实现）

`GET /assets/{assetId}/versions/{versionId}`（含官方公开精确版本）返回 `testCases:[{label,input,fileIds,expectation}]`；旧版没有存储字段时优先只读恢复本人历史验证套件提交的首例，随后才是包内示例与静态候选，不读取实际输出。`expectation:null` 表示 Tool 预期待补；Skill 静态候选可有非空 `prompt` 与空 `criteria`，也未填完预期。新导入 multipart `POST /imports` 可带 JSON 文本字段 `testCases`，手动 `POST /drafts`、`PATCH /drafts/{id}` 和 `POST /drafts/{id}/save` 可带同结构；不提供时从原件明确示例生成。用户文件 ID 只接受当前账号授权，不从包内文件路径映射或继承。保存不执行资产，响应仍为已保存、未验证/未启用的原语义。

`POST /validation-suites` 仍提交完整 `cases`，现在允许 1–10 组；首组独立预期必填，第二组可选，提交多组时继续检查至少一组真实不同输入。Tool 用 `json_equals` / `assertions`，Skill 用含 `prompt/criteria` 的 `manual_review`；验证证据绑定实际提交的完整用例快照。此前新版本单例阻断 `VALIDATION_SUITE_REQUIRED` 仅用于要求走套件接口，不再要求强制第二组。个人 `/test-cases` 仍是独立、可删除的用例库，不自动替换版本原用例；未知/失败重试沿用原请求幂等身份。下方 2026-10-14 两例要求保留为历史阶段契约。

`POST /exports` 的 `format=platform` 对普通 Skill / Tool 返回 `capability.zip`，对自足组件返回 `component.zip`；两者均含旁置 `test-cases.json`，不把用例混入 `SKILL.md`、原资源或组件快照。导出保留输入与预期，但清空账号专属 `fileIds`。`POST /imports/preview` 会显示随完整包保存的用例；`POST /imports` 可用 multipart `testCases` 覆盖该包用例，涉及文件时应先改为当前账号授权的文件 ID。裸 `cd80.component/1` JSON 导入继续兼容。相同内容且显式用例相同保持去重；显式用例不同创建新版本，旧版验证证据不会继承。`format=original` 和 `agent_skills` 不包含旁置平台元数据。

旧“原件入库→准备”入口在读取 Skill / Tool 的平台 ZIP 或组件 ZIP 时也返回草稿顶层 `testCases`，后续草稿保存沿用该独立预期；它仍只解析，不运行原件。旧裸组件 JSON 没有旁置用例时仅生成静态候选。社区公开发布不自动携带私人用例，只沿用清单中已公开的 `examples`。

## 2026-10-14 统一创作与候选验证衔接（定稿时说明）

实施更新：统一创作主流程已有工作区实现；准确源码、接口及本地分层证据见统一创作进度（本地资料，未随源码发布）与实施验收（本地资料，未随源码发布）。本节下方“未实现/待实施”保留文档定稿时点，不表示当前仍未开发；真实上游、完整路径矩阵及正式加载不能由旧基线或局部通过推定完成。

主对话、资产详情、成果沉淀和导入后准备统一使用[接口与存储契约](../asset-authoring/接口与存储契约.md)中的 `/desktop/api/authoring-sessions` 操作族；本模块继续维护个人资产、不可变版本、配置、实际执行及准入。新创作端点及内部候选适配尚未实现，下方 `/capabilities` 已有接口和机器契约继续作为当前可调用事实，不把新概念字段直接追加到旧请求。

待实施的内部适配允许验证持久化的不可变候选，绑定账号、内容/执行摘要、完整依赖、运行条件、用例与检查标准；候选不必先注册为个人库正式版本。系统准备原案例及不同输入，保留逐例真实结果。Skill 人工效果确认并入最后一次候选审阅；统一提交将相同内容保存为正式版本、关联有效证据并启用，后台各阶段仍独立核对并幂等恢复。客观失败、过时证据和客户端 `passed` 不能放行；最后确认不生成新实现或再次执行业务。

旧 `/drafts/generate` 的显式消息选择、`/drafts/{id}/save` 的仅保存，以及验证/人工审核/启用端点保留兼容；统一创作由协调服务自动整理来源并调用内部适配，不要求用户逐个操作。普通调用失败不能自动修改原资产，已授权创作只能修改候选。预算、恢复、证据晋升和跨库部分失败见[统一技术规范](../asset-authoring/技术规范.md)，体验及验收见[测试体验规范](测试体验产品设计与技术规范.md)和[实施与验收计划](../asset-authoring/实施与验收计划.md)。

## 2026-10-14 验证失败诊断

旧标准Skill的 `GET /verifications/{id}`、`GET /trials/{id}`，以及套件 `cases[]` 增加 `modelRequests[]` 与 `executionEvidence[]`。前者含 `requestId/round/attempt/requestNumber/status/stage/startedAt/completedAt/inputChars/contextDigest/outputChars/limits`，可附有限传输元数据及错误；失败部分输出仅保留 `partialOutputDigest`、字符数与 `partialOutputAccepted=false`，不返回失败轮正文或系统prompt。后者沿用真实Tool/Skill执行事件，成功Tool保留 `invocationId`，与模型请求分开。失败记录保存 `error.code/error.error/error.stage/error.completedToolCalls` 与 `completedAt`；未完成结果标 `result.incomplete=true`，不能接受为验证通过。

异步作业失败后客户端仍可用启动响应的 `verificationId` 查询上述记录；旧历史记录没有这些字段，客户端按缺失处理，不推测曾调用工具。新增错误 `MODEL_TIMEOUT`（504，同轮重试未恢复）、`VALIDATION_DEADLINE`（504，预算到期）、`MODEL_REQUEST_LIMIT`（429）、`MODEL_CONTEXT_TOO_LARGE`（413）、`MODEL_INCOMPLETE/MODEL_OUTPUT_LIMIT`（502）。预算和独立Skill范围见[技术规范](技术规范.md)。


## 2026-10-14 自足组件与多用例验证

新增 `POST /validation-suites`，请求 `{assetId,versionId,configurationId,cases:[{label,input,fileIds,expectation}]}`；至少原预期及一组不同实际输入，最多10组。Tool使用json_equals/assertions，Skill使用带prompt/criteria的manual_review；返回普通202 job及verificationId，使用既有 `/verifications/{id}` 查询逐案真实结果，人工审核仍走 `/verifications/{id}/review`。本轮以后新导入、创作、安装及社区复制版本 `validationPolicy=original_and_new`，单用例接口返回 `VALIDATION_SUITE_REQUIRED`，没有执行的预览/草稿不形成验证证据。

草稿files允许 `{path,text}` 或 `{path,base64}`；可带 `dependencySnapshots` 完整Tool闭包及 `authoringProvenance` 来源声明。来源声明仅旁置保存并标记historicalEvidenceVerified=false，不会把客户端historical标签当作已核实证据。导入支持纯标准SKILL.md/ZIP和完整 `cd80.component/1` JSON，导出 `format=agent_skills` 返回纯标准Skill目录ZIP；新自足版本 `format=platform` 返回完整组件JSON。导入与保存不会执行或启用，完整快照不携带连接ID/凭据/作者启用及验证记录。版本/导入响应以 `contentValidity` 和 `runtimeReadiness` 分开表达标准内容有效性与本机可执行性；现有验证是否失效仍看当前配置和证据。

新自足组件的社区发布审阅整个内嵌闭包，删除个人库来源不影响发布；接收方复制为同样完整的新版本，以自己当前连接和两用例重新验证。既有社区版本维持原协议。

## 通用约定

- JSON 使用 UTF-8；时间为 UTC ISO8601，界面转换本地时区；ID 为不透明字符串。
- 除上传与文件下载外均为 application/json。列表使用 `{items,nextCursor}`，默认 limit=20，最大100；cursor 不透明且绑定用户与筛选条件。
- 长操作返回 202 和 `{jobId,status,statusUrl,eventsUrl}`；GET/SSE 仅观察，不能启动工作。
- 有执行、生成、导出或保存效果的 POST 要求 `Idempotency-Key`。相同用户、操作、键和请求内容返回同一资源；同键异内容返回409，不重复模型调用或远端调用。
- PATCH 要求 `If-Match` 为 GET 响应的 ETag；请求也携带基础版本时两者必须一致。缺少返回428，陈旧返回412。
- 私有对象无权访问时返回404，避免跨账号枚举。查询接口不返回密钥。秘密写入接口禁止记录请求体。
- 错误格式 `{error,code,requestId,details}`，保留现有前端对 error 文本的支持。

## 导入与重导入

`POST /imports` 使用 multipart/form-data：`file` 为 ZIP、JSON 或原生 SKILL.md；可选 targetAssetId；原生目录由前端打包或文件选择器提交后统一形成 ZIP；不是宿主路径。标准化包装工作不能改动原生文件字节。

```json
{
  "importId": "imp_01",
  "jobId": "job_01",
  "status": "queued",
  "statusUrl": "/desktop/api/capabilities/jobs/job_01",
  "eventsUrl": "/desktop/api/capabilities/jobs/job_01/events"
}
```

完成后 GET `/imports/imp_01`：

```json
{
  "importId": "imp_01",
  "status": "completed",
  "assetId": "asset_skill_01",
  "versionId": "version_01",
  "deduplicated": false,
  "readiness": "needs_configuration",
  "issues": [{
    "code": "MISSING_DEPENDENCY",
    "severity": "configuration",
    "message": "缺少 quote-reader 工具，请补齐后重新导入 Skill。",
    "path": "dependencies[0]",
    "required": {"sourceIdentity": "org.example/quote-reader", "contentDigest": "<sha256>"}
  }]
}
```

导入任务 completed 表示检查过程完成，不等于 readiness=verified。已知资产相同内容复查返回原 versionId、deduplicated=true，不重写原件、不改变已有依赖锁。内容不同创建新版本，activeVersionId 不自动改变。首次相同包去重范围限本人及明确来源，不跨账号泄露是否存在。

## 草稿与对话沉淀

POST `/drafts` 接收 `{kind,name,description,baseAssetId?,baseVersionId?,manifest?,files?}`。files 为相对路径与 UTF-8 文本，二进制资源通过导入包携带；编辑大型资源用重导入。baseAssetId/baseVersionId 必须成对提供且属于本人。

POST `/drafts/generate` 接收 `{kind,taskId,messageIds,instruction}`，仅读取本人明确选择的消息；附件仍需单独 fileIds 授权。返回 job，结果为 draftId，不自动保存或验证。模型生成不能修改公共原件或已保存版本。

POST `/drafts/{id}/save` 接收 `{draftRevision}`，服务器与最新草稿版本比对，不一致返回409；首次保存返回 assetId/versionId/jobId，同次重试返回同一结果。

## 启用与版本切换

```http
PATCH /desktop/api/capabilities/assets/asset_01
If-Match: "7"
Content-Type: application/json
```

```json
{"enabled": true, "activeVersionId": "version_02"}
```

服务器检查 version_02 属于该资产，验证证据仍有效，生命周期非归档；不允许仅传 enabled=true 绕过待配置状态。禁用可直接传 false，不要求验证通过。`lifecycle` 仅允许 active/archived。恢复归档不自动启用或重新验证。

修改 activeVersionId 只影响新对话候选。旧对话显式切换能力需后文所述 `replaceCapabilityLocks`，默认不同版本引用返回 VERSION_LOCK_CONFLICT。

## 连接与 MCP 工具发现

创建连接示例：

```json
{"name":"行情查询连接","sourceIdentity":"org.example/quotes","transport":"streamable_http","endpoint":"https://quotes.example.invalid/mcp","authMode":"bearer"}
```

连接 POST 不联网。凭据 POST 使用 `{action:"set",value:"..."}` 或 `{action:"clear"}`；GET 仅返回 configured、credentialRevision，不返回 value。凭据变化使对应验证证据失效。

主动 discover 返回 job；结果含 discoveryId、protocolVersion、tools，每项含名称、schema 摘要和准入问题。随后 POST `/connections/{id}/tools/import` 使用 `{discoveryId,toolNames:[...]}`，仅从本人且未过期快照创建资产，不发起 tools/call。发现快照默认有效10分钟，过期返回 DISCOVERY_EXPIRED。

描述变化不自动替换旧资产；来源身份结合 connection sourceIdentity 和 toolName，schema 摘要纳入版本内容。未知权限保持 blocked，即使发现成功也不能验证。

## 验证

POST `/verifications`：

```json
{
  "assetId":"asset_tool_01",
  "versionId":"version_01",
  "configurationId":"config_01",
  "input":{"values":["0.10","0.20"]},
  "fileIds":[],
  "expectation":{"mode":"json_equals","value":{"total":"0.30"}}
}
```

Tool 首版支持 `json_equals` 对 content 精确比较、`schema` 结构校验加人工结果确认。仅 schema 校验不等于内容正确；此模式进入 awaiting_review。Skill 使用 `manual_review` 并提供 prompt 和验收说明；实际运行完成后等待 review。用户确认 API 为 `{decision:"accept"|"reject",comment?:...}`。

验证请求不要求 enabled，但必须通过执行准入和内容检查。禁止向 blocked、needs_configuration、checking 版本排队。测试过程复用调用记录与产物；同一证明不能被别的版本或用户直接冒用。

## 显式工具调用与追溯

POST `/invocations` 使用 `{assetId,versionId,configurationId,input,fileIds,taskId?}`，只接受 Tool；Skill 通过对话加载，不能伪装成函数工具执行。允许的 Skill 脚本由内部受控入口触发并关联版本，不对用户提供任意脚本路径执行 API。

返回 jobId/invocationId。GET 详情包含 status、versionId、configurationId、input、result、artifacts、error、redactions、时间、taskId 和 sourceSkillRefs。sourceSkillRefs 无可靠关联则为空，不根据当前选中列表推测。

状态 unknown 表示请求已发出但无法判断是否完成。此时服务器不能自动重放；用户发起新的显式请求需使用新的幂等键，并看到上次状态。

## 对话接口扩展

现有 POST `/desktop/api/chat` 保持 SSE，增加：

```json
{
  "message":"请使用这个工具计算",
  "taskId":"task_01",
  "capabilityRefs":[{"assetId":"asset_tool_01","versionId":"version_01"}],
  "fileIds":[],
  "replaceCapabilityLocks":false
}
```

首次引用形成锁。replaceCapabilityLocks=true 只允许界面明确确认后提交，用于本次引用资产的切换，不能解除其他权限；请求须携带用户看到的 taskRevision，避免陈旧页面覆盖。默认版本冲突返回409。原 skillNames 只解析既有内置名称，不能按同名寻找个人资产；个人资产使用capabilityRefs，两者身份分开解析。

2026-10-13实现：显式选择Skill/Tool时前端直接请求 `/chat`，不经过应用分流。未选择时保留 `/agent-dispatch`，分类提示明确一次性Skill/Tool任务属于chat；随后主对话也可自动发现个人能力。不能将capabilityRefs视为已实现的应用编排参数。选择Application时填写既有输入表单，POST `/agent-runs`，mode=invoke、agentRef为准确应用引用，沿用已有输入与文件授权。

主对话在原LangGraph中增加本轮隔离桥接：模型工具library_catalog（每页30项，nextOffset继续）、library_load（assetId/versionId）、library_resource（assetId/path）、library_script（assetId/path/input）。加载Tool后按该版本Schema提供cap_别名；这些是模型内部工具，不是新增HTTP端点。最多加载8项个人能力、12次个人能力操作；加载和执行重复准入。目录含本人不可用状态，不含他人数据或未复制的公共资产。新会话不自动沿用旧文件授权。

## 异步事件和下载

GET `/jobs/{id}/events` 接受 Last-Event-ID 或 after 游标。事件包含 id/type/data；断线可重连补读，不能重新执行。服务重启未结束任务标 interrupted；取消为 cancelling，实际终止后 cancelled，远程无法确认则 unknown。

导出 POST `/exports` 接收 `{assetId,versionId,format}`，format 为 original、platform、openai_chat、openai_responses、claude_tool。不支持的 kind/format 组合返回422；危险原件或疑似秘密导出返回403及明确原因，不返回被静默篡改的“原件”。下载凭 owner 验证，设置 attachment、no-store、nosniff；下载 URL 不承载密钥。

## 错误码

| HTTP | code | 语义 |
| --- | --- | --- |
| 400 | INVALID_REQUEST / INVALID_PACKAGE | 格式或上传布局错误 |
| 401 | AUTH_REQUIRED | 未登录 |
| 403 | CAPABILITY_BLOCKED / CAPABILITY_DISABLED / FILE_NOT_GRANTED | 不可执行、已禁用或未授权文件 |
| 403 | EXPORT_CONTAINS_SECRET | 原件可能含凭据，需用户处理后重导入 |
| 404 | NOT_FOUND | 不存在或不属于当前用户 |
| 409 | IDEMPOTENCY_CONFLICT / VERSION_LOCK_CONFLICT / STALE_CONFIGURATION | 幂等冲突、版本锁冲突、配置快照失效 |
| 409 | VERIFICATION_REQUIRED / DISCOVERY_EXPIRED | 验证失效或发现快照过期 |
| 412 / 428 | REVISION_CONFLICT / PRECONDITION_REQUIRED | ETag 冲突或缺失 |
| 413 | LIMIT_EXCEEDED | 包、正文或文件超限 |
| 422 | UNSUPPORTED_EXECUTION / UNSUPPORTED_SCHEMA / UNSUPPORTED_EXPORT | 当前运行或导出不支持 |
| 429 | CONCURRENCY_LIMIT | 超过并发限额 |
| 502 / 504 | UPSTREAM_FAILED / EXECUTION_TIMEOUT | 上游错误或超时 |

缺依赖通常作为导入检查报告问题返回，不使整个上传 HTTP 失败。任何执行入口尝试使用未就绪版本必须被后端拒绝，不能只在前端禁用按钮。

## 官方免配置准备

POST `/desktop/api/capabilities/official-preparations`，参数assetId/versionId/scope(public或personal)，必带Idempotency-Key，返回202后台任务。个人scope按服务端保存的公共溯源修复；内容变化则拒绝覆盖。平台完成依赖复制与真实Tool样例验证，主Skill仍未验证/未启用。失败码OFFICIAL_SERVICE_UNAVAILABLE表示平台负责的服务异常；DEPENDENCY_DISABLED表示用户曾主动停用，不索取连接参数。原copy接口保持兼容，新UI使用准备流程。

## 2026-10-13：更新与删除接口增补

- `GET /assets?deleted=true`：个人目录只列已删除项；默认排除。详情增加 `deletedAt`、`configurationStale`、`officialUpdate {available, versionId, number, publicAssetId}`；官方更新按保存来源对比，读取不修改数据。版本读取的 readiness 反映当前配置有效性。
- `POST /assets/{assetId}/official-update`：传官方 `versionId`、`If-Match` 与 `Idempotency-Key`，返回异步 Job。必须匹配确认时的公共最新版和个人修订；个人变化412，公共版本变化409（异步错误见Job）。保留历史版本，新版停用。
- `POST /assets/{assetId}/recheck`：传个人 `versionId`、`Idempotency-Key`，重新检查配置并返回 Version；不运行测试，不把失效验证恢复为有效。官方依赖准备沿用 official-preparations。
- `DELETE /assets/{assetId}`：传 `If-Match`，返回带新 ETag 的 Asset。本人软删除，立即停用，历史执行也不能绕过；其他账号和公共源404。
- `POST /assets/{assetId}/restore`：传 `If-Match`，恢复但保持停用；支持同来源多个副本；恢复时若重名则分配新展示名称。

本次无表结构迁移：Asset增加可选删除时间；版本、原件及审计记录保留。回滚到不识别deletedAt的旧代码会重新展示删除项，因此回退需要同时保留过滤及准入规则。

## 2026-10-13：公共副本状态与重复确认

公共Asset及公共Version返回当前账号 `personalCopies: [{assetId,name}]`，按当前个人latestVersion内容摘要匹配，已删除项排除；展示名称不纳入内容摘要。

`POST /assets/{assetId}/copy` 和 public范围的 `POST /official-preparations` 增加 `confirmDuplicate: boolean`。已有同内容且未确认返回409 `DUPLICATE_CONFIRMATION_REQUIRED`，不创建主副本；确认后新建独立asset，名称依次分配 `_2`、`_3`，个人展示名存于displayName，不改原清单或包。幂等重放返回同一结果。普通重新导入保持原有版本管理语义；官方更新及个人修复明确传入目标assetId，不因同来源副本变多而更新其他副本。精确依赖优先沿用已有锁，其次选已启用的匹配工具。
