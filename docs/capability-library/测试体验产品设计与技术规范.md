## 3. 表单与测试流程

### 普通表单

默认无需填写 JSON。数字、文本、选项、文件使用对应控件；数组允许增删项目，嵌套对象按组展开；字段提供中文用途、必填说明、示例及约束。高级 JSON 模式保留，切换不得静默丢失输入或改变值类型。

表单依照能力真实 Schema 序列化，不通过字段名称猜测执行契约。十进制求和的输入实际为字符串数组；视觉上可呈现数字输入行，但不得先转为浮点数再还原字符串，以免损失精度或尾随零。暂时不能呈现的参数说明具体限制及高级入口，不以空 {} 冒充可用表单。

错误定位到字段并给出修改办法；全局错误用于连接、权限、超时等非字段问题。后端仍做完整校验，前端校验不能替代后端检查。

### 示例测试与自由试用

| 模式 | 输入 | 结果与验证 |
| --- | --- | --- |
| 示例测试 | 作者提供的完整输入，可一键填入 | Tool 自动比较实际与预期；Skill 展示回答及验收项，用户人工确认 |
| 自由试用 | 用户自填，默认不要求预期结果 | 仅显示运行结果，不因未报错自动记为验证通过 |
| 自由试用转验证 | Tool 另填预期结果后重新运行；Skill 使用明确验收项 | Tool 比较通过或 Skill 人工确认后，才可形成相应验证证据 |

Tool 预期结果默认同样使用普通表单；不具备可呈现输出契约时，说明限制并提供高级模式，不伪造输出结构。Skill 的验收项应可理解，例如“只依据原文”“保留关键事实”；作者的声明与用户实际确认分开保存。

测试成功不自动启用。验证有效后，结果附近展示“启用并用于对话”，由用户主动点击；Skill 必须先完成用户效果确认。启用成功后进入原有对话选择流程，保留草稿，并遵守现有数量、版本锁及 Application 互斥规则。启用失败留在当前页面说明原因，不能假装已加入对话。

### 结果示例

十进制求和显示“输入：0.10 + 0.20”“求和结果：0.30”“与示例预期一致，本次测试通过”。高级详情才展示输入 {"values":["0.10","0.20"]} 与输出 {"total":"0.30"}。

Skill 直接展示生成文本和待确认验收项。失败展示原因、下一步及实际状态，不自动重试或用解释冒充执行结果；未知远端结果不能标记成功。

## 4. 官方示例与个人用例

官方扩展能力发布时必须随版本提供用途、至少一个完整可运行示例、预期结果或验收标准、运行条件及必要示例文件。发布前实际验证；缺少上述内容或发布验证未通过，不作为完整官方版本发布。平台逐项盘点所有官方 Skill / Tool，不只修复十进制求和。

官方验证证据记录能力版本与内容摘要、环境、时间、配置指纹及执行结果；不得包含凭据。官方通过记录不替代用户当前环境验证。个人副本仍需配置、运行示例并主动启用。

示例是版本内容的一部分，应随导入导出保留，不能长期只依赖按名称匹配或平台端硬编码指南。作者写出的预期结果只是验收依据，不等于平台已运行通过。无示例的第三方能力可自由试用，明确显示“作者尚未提供示例”；不能因此放宽原有准入。

用户可以保存“我的测试用例”，与官方示例分开展示。保存输入、预期结果或验收项及必要文件引用，不把密钥保存进用例。用例可在新版本再次运行；旧版本通过记录不能自动成为新版本证据，字段不兼容或文件失效时先提示修正。个人用例和运行记录不默认写入官方包或分享给其他账号。

## 5. 目标技术规范

以下为待实现约束，现有接口事实仍以 [接口规范](接口规范.md) 为准。不得将本文概念字段视为已经上线的端点或 Schema。

### 职责与契约

- 前端分离详情说明、Schema 表单、示例选择、运行结果及状态操作，避免单个页面继续集中全部职责。
- 后端负责示例解析、个人用例持久化、参数校验、试运行及验证证据；启用继续使用统一准入检查。自由试用的执行入口不能要求先启用，也不能绕过检查、配置或权限要求。
- 包内示例最少描述稳定标识、标题/用途、输入、Tool 预期结果或 Skill 验收项、条件和包内文件引用；绑定不可变版本与内容摘要。
- 个人用例最少描述 owner、能力身份、源版本、名称、输入、预期结果/验收项和文件引用。运行记录另存，绑定实际执行版本、用例快照及现有配置/执行器证据；编辑用例不改写历史。
- Tool 比较默认沿用严格结构和值比较，不增加未经定义的模糊判断；动态结果暂不能严格比较时明确限制，不把自由试用成功当验证通过。
- 错误应支持可映射到嵌套字段的路径与说明，保留已有错误码和非字段错误处理。若后端只能返回泛化错误，不得编造具体字段原因。

实现前完成包示例格式、个人用例操作、自由试用与验证区别、字段错误的精确契约，并同步 OpenAPI、文档 Schema 和运行 Schema。以增量兼容为原则，不在本轮文档任务修改机器契约。

### 权限、并发与生命周期

能力、用例、输入文件、结果均按账号校验归属。文件只能引用包内受检查资源或当前用户授权文件，不接受任意宿主路径。示例文本和输出按不可信内容安全渲染。

重复点击防重复提交，沿用现有幂等约束；旧版本、旧账号或旧请求的迟到响应不能覆盖当前表单。运行中显示进度，取消沿用真实状态；重启中断不得自动重放。

配置、凭据、依赖、内容或执行器变化仍按现有证据失效规则处理。“运行成功”“验证通过”“已启用”分开展示，前端组合按钮不得合并后端权限判断。

### 兼容与迁移

旧包无示例仍可导入并按现有规则检查；原始文件保留，不原地改写旧不可变版本。已有官方硬编码指南可作过渡兼容来源，但发布的新版本必须带示例。新增包内示例导致内容摘要改变时走新版本，不静默覆盖个人副本。

个人用例存储采用现有模块的账号隔离机制；具体持久化格式、版本升级与回退办法随实现契约补齐。正式数据迁移须先备份并在隔离副本验证；本次没有迁移或启用任何正式能力。

## 7. 实施契约（2026-10-13）

- manifest 新增可选 examples 数组（最多20项），每项包含 id、title、description、input、prompt、criteria、expected、requirements、filePaths；id 在版本内唯一。Tool 必须 input 与 expected，Skill 必须 prompt 与 criteria。filePaths 引用已索引包内资源。旧包无此字段兼容。版本响应附加 usageExamples；usageGuide 保留首例兼容。
- POST /trials：与调用相同的 assetId/versionId/configurationId/input/fileIds，Skill 增加 prompt；返回异步 job，其结果包含 trialId、result、status。按试运行准入，记录 trial，不生成验证证据、不改变最后验证记录。GET /trials/{id} 仅本人可读。
- GET /test-cases?assetId=…：分页列出个人用例；POST /test-cases：保存不可变用例（name、assetId、versionId、input、fileIds、可选 expected/prompt/criteria）；DELETE /test-cases/{id} 删除个人用例，不删除运行历史。保存使用 Idempotency-Key，默认不允许保存疑似凭据。重跑仍提交当前版本与用户确认的文件授权，不自动执行保存内容。
- 使用现有 capability_records 新增 trial/test_case 类型，不改物理表；旧服务不会读取新记录。回退保留记录与新版本原件，旧服务不能执行新格式包时应保持不可用，不回写旧版本。
- 异步字段错误 details.fields 为 path（数组形式）/message 列表，前端映射字段并保留全局提示。
