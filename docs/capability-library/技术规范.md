# 能力库技术规范

## 2026-10-15 可信版本与精确依赖启用

继续使用 `PATCH /desktop/api/capabilities/assets/{assetId}`，请求体与 `If-Match` 不变。启用可信官方/公开版本时，在同一能力库事务中处理锁定的精确 Tool 依赖，再检查根版本准入。可信版本按当前平台配置重新执行静态检查，更新配置摘要；不执行示例、不调用模型、不制造验证通过记录。依赖必须具备服务端精确来源信任或本账号当前有效验证；默认关闭的合格依赖可随根能力一并启用。已有启用依赖保留其当前主版本。

`explicitlyDisabled=true`、归档、删除或不满足当前条件的依赖拒绝整次操作，检查与启用写入一并回滚。普通调用和试用的 `admit` 检查不变；私人未验证或配置过期版本不因本次流程取得免验证资格。前端仅为可信、无已知问题且配置过期的版本额外保留启用入口，最终权限与来源由服务端判断。验证及运行证据见本轮记录（本地资料，未随源码发布）。


## 2026-10-15 个人数据文件授权（当前实现）

能力库继续复用工作台的文件 ID 和当前账号鉴权；数据管理上传的文件以服务端 `source=data_management` 标识，参见[个人数据文件规范](../financial-data/个人数据文件.md)及[复用文件池决定](../decisions/2026-10-15-个人数据复用文件池.md)。`file_grants(owner, ids, manifest)` 先要求能力声明 `permissions.inputFiles=true`，再逐个调用工作台 `open_file(owner, id)`，按当前账号读取实际字节并核对 SHA-256。只有这个来源的单文件授权上限为 10 MiB；普通上传文件继续为 2 MiB。超过限额、文件丢失、无权访问或摘要变化均拒绝，不能靠客户端文件名或模型声明扩大授权。

授权文件以不透明文件 ID 加后缀映射为隔离执行器只读输入；长展示名被截断时，数据管理文件使用上传时验证的格式恢复 `.csv/.tsv/.json/.xlsx` 后缀。完整字节用于获准的 Tool/Skill 或固定流程，执行器原有总输入 16 MiB 预算、版本准入及其他权限继续生效。模型看到的只是工作台按本次所选文件生成的有界预览，能力调用不自动附带同账号其他文件。该变更不修改官方金融 SQLite 库，也不使数据文件成为公共资产。

## 2026-10-15 版本原用例与单例准入（后端已实现）

Skill / Tool 新版本顶层持久化 `testCases:[{label,input,fileIds,expectation}]`，至少一条、最多十条，首条为原用例。Tool 的 `expectation:null` 表示没有独立可核对的预期、需要用户补充；Skill 无明确标准时保留静态任务 `{mode:manual_review,prompt,criteria:""}`，空标准同样不可验证通过。不能把运行结果、模型猜测、格式通过或上传来源声明当作预期。Tool 的明确预期映射为 `json_equals` 或 `assertions`，Skill 映射为含 `prompt/criteria` 的 `manual_review`。包内 `manifest.examples` 的 `filePaths` 不是当前账号上传文件 ID；需要文件而尚未重新授权时，候选仍可保存但预期留待补，验证时按本人 `fileIds` 重新核对。没有原件示例时从 Tool 输入 Schema 静态构造候选，无法可靠确定字段时只保留待填对象；Skill 用名称和说明构造非空任务，不虚构业务判断标准。所有生成只解析声明，不调用模型、Tool、Skill 或用户代码。

正式导入、手动草稿、模型草稿保存和完整组件安装在保存版本时写入同一结构；官方/社区复制只继承精确包内原例，不继承他人个人文件 ID、凭据、验证或启用。版本用例不加入 `contentDigest` 或组件执行摘要，不修改不可变原件；旧版本读取优先只读投影本人历史验证套件提交的首例 `label/input/fileIds/expectation`，不带运行状态或实际结果，无可用记录时才用包内示例或静态候选，不迁移库。输入/预期及文件身份仍按当前账号校验；没有另交用例时同内容可按原方式去重，明确提交相同实现但不同用例时创建新的不可变版本，旧版证据不迁移。验证套件由原先 2–10 组改为 1–10 组：首组完整预期必需；若有后续组，每组也须完整预期，且至少一组与首组实际输入不同。逐组仍真实运行、比对或等待 Skill 人工审阅；全部通过并满足当前配置/依赖证据后才可启用与发布。可信官方/公开副本保留既有免验证准入，其他执行安全门不变。旧版单例验证历史协议继续兼容。

平台完整导出将用例放在 ZIP 旁置 `test-cases.json`，普通资产保留原清单与资源，组件保留 `component.json` 的原快照；导出时将用例 `fileIds` 清空，防止跨账号携带授权，同时保留输入和独立预期。导入端只在明确的平台包读取该文件，再按当前账号校验。纯 Agent Skills 导出不附带平台元数据，原件导出保持原字节。社区发布仍只向他人提供经作者审阅的源码和公开清单示例，不因本轮自动公开个人版本测试输入。详情见[能力包规范](能力包规范.md#2026-10-15-版本原用例与完整包当前规则)。

## 2026-10-14 Skill验证模型超时修复契约

旧标准Skill的验证/试用沿用真实工具循环，模型每轮输出先缓冲，完整结束后才接受该轮文本和工具调用。只有模型请求超时且用户未取消时，同一轮至多重试一次；使用相同messages及已经成功的Tool结果，不从头重跑验证或重放工具。认证、参数、业务工具错误不自动重试；模型后续明确请求相同参数仍按新的调用处理，不增加全局结果缓存。

旧标准Skill的验证模型循环采用同一任务共享预算（双用例也共享）：300秒、6次模型请求；不延长现有单请求连接/读取超时，仅按剩余预算收紧。独立监视器检查绝对期限与取消，持续心跳或无可见输出不能绕过模型等待期限；已有响应使用既有AbortableResponse中断。尚无响应头时调用方及时终止，迟到请求不得产生工具执行或写回验证结果，底层连接按有界HTTP超时回收，模型在途并发最多2个。取得并发槽后再次检查预算，消费者关闭或持久化失败会关闭生成器，由请求线程最终回收槽。Tool/WASI接收预算取消信号并在返回后再检查；不声称所有底层网络请求都可瞬时硬截断。完整快照的独立Skill仍沿用原节点模型调用预算，接收协作取消并在返回处检查本次验证预算，不属于旧循环6次模型上限，也不承诺无响应头时可在300秒内硬中断。

验证/试用记录新增modelRequests（逐次请求ID、轮次/尝试、起止时间、阶段、上下文字符数/摘要、输出字符数、有限传输元数据、失败部分输出摘要与未接受标记）及executionEvidence（真实Tool/Skill完成或失败事件和invocationId）。不在新增诊断中保存完整系统prompt或失败轮正文；失败部分输出不拼接为重试成功结果，也不形成验证成功。错误保存code、阶段和完成时间；页面在作业失败后读取已保存记录，只展示请求次数、完成工具数、停止阶段等简短诊断，区分“工具尚未调用”与“工具成功、模型解释未完成”。不根据模型替身或诊断信息宣称真实金融或模型服务恢复。

2026-10-14 补充实施契约：`components.tool_draft_from_nodes(definition,nodes)` 将有序 code/tool 节点转换为 `fixed_pipeline` 草稿；动态 Skill 不能转换为固定 Tool。未包含的前序结果返回 `SOURCE_NEEDS_EDIT` 与缺口；固定步骤使用明确输入/前序 JSON/本次授权文件/前序工件绑定，保留代码相对资源。草稿支持 `{path,text|base64}` 和 `dependencySnapshots`；`install_snapshot` 将完整闭包作为新版本的 `embeddedSnapshot` 保存，不创建需单独启用的隐藏个人资产。保存和导入均不执行闭包；正式入口仍以主版本的当前验证及启用为准，内部快照逐次检查当前连接、凭据和平台权限。平台包可使用 `cd80.component/1` 完整快照，标准 Skill ZIP 仅含标准内容与资源。

本轮以后所有新导入、创作、安装及社区复制版本使用 `validationPolicy: original_and_new`。`POST /desktop/api/capabilities/validation-suites` 输入 `{assetId,versionId,configurationId,cases:[{label,input,fileIds,expectation}]}`，首项为原预期，至少另一项输入不同（Skill 还计测试问题；文件内容摘要参与比较），最多10项；Tool expectation 为 `json_equals`/`assertions`，Skill 为含 prompt/criteria 的 `manual_review`。返回普通异步 job 和 verificationId；逐案实际执行后自动比较或等待用户对真实结果审阅。任一失败、取消、配置失效不能通过，单案验证不能替代新版本准入。历史版本保留其既有验证协议。

## 2026-10-14 统一资产组件契约（本轮实施）

新增内部 `components.py`，供统一 App 服务调用，不开放可绕过 App 验证/启用的 HTTP 执行入口：

- `build_snapshot(library, owner, asset_id, version_id)` 保存精确版本及全部 Tool 依赖，返回 `format=cd80.component/1`、`manifest`、`files`（相对路径到 base64 字节）、`dependencies`（完整子快照）、`provenance`、`contentDigest` 与 `snapshotDigest`。来源记录只用于追溯，不作为持续执行授权。
- `snapshot_from_package(manifest, files, dependencies=(), provenance=None)` 将新内嵌实现转换成相同快照；`validate_snapshot(snapshot)` 检查 Schema、文件清单/摘要、大小、依赖闭包及快照摘要，无模型或外部调用。
- `runtime_digest(library, owner, snapshot)` 校验当前账号与运行条件，返回当前执行器、模型连接、数据连接和 MCP 策略/连接修订的摘要。App 验证证据必须绑定该值，变化后重验。
- `invoke_snapshot(library, owner, snapshot, arguments, files=None, stopped=None, context=None)` 复用既有 WASI/受控连接执行并返回原 invocation 结构；`files` 只能由调用方校验 owner、运行和摘要后提供。每次仍检查当前账号与连接准入，不读取已删除原组件，不继承来源的验证/启用。App 调用方必须先验证 App 当前版本、当前运行配置及启用状态。
- `skill_material(snapshot)` 返回标准入口、全部资源、已声明脚本与完整依赖快照，供独立 Skill 调用边界使用；`invoke_skill_script` 仅执行快照明确声明的脚本，沿用相同权限与文件边界。

快照限制为闭包最多16个包、总文件500个、源字节50 MiB、单文件1 MiB、深度8；超限明确失败。不允许从快照声明 owner、凭据或已验证状态取得权限。单个调用结果沿用512 KiB和既有WASI文件限制。快照执行记录以独立内容身份记录，并关联调用方提供的运行/节点上下文。

标准 Skill 导出新增 `format=agent_skills`，将入口所属标准目录原样导出，包含二进制资源及未支持语言文件，不含平台清单、配置、验证和启用状态。站内创建、编辑与沉淀的 Skill 同样支持；入口目录外资源不能无损映射时明确拒绝，禁止静默丢文件。导入继续自动生成旁置平台适配，额外返回 `contentValidity` 与 `runtimeReadiness` 分开表达标准内容和本机执行条件。原 `original/platform` 导出语义保持。

固定多步骤 Tool 新增 `execution.type=fixed_pipeline`、`protocolVersion=1`、`steps`。每步有 `id`、`kind=python_wasi|model|tool`、`inputFrom=input|steps.<前序id>` 和 `outputSchema`；Python步指定包内 `path/callable=run`，模型步指定固定 `prompt`，Tool步指定 `sourceIdentity/contentDigest` 并从完整闭包调用。也可指定 `inputBindings:{key:{source,path}|{value}|{inputFile}|{artifact:{stepId,name}}}`：source为input或steps.id，path为字符串/数组索引列表；inputFile值为顶层本次参数字段名，字段值必须匹配实际授权 `/input/` 文件；artifact引用前序真实产物。`delivery:{schema,files:[{name,mediaType?}],evidenceFields:[点路径]}` 保留所选App的交付门，复用App的实际交付检查，逐步核对非空字节、文件类型/可解析内容和非空证据字段后才启动下游。最多16个顺序步骤，超限或缺前序明确列缺口，最终返回末步结果。固定模型prompt最多120000字符，完整保留旧流程允许的prompt与Skill正文，不截断。模型仅输出单个JSON值，不提供工具、不接受其新增调用/流程；每步输出Schema严格校验。代码/提示/连接修订属于版本及验证上下文，失败不能静默改写。默认交付全部内部文件，以 `<stepId>__<name>` 命名；可显式声明 `execution.outputFileNames=last_step`，只交付末步骤的实际文件并保留原文件名，供旧单工具协议包装使用，不能误认为前序文件已交付。内部文件仍以 `<stepId>__<name>` 命名，后续步骤只读 `/input/`，映射位于 `payload._files`；提取代码的 `fileAliases:true` 另提供 `payload.files` 明确别名映射；累计输出受4 MiB限制。总调用预算120秒，模型JSON不超过512KiB。真实模型调用使用宿主既有受控provider，无WASI网络或宿主回退。该扩展必须显式声明协议，旧执行类型保持原语义。

本节为具体实施契约；验证结果另记开发进度，不据此宣称通过。

旧固定流程转换保留固定实现：单来源完整对象原样传入，多来源按旧语义组成 `{"inputs":[...]}`。代码通过隔离包装层补充旧 `filePaths/filePath/outputDir`，旧文件授权转换为本次明确fileBinding及稳定逻辑别名，不携带历史上传ID。平台registeredTool仅可映射当前可信只读注册表中的同Schema工具（含web_search与既有SFC），当前服务/策略仍逐次检查；未知或已撤销类型给具体缺口。旧末尾explain保存原prompt、Skill正文及精确参考资源为固定模型Tool，输入包含当前input、当前授权文件元数据与全部已执行步骤结果；新增JSON交付封装标modified，不声称原历史源码或自动通过验证。

Creator来源归因仅使用最终交付闭包/明确adopted成功步骤的完整执行证据；loadedRefs本身不证明方法被采用。精确调用记录的sourceSkillRefs、library_script的实际scriptPath与入参、library_skill的真实skillCallId用于恢复对应内容。标准脚本恢复为包含完整源码/资源的固定Tool，完整Skill调用保留动态Skill节点，不能把子轨迹冒充固定方法。来源声明/旧版本追溯在草稿修改时保留，但所有客户端声明仍非已核实历史证据，验证状态不继承。旧recipe仅接受同账号实际sub_agent来源runId，兼容旧顶层字段；公共/复制来源不猜为本人的运行。

## 存储、锁和重启

路径为 DATA_DIR/capability-library/capabilities.sqlite3，WAL，busy_timeout 5000，user_version=1。Store持有一个 check_same_thread=False 连接，用进程内RLock和 BEGIN IMMEDIATE 事务保护写操作，不是原设计的每请求连接。

物理表：
- capability_records(owner,kind,id,body)，联合主键；资产、版本、配置、连接、验证、任务、调用等按kind区分。
- capability_blobs(owner,id,content)，联合主键；保存原件和产物字节。

版本与原件在同库事务保存，没有 data/capabilities/<owner>/<asset>/<version>/ 文件树。工作台任务保存 capabilityLocks / capabilityRevision；该JSON与能力库之间没有跨存储统一事务。更换机器的DPAPI凭据需重新配置，不能假设复制库即可解密。

启动时 queued/running/cancelling 的 job、invocation、verification 标记 interrupted；不自动重放。远端结果不确定可记录 unknown，用户检查后主动重试。

## 准入与执行

service.admit() 统一检查用户、版本、开关、配置、验证、依赖和权限；导入声明不能授予执行权。配置/凭据修订和执行器相关源文件摘要参与证据有效性，代码更新可能导致旧验证失效。发现返回的完整工具定义摘要变化后不能静默沿用信任。

Python使用已有SandboxExecutor、只读包/输入及隔离输出；不回退宿主。内置适配限已注册南财只读handler及完全一致的参数声明。MCP支持Streamable HTTP、无认证/Bearer/API Key；不支持OAuth、stdio、旧独立SSE传输、服务器要求客户端执行或图片/二进制结果。

CAPABILITY_MCP_POLICY_FILE为维护者审核文件，内容与准入示例见 第一版记录（本地资料，未随源码发布）。普通用户不能凭readOnlyHint自行放行。DPAPI密文不返回前端/模型；返回秘密的远端结果会被拒绝。

## 接口与并发

路由前缀 /desktop/api/capabilities；错误为 error/code/requestId/details。列表 items/nextCursor，默认20最大100，游标绑定用户与筛选。返回revision的对象提供ETag；PATCH使用If-Match。经action包装的POST要求Idempotency-Key，同键异内容409，未确定结果不能自动重放。

GET/SSE只是观察。导入、验证、生成、发现、调用、导出等操作详见 [接口规范](接口规范.md) 和 [OpenAPI](openapi.yaml)；本页不维护第二份端点清单。

## 限额和已知边界

压缩包20 MiB、展开50 MiB、最多500项、路径深度12、单个包文件统一1 MiB（包括非文本）。结果512 KiB，隔离输出合计4 MiB；单用户最多2个异步任务、全站4个，一次对话最多12次工具请求。WASI执行时间和内存沿用既有运行器配置。

试运行成功不等于启用；需要人工确认的样例必须完成审阅。第一版不支持任意第三方依赖或任意供应商产物原样执行。应用编排消费新个人能力仍在范围外。

## 官方更新、重新检查与删除（本轮确认）

个人副本读取时只计算官方最新版与当前运行配置差异，不隐式更新。新版提示需用户确认，按其确认的公共versionId更新为新的个人版本，保留历史内容并停用，重新测试后启用；若公共版本再次变化返回冲突，不静默更新到其他版本。运行规则变化单独提示重新检查与验证，不能仍显示验证有效。个人Skill/Tool删除需确认，使用可恢复删除，默认列表与对话发现隐藏，所有新调用（包括旧会话）拒绝；保留历史记录与版本供恢复。公共共享库不因个人删除而改变。

## 2026-10-13：官方目录已添加标识与重复副本

公共Skill/Tool和预置Application显示当前账号“已添加到我的库（内容一致）”及数量；此状态表示保存，不表示已经验证或启用。只比较个人当前内容，删除或修改后的副本不算一致。

重复添加允许，但提交前说明已有相同内容，确认才创建独立个人副本，并按名称、名称_2、名称_3分配未占用名称。后端再次检查重复并要求confirmDuplicate，幂等重试不额外创建；事务中分配名称防并发冲突。名称是展示信息，不应改变Skill/Tool包摘要或官方依赖。自动依赖准备继续复用精确版本，不因主能力重复添加而重复依赖；官方更新必须精确定位个人assetId。

Application沿用预置目录，新增只保存不执行的复制入口；原先成功运行后保存仍保留。新副本独立ID和名称，输入授权、运行确认及隔离执行规则不变。
