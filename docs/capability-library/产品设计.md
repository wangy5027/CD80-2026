## 2026-10-15 本地 Skill / Tool 启用修复

官方或公开的可信精确版本仍由用户主动启用；添加个人副本只保存、不运行、不启用。启用 Skill 时一并启用其所需、尚未主动禁用的可信 Tool 精确依赖，避免“可启用”却因默认关闭依赖而失败。界面在操作前说明这一行为。仅运行配置过期且无已知检查问题的可信版本仍保留启用入口，由服务端重新检查当前条件。

## 用户和信息架构

普通用户管理自己的能力、连接、测试和记录；平台维护公共能力及可信连接准入规则。第一版不开放用户向公共库发布、其他用户分享或团队协作。

```text

扩展
  Skills                    我的能力 / 平台公共能力
  Tools                     我的能力 / 平台公共能力
  连接配置                   凭据、服务地址、主动连接检查
  调用记录                   按能力、版本、会话和结果筛选
```

个人库列表显示名称、类型、来源、版本、当前状态、最后验证时间。支持名称搜索、来源和状态筛选；同名资产必须展示来源，不能把名称当作唯一身份。公共列表操作为“加入个人库”，不能直接修改公共原件。

能力详情页包含“概览、文件、检查结果、配置、验证、版本、调用记录”。代码和原始定义默认折叠。Skill 配置页只列缺失工具、接口要求和处理说明，不出现匹配推荐、替代建议或依赖绑定按钮。

## 导入向导

1. 选择 Skill、Tool 或 MCP 描述；上传 ZIP、选择目录文件，或填写工具定义及执行信息。目录通过浏览器文件选择上传，不能提交任意宿主目录路径让服务端读取。
2. 展示来源、原始文件清单、文件数量和摘要。用户填写的来源标记为声明来源，不伪装成已验证发布者。
3. 保存原件并解析；不执行代码，不安装依赖，不发起 MCP 工具发现。
4. 展示检查报告，分为阻断项、待配置项和说明项。检查失败不显示可操作的试运行按钮；后端同样拒绝请求。
5. 无阻断项且配置完整时进入“待验证”；用户明确点击试运行。

原件保留不代表必须展开危险压缩包。路径穿越、压缩炸弹等不安全上传直接拒绝；可安全存储但不能解释的包保留在隔离区，不进入可调用目录。支持界限见包规范。

## 状态与操作

状态分为三个维度，避免“已启用但缺少密钥”等情况被一个标签掩盖。前端展示主状态与附加标记，后端返回完整维度。

| 维度 | 值 | 含义 |
| --- | --- | --- |
| 生命周期 lifecycle | draft / active / archived | 未保存草稿、已保存资产、已归档 |
| 就绪状态 readiness | checking / needs_configuration / blocked / unverified / verifying / verified / failed | 检查中、待配置、不可调用、待验证、验证中、已验证、验证失败 |
| 用户开关 enabled | true / false | 是否允许正式对话选择或继续使用 |

正式调用要求 `active + verified + enabled`，且运行时权限检查再次通过。已归档版本不能加入新对话，但已锁定它的旧对话可继续使用，前提是仍启用且验证有效。禁用阻止新调用，包括旧对话；对于已执行的远端请求不能宣称撤回，系统尽力取消并明确记录状态。

首次导入、编辑和公共复制默认不启用。试运行不要求先启用，否则形成循环；它要求已保存、非归档、解析检查通过、配置完整和用户明确发起。草稿先保存版本，再试运行。

| 详情页操作 | 前置条件 | 结果 |
| --- | --- | --- |
| 编辑 | 本人草稿或个人资产 | 创建编辑草稿，不覆盖原件 |
| 保存 | 用户已审阅草稿 | 产生不可变版本，重新检查 |
| 重新导入 | 本人资产或新资产 | 同内容复查；新内容创建版本 |
| 试运行 | 检查通过、配置完整 | 异步验证，不自动启用 |
| 启用 | 验证有效 | 供新对话选择；不能自动升级旧对话 |
| 禁用 | 本人资产 | 后续执行被阻止；界面显示受影响旧会话 |
| 归档 | 已保存资产 | 从新对话候选移除，保留历史 |
| 删除草稿 | 未保存且未被引用 | 删除该草稿；不连带删除历史版本 |
| 导出 | 本人有权读取原件 | 下载原件或平台完整包 |

## 缺失依赖与重新导入

例如 Skill 声明需要 `org.example/quote-reader`，但用户库不存在该依赖。页面只显示“缺少 quote-reader 工具”及声明的接口要求。用户自行引入该工具或在外部修正 Skill 后，重新导入 Skill。平台只核对明确身份，不按相似名称、描述或模型推测匹配。

相同内容重导入不增加版本。首次缺失的依赖在重检时可完成精确解析并写入配置快照；已有版本的依赖解析不能被重导入悄悄换成其他工具。需要改引用时，用户更新声明并导入新版本。

用户取消导入或试运行时显示实际状态；取消请求已发出不等于远程执行已停止。未获得结果的调用不得显示成功。

## 公共能力与个人副本

“加入个人库”复制指定公共版本的文件及定义，记录来源版本；不复制平台密钥、用户凭据、调用历史、授权文件和启用状态。复制后由本人配置、验证和启用。无凭据、无文件的纯文本 Skill 可以复用对应内容的结构检查证据，仍需完成用户效果确认。

公共更新不会覆盖个人副本，不做自动升级。平台现有内置工具可以使用由后端控制的服务级连接配置，但密钥不会以个人副本文件形式分发，也不会在导出后自动获得同样授权。

## 对话中的能力选择

选择器中不可选项目必须展示具体原因和下一步：已验证但未启用、未验证、验证中、验证失败、缺配置、检查阻断、已归档分别说明。提供“去扩展处理”直达该个人资产详情，不自动验证或启用；已选中项目提示可从输入框移除，不误导为需要再次启用。跳转保留对话草稿。

引入的文本属于用户提供的任务资料，不得提升为平台系统规则。Skill 不能通过文字要求授予额外权限、安装脚本或绕过禁止调用的工具。

## 从对话沉淀与编辑

用户明确要求保存方法或工具时，生成能力草稿。用户可以查看来源消息、文件及差异，修改名称和内容，再确认保存。普通成功回答、点击点赞或完成一次调用不会自动沉淀。

生成 Skill 和生成 Tool 是独立选择；不能把应用运行记录直接当作能力。已成功执行的代码，仅在内容、执行器、依赖、配置和样例证据完全对应时才允许复用验证记录。文字声称“验证过”无效。

## 错误与反馈

页面应说明原因和下一步动作，例如“缺少 X 工具，请自行补齐后重新导入”“包含本平台不支持的 Bash 执行要求”“该工具可能修改外部数据，本版不可调用”。不得提供一键强制运行。

工具失败后停止依赖该结果的后续动作；不自动修复、替代或重放。可以继续向用户解释已知失败，但不能把解释当作任务成功结果。

## 首版非目标
