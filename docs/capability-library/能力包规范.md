# 能力包规范

## 2026-10-15 技能池标准详情 ZIP

详情页“标准格式导出”的 Skill / Tool ZIP 是可直接回导的扩展组件包，不改变 `format=agent_skills` 纯标准目录、`format=original` 原字节和 `format=platform` 旧完整包。根文件为 `component.json`、可选 `test-cases.json`、`readme.md`、`standard-export.json`。`standard-export.json` 逐文件记录除自身外的全部成员路径、SHA-256 与大小，供只读导入解析核对；没有此版本化精确索引时，旧组件包仍禁止额外文件。

`component.json` 保存 `cd80.component/1` 根 Skill / Tool、所有源文件字节和精确 Tool 依赖闭包，是平台再导入的真实实现。`implementation/source/root/` 和 `implementation/source/dependency-N/` 仅提供逐文件阅读副本，原始大小写及相对路径仍保存在组件中。`readme.md` 有无截断的详情文本、输入输出契约、依赖、公开示例、原用例/独立预期、文件索引以及 UTF-8 原始文本全文；非文本资源记录路径、大小和摘要并保留实际字节。原始同名 README 在源码路径下仍原样存在。可无损转换时，`standard-skill/` 保留纯 Agent Skills 的 `SKILL.md` 及全部相对资源；无法无损转换时说明原因并保留平台组件完整源码。Tool 的 `standard-tool/tool.json` 是外部工具调用接口，执行代码、资源与连接声明仍以平台组件和源文件为准。

个人/官方源从精确不可变版本与绑定的依赖构建；官方旧包没有依赖锁时仅按官方目录的来源身份和内容摘要匹配。社区源只取发布记录及冻结的源码 blob，不重新读取发布者私人版本或测试记录。账号文件 ID 清空，组件 `provenance` 去除个人来源，目标账号仍需自行配置连接并检查验证/启用门禁。输出在文件数、单文件、总解压和 20 MiB 上传上限内进行完整有界校验；不能完整表达时拒绝，不静默截断或遗漏资源。

## 2026-10-15 版本原用例与完整包（当前规则）

`format=platform` 导出的普通 Skill / Tool 是 `capability.zip`：原有 `capability.json`、`provenance.json` 和资源之外，增加平台专用 `test-cases.json`，保存该精确版本的原用例输入及独立预期。自足组件导出为 `component.zip`，内含原 `cd80.component/1` 的 `component.json` 与旁置 `test-cases.json`；旧的裸 `component.json` 仍可导入。导入同一完整包会恢复用例，但不会继承原账号的验证、启用或连接权限。用例元数据不进入原件资源索引、`contentDigest` 或组件快照摘要。普通包资源占用 `capability.json`、`provenance.json` 或 `test-cases.json` 保留名称时，完整转换会明确拒绝，避免覆盖原件。

显式修改原用例后，即使实现内容不变，也保存为新的精确版本，旧版证据不自动迁移；完全相同的实现和用例继续去重。完整包保留用例的输入和独立预期，但导出时清空账号专属 `fileIds`；涉及上传文件的用例必须由接收账号重新选择本人文件，不能沿用原账号授权。社区发布仍只公开源码和清单里的公开示例，不把私有版本用例自动公开。`format=original` 仍返回上传原字节；`format=agent_skills` 仍只含标准 `SKILL.md` 和其资源，不附加平台用例文件。下方 2026-10-14 的组件 JSON 导出说明为历史阶段行为。

## 2026-10-14 标准内容与完整组件（当前补充）

标准Skill目录/ZIP只需合法`SKILL.md`及其配套资源，不要求平台`capability.json`。导入后平台清单、精确Tool绑定、当前连接、验证与启用独立保存；标准正文、资源、二进制和本机不支持的语言文件原样保留。内容有效与当前平台可执行分别返回，导入不是执行授权。

`agent_skills`导出以`SKILL.md`所在目录为根，保留该目录全部相对资源，不附加平台生成清单、账号连接或验证元数据。目录外还有必需资源时明确拒绝无损转换，不能静默遗漏。纯标准包可交给其他Agent Skills宿主使用，但本机WASI及平台Tool连接条件不自动成为外部宿主能力；外部运行兼容性须另验。

App组件及自足平台导出采用`cd80.component/1`：完整清单、文件字节、内容摘要及精确Tool依赖闭包，不能靠个人库最新版重建。导出移除平台来源账号/连接绑定及验证权威；接收者绑定自己的当前连接。删除原个人组件不删除已有App的实现，当前账号权限撤销仍拦截执行。根包和全部闭包共同受到深度、文件及字节限额约束。

Tool新增`fixed_pipeline`，固定Python、Tool、模型多步骤，逐步校验真实结果、文件与依据字段；不是Skill自主规划。新导入、编辑保存、自足安装和社区复制版本一律要求原预期及另一组不同实际输入验证，既存迁移前版本保留历史协议。完整字段、工程限额和准入见[技术规范](技术规范.md)。下文标注首版/2026-10-13的能力和验证记录保持历史范围，不能用其单用例规则覆盖新版本。

## 本地数据能力扩展（2026-10-13）

新增 `python_connector` 包执行方式与宿主只读连接注册表；既有 WASI 不开放网络。新增官方示例 `assertions`、验证 `expectation.mode=assertions` 和个人用例同名字段，前端可加载并执行规则。公共包通过维护者目录和逐包证据加载，个人仍须独立复制、验证、启用。精确协议见 [本地能力执行协议](../local-financial-capabilities/执行协议.md)，机器契约以同目录 Schema/OpenAPI 为准。

## 2026-10-13 包内示例与官方发布（已实现）

manifest 新增可选 examples 数组，最多20项。每项必须包含 id、title、description、requirements（说明数组）、filePaths（包内文件路径数组，最多8项）；id版本内唯一。Tool 另需 input对象与 expected（任意合法JSON值），Skill 另需非空 prompt 与 criteria。每个文件路径必须存在于 files 索引；不含真实密钥。输入与预期按工具 Schema 检查，不符合时阻断包使用。

示例随清单导入导出并参与内容摘要。旧包没有 examples 仍可导入；旧版官方两项样例以精确清单摘要兼容，不通过名称猜测。新官方版本加入示例和友好字段说明后内容摘要改变，公共更新不覆盖个人旧副本。

目前公共 Skill/Tool 为 summary-skill、decimal-total，均有包内完整示例；mcp-connection 是连接格式样本，非可执行官方能力，不冒充已通过工具发布验收。

发布流程：运行 `python scripts/verify_official_examples.py`，在临时账号/数据库执行真实示例；复核 Skill 输出后将实际证据及复核结论保存至 backend/app/modules/capability_library/official_example_evidence.json；运行 `python scripts/check_official_release.py`。示例缺失、内容变化、执行失败或Skill未复核时检查失败，公共导入也拒绝发布。作者预期、官方验证、用户当前环境验证分别记录。

当前官方示例不需要输入文件；发布验收脚本对未来需要文件的示例会明确阻断，维护者必须补齐显式授权适配并验证，不能跳过文件步骤后发布。普通用户页面已支持下载包内示例文件、上传和授权实际输入。

本平台包规范版本为 `cd80.capability/1`。它统一管理原件、声明和迁移信息，不替代 Agent Skills、OpenAI/Claude 工具描述或 MCP 协议。完整的跨平台运行等价性只在支持的执行范围内成立。

## 标准依据与适配范围

| 原生规范 | 导入映射 | 保留与限制 |
| --- | --- | --- |
| Agent Skills | `SKILL.md` frontmatter 的 name、description；正文及配套目录 | 原始文件保留；未知执行扩展不能静默忽略 |
| OpenAI Chat Completions function | `function.name/description/parameters` | 解析为平台 ToolDefinition；保留外层原生文件 |
| OpenAI Responses function | 顶层 `name/description/parameters` | 与嵌套格式分别识别，不能混淆；不新增 Responses 模型调用 |
| Claude custom tool | `name/description/input_schema` | 输入映射为 inputSchema；供应商托管工具另行标不支持 |
| MCP tool | `name/description/inputSchema/outputSchema` | schema 与结果类型逐项检查；annotations 不作为授权 |

Skill 标准定义方法与资源的目录结构，OpenAI 官方说明其 Skills 与该标准兼容。来源：[Agent Skills](https://agentskills.io/specification)、[OpenAI Skills](https://developers.openai.com/api/docs/guides/tools-skills)。

函数工具需要宿主实际执行并回传结果，描述格式本身不携带可运行实现。来源：[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)、[Claude Tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)。

MCP 提供工具发现与调用契约；本平台实现范围与完整协议范围分开声明。来源：[MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。协议升级需更新兼容性测试，不因文档地址变化自动改变已导入版本。

## 平台完整包布局

```text
capability.json                 平台声明，见 JSON Schema
original/                       原生资产文件，字节不变
  SKILL.md                      Skill 类型示例
  references/method.md
  scripts/compute.py
provenance.json                 原件清单、各文件 sha256、声明来源
```

一个平台包包含一个 Skill 或 Tool。MCP 连接描述包用于发现工具，一个连接可发现多个 Tool，不能把一个连接当成所有工具的共同执行授权。

可直接上传原生 Skill 目录/ZIP 或 OpenAI/Claude 工具 JSON，导入器创建独立平台声明，不写回原件。信息不足时保持待配置；用户可以下载平台包补充声明后重新导入。更新资产需明确提供 targetAssetId，不根据同名自动覆盖。

目录上传保留每个文件相对路径和字节，原件导出生成 ZIP；原 ZIP 上传保留原 ZIP，原件导出保证字节一致。编辑版的“原件”指该编辑版本保存时的原生文件集，原始导入版仍可独立下载。

## 清单字段

完整结构校验见 [capability.schema.json](schemas/capability.schema.json)。

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| format | 是 | 固定 `cd80.capability/1` |
| kind | 是 | `skill`、`tool`、`mcp_connection` |
| name、description | 是 | 用户显示名称和能力说明 |
| source | 是 | 声明来源、来源身份、原生格式、可选 URL/版本/许可证 |
| files | 是 | 包内原件的相对路径、字节数与 SHA256 |
| dependencies | 是 | 明确需要的 Tool 身份及内容摘要；可为空 |
| permissions | 是 | 网络、外部状态、输入文件、隔离输出的声明；不是授权凭证 |
| skill | Skill 必填 | entry 指向 SKILL.md，可选受控脚本执行声明 |
| tool | Tool 必填 | inputSchema、可选 outputSchema、execution |
| connection | MCP 描述必填 | transport、endpoint、authentication 配置项名称 |

`source.identity` 使用发布者命名空间，例如 `org.example/positive-sum`。只表示声明身份，不证明发布者。`files` 中的摘要为原文件字节摘要，由服务器重新计算核对。

版本和 owner 为服务器权威数据，不允许通过清单设置。`source.version` 为外部版本说明，不代替平台 versionId。contentDigest 由平台计算，不能由清单自报。

## Skill 依赖与脚本

依赖示例：

```json
{
  "sourceIdentity": "org.example/quote-reader",
  "contentDigest": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "required": true,
  "reason": "获取待分析证券的行情"
}
```

服务器只核对完全一致的身份与摘要。上例摘要是格式示例，不能指向实际工具；示例文件不应被标成已验证能力。无依赖 Skill 使用空数组。

没有统一、完整的上游工具依赖声明时，平台不把正文中的工具名猜测为可执行绑定。`allowed-tools` 等原生限制原样保留，并作为检查输入；平台清单用于明确需要的实际资产。无法建立明确关系时保持待配置。

Skill 正文不能直接产生 shell 权限。`skill.scripts` 为显式声明的受控 Python 入口，采用与 Tool 相同的 Python 执行定义；未声明脚本只能作为资料保存。检测到正文必须使用未支持脚本而声明缺失时阻断，不当作纯说明放行。

## Tool 执行定义

| execution.type | 必需字段 | 行为 |
| --- | --- | --- |
| python_wasi | path、callable | 从原件路径加载；首版 callable 固定 run，签名 run(payload) |
| builtin | handlerId | 引用平台可信适配器 ID；包不能自造可执行 handler |
| mcp_http | connectionIdentity、toolName、toolSchemaDigest | 引用用户已配置且准入通过的连接工具 |

MCP execution 里的连接身份不是连接密钥，也不能直接绑定他人 connectionId。导入者在独立连接配置页创建同一来源身份的个人配置；不存在或歧义时标为待配置。Skill 依赖仍通过重导入解决，没有手动绑定操作。

工具参数必须是 JSON 对象。首版运行 schema 支持 object、array、string、integer、number、boolean、null，以及 properties、required、additionalProperties、items、enum、const、数值/长度边界和 description/title/default。未知 schema 关键字完整保留，但不在运行子集内时阻断；不删除约束后宣称等价。递归引用、外部 $ref、供应商特定控制字段先标不支持。服务端严格验证，不能依赖模型校验。

结果内部统一为 `{content, sources, artifacts}`。content 为可验证 JSON；sources 是来源链接元数据；artifacts 是平台受控文件 ID，不是宿主路径。原生输出 schema 与平台结果封装分开：outputSchema 校验 content。MCP isError=true 即失败，不能仅以 HTTP 200 标成功。

## 声明与准入检查

permissions 的 `network` 为 none 或 connector_only；`externalEffects` 为 none、write 或 unknown；`inputFiles`、`outputFiles` 为布尔值。write/unknown 一律不可执行。声明 none 仍需运行器边界或平台准入证据，不能自助绕过。

禁止绝对路径、父目录跳转、符号链接、硬链接、设备文件、Windows 保留名称和大小写路径碰撞。不能在解析时执行模板、动态命令、远程 include、包安装或解码后运行脚本。附加资源的可执行扩展与纯说明分开检查。

## 导出规则

原件导出不转换文件。平台完整包添加独立清单与溯源信息，不包含平台有效权限、启用标记、验证通过凭证、凭据值、输入文件和执行日志。重新导入后必须重新检查和配置，不能凭导出包内“已验证”字样放行。

可单独转换为 OpenAI Chat Completions、OpenAI Responses 或 Claude 工具定义的导出副本。该副本只提供接口定义，不保证外部宿主已获得执行实现；如完整运行语义不能转换，返回 UNSUPPORTED_EXPORT，而非静默删字段。MCP 描述导出只保留连接信息和工具契约。

若原件疑似包含硬编码凭据，禁止普通导出并提示用户自行清理后重导入；不自动改写原文件制造“原件”。原件可在隔离存储中保留供本人检查，服务端不得把其可疑内容送给模型。独立凭据配置始终不属于原件。

## 第一版实现限额

当前实现对每个包内文件统一限制1 MiB，包括非文本；压缩20 MiB、展开50 MiB、最多500项。目录布局与物理存储见 [技术规范](技术规范.md)，原设计目标不得覆盖当前实际限制。文档schemas和运行Schema位置保持不变。
