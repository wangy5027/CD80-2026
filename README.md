# 成都八零：应用二与应用三功能开发项目

本项目用于独立实现、验证和联调以下两个主应用：

| 应用编号 | 应用名称 | 核心功能 |
| --- | --- | --- |
| 应用二 | 策略工坊 | 分析投资想法、匹配与修改策略、回测、展示结果，以及保存个人策略并重新配置回测 |
| 应用三 | 应用工坊 | 分析金融应用需求、推荐已有应用，或从应用池检索、组合和修改相关应用，生成并保存新应用 |

**现有网站和前端是配合这两个应用进行功能实现、演示与联调的界面。** 当前工作台、导航和页面布局属于开发验证环境；本仓库的主要交付是应用二、应用三的功能，最终平台界面将在后续整合时统一。

技术栈为 Vue 3 + Vite、Flask + Waitress、LangGraph、SQLite 和 Wasmtime。

## 后续整合

后续需要将**平台、应用一、应用二（策略工坊）、应用三（应用工坊）**整合到同一套产品中，保留各应用的业务功能，使用统一界面。

- 保留本项目已经实现的策略匹配、策略改写、回测、结果展示、个人策略保存与复跑，以及应用需求分析、推荐、组合创建和个人应用保存能力。
- 将两工坊接入统一的平台入口、导航、页面布局、视觉和交互；现阶段前端用于验证功能，不作为最终界面的定稿。
- 整合时对接平台的公共能力、应用目录、数据和业务记录，具体接口与迁移方案届时统一确定。

当前为应用二、应用三的独立功能实现阶段，整体平台及各应用的统一整合尚待完成。

## 两个主应用的已实现功能

### 应用二：策略工坊

将用户的投资想法转成可解释的策略规则，并用历史行情进行回测。

| 功能 | 当前可以做什么 |
| --- | --- |
| 自然语言分析与匹配 | 接收投资想法，从十种已有策略中推荐一条接近的方案，解释用户意图、实现思路、相同点和差异 |
| 选择与自定义策略 | 用户可采用推荐方案，或坚持自己的想法；基于已有日线行情字段补充买卖条件，确认规则后生成并校验策略代码 |
| 回测配置与执行 | 选择已接入行情的股票或 ETF、开始日期、结束日期和初始资金，检查数据覆盖，确认实际可运行区间后发起回测 |
| 指标与可视化 | 展示总收益率、年化收益率、最大回撤、夏普比率、交易次数、胜率，以及策略和同标的买入持有基准的净值、回撤曲线 |
| 策略代码查看 | 代码默认折叠，展开后查看本次策略代码，可一键复制；历史运行展示当时的代码快照 |
| 完整对话与历史 | 回看需求输入、策略分析、用户选择、规则修改、确认、配置和回测结果，保留不同会话及运行记录 |
| 保存个人策略应用与复跑 | 回测完成后添加到个人应用，在“应用”中打开；沿用保存的规则和代码，重新选择标的、日期和资金进行回测，每次结果独立保留 |
| 表达风格与草稿恢复 | 默认小白模式，可切换专家模式；按账号记住偏好，个人应用的回测配置和运行状态可在刷新后恢复 |

主要流程：**描述投资想法 → 分析并推荐策略 → 采用原方案或自定义并确认规则 → 配置并确认回测 → 查看结果 → 保存为个人应用并复用。**

### 应用三：应用工坊

将用户的金融功能需求转成已有应用的使用方案，或创建一个新的个人应用，全程使用简单直白的语言。

| 功能 | 当前可以做什么 |
| --- | --- |
| 金融需求分析 | 理解用户想实现的功能，拆解处理步骤，并解释需要使用的工具和技能 |
| 已有应用推荐 | 从当前已接入的应用池推荐一个合适的应用，说明推荐理由、已经覆盖的部分以及用户仍需要的独立功能；没有合适推荐时仍可创建新应用 |
| 使用推荐应用 | 点击“使用推荐 APP”进入对应应用，带入用户原问题和可确认的参数，供用户继续操作 |
| 检索、组合和修改 | 点击“创建新的 APP”后重新检索应用池，选取相关应用，复用其实际工具代码、技能和处理流程，按需求组合、修改并生成独立的新应用 |
| 新应用介绍 | 展示名称、一句话目标、功能、输入输出、选用的来源应用，以及组合与修改方案 |
| 保存与继续使用 | 点击“添加到我的应用池”保存到当前账号，可在“应用”中找到；创建和保存不要求先运行成功，保存时标明尚未运行 |
| 会话与输入恢复 | 保留当前分析、生成预览和保存状态，支持刷新恢复；不同账号的数据相互隔离 |

主要流程：**描述金融需求 → 分析并推荐应用 → 使用推荐 APP，或创建新的 APP → 查看介绍并添加到个人应用池。**

### 当前功能范围

- 策略回测支持日频、单标的、只做多、无杠杆；自定义规则基于已接入的日线行情字段。
- 当前策略结果为明确标记的诊断回测，正式收益报告仍受数据完整性门槛约束；不提供实盘自动交易。
- 微博热度、公告情绪等外源数据尚未接入，策略工坊也尚未开放外源数据上传入口。
- 应用工坊创建的是包含工具、技能和流程的应用定义。创建和保存不自动执行工具，保存成功不表示该应用已经运行验证通过；实际生成工具通过 WASI 隔离环境执行，目前使用 Python 标准库且不能联网。

## 本地联调支撑

以下能力用于支撑两个主应用的独立开发、验证和接入：

- **工作台**：本地账号、流式聊天、会话历史、项目、文件和日程；未提交草稿按账号保存在当前浏览器。
- **通用应用执行与目录**：识别需求、澄清参数、调用已有应用或生成新应用；用户确认流程和文件授权后执行，支持个人应用保存与复用。

## 本地验证环境启动

后端使用 Python 3.10 或更高版本。Windows PowerShell 在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

打开 [本地验证工作台](http://127.0.0.1:8893/desktop/)，注册或登录本地账号；从侧栏进入“应用”“应用工坊”或“策略工坊”。服务仅监听 `127.0.0.1`，可使用 `main.py --port 8894` 更换端口。macOS/Linux 使用 `.venv/bin/python`。

日常启动直接使用仓库内的 `frontend/dist/`，无需安装 Node.js。模型、行情数据及隔离运行时需要在部署环境另行配置；仅克隆源码不能完成全部策略生成与回测功能。

## 部署配置

在本地自行创建根目录 `.env`，或设置以下环境变量。进程环境变量优先于 `.env`；模型密钥仅由后端读取。

| 配置 | 用途与默认值 |
| --- | --- |
| `GITEE_AI_API_KEY` | 模型服务凭据，启用 AI 功能前需配置 |
| `GITEE_AI_BASE_URL` | 模型接口，默认 `https://ai.gitee.com/v1` |
| `GITEE_AI_MODEL` | 默认 `GLM-5.3` |
| `PORT` | 默认 `8893` |
| `DATA_DIR` | 账号、业务记录及产物目录，默认 `data` |
| `FRONTEND_DIST` | 前端构建目录，默认 `frontend/dist` |
| `AGENT_RUNTIME_DIR` | 已配置并通过完整性校验的 WASI 运行时目录，默认 `data/agent-runtime` |
| `STRATEGY_WORKSHOP_SOURCE_DB` | 部署环境提供的原始行情库路径 |
| `STRATEGY_WORKSHOP_MARKET_DB` | 规范化行情库路径 |
| `STRATEGY_WORKSHOP_MAPPING_DIR` | 行情映射及血缘说明目录 |
| `STRATEGY_WORKSHOP_INSTRUMENTS` | 需要额外配置时使用的证券交易元数据 JSON |

具体配置默认值见 [backend/app/config.py](backend/app/config.py)。相对路径以项目根目录为基准；更改 `DATA_DIR` 不会自动迁移共享行情库或隔离运行时。

行情库、映射和运行时应使用与当前代码契约兼容的部署资源。运行时缺失或校验失败时，生成工具与自定义策略执行不可用。数据库文件、用户记录、行情、密钥、安装环境以及本地开发资料均不随源码发布。

## 前端开发

使用 Node.js 20.19+ 或 22.12+，在项目根目录执行：

```powershell
npm --prefix frontend ci
npm --prefix frontend run dev
```

开发服务默认代理到 `http://127.0.0.1:8893`，需要同时启动后端。完成修改后构建发布资源：

```powershell
npm --prefix frontend run build
```

更多配置见 [前端说明](frontend/README.md)。
